Part I · 신호의 언어 — 1장

신호처리의 지도: 수신기는 숫자 공장이다

이 장을 마치면: RF 수신 체인의 블록 이름을 대고 각 블록이 어떤 신호처리 개념인지 말할 수 있으며, dB·dBm·dBFS를 머릿속에서 바로 환산하고, Zynq의 PL과 PS가 체인의 어느 부분을 맡는지 설명할 수 있습니다.

신호는 시간에 따라 변하는 숫자다

신호(signal)는 시간에 따라 변하는 어떤 양입니다. 안테나 단자의 전압, 마이크의 음압, 가속도 센서의 출력이 모두 신호입니다. 신호를 분류하는 축은 두 개입니다. 시간이 연속인가 띄엄띄엄인가, 그리고 값이 연속인가 정해진 단계만 가질 수 있는가.

값이 연속값이 이산 (양자화)
시간 연속아날로그 신호 x(t) — 안테나 전압비교기 출력, PWM
시간 이산이산 시간 신호 x[n] — 수학적 이상형디지털 신호 — ADC가 내놓는 12비트 정수열

이 책에서는 괄호 모양으로 둘을 구분합니다. x(t)는 연속 시간, x[n]은 n번째 샘플입니다. 신호처리 이론의 대부분은 "시간 이산, 값 연속"을 가정하고 전개되고, 값이 이산이라서 생기는 문제(양자화 잡음, 오버플로)는 9장에서 따로 다룹니다. FPGA를 다루는 사람에게 이 구분은 실무적으로 중요합니다. 알고리즘은 실수(real number)로 설계하고, 구현은 정수로 하기 때문입니다.

시스템은 신호를 받아 신호를 내놓는 함수다

필터, 믹서, 증폭기, 복조기처럼 신호를 받아 다른 신호를 내놓는 것을 모두 시스템이라고 부릅니다. 그중 신호처리가 특별히 아끼는 부류가 선형 시불변(LTI, Linear Time-Invariant) 시스템입니다.

  • 선형: 입력을 두 배 하면 출력도 두 배, 두 입력을 더해 넣으면 각각의 출력을 더한 것이 나옵니다. 중첩의 원리가 성립합니다.
  • 시불변: 오늘 넣든 내일 넣든 같은 입력에는 같은 출력이 (그만큼 늦게) 나옵니다. 계수가 시간에 따라 바뀌지 않습니다.

LTI가 중요한 이유는 하나로 요약됩니다. LTI 시스템에 사인파를 넣으면 같은 주파수의 사인파가 나온다. 크기와 위상만 바뀝니다. 그래서 어떤 신호든 사인파들의 합으로 쪼갤 수 있다면(5장의 푸리에 변환), 시스템은 "주파수마다 크기와 위상을 얼마나 바꾸는가"라는 표 하나로 완전히 기술됩니다. 이 표가 주파수 응답이고, 필터 설계(6장)는 이 표를 원하는 모양으로 만드는 일입니다. 반대로 믹서는 일부러 LTI가 아니게 만든 시스템입니다. 주파수를 옮기는 것이 목적이니까요(8장).

신호처리 체인은 처리량이 고정된 데이터 파이프라인입니다. 샘플률은 처리량(throughput)이고, 필터 탭 수는 샘플당 연산량이며, 데시메이션은 다음 단계로 넘기는 데이터율을 줄이는 압축입니다. FPGA에서는 "클록마다 샘플 하나가 들어온다"가 기본 계약이고, 그 계약을 지키는 한 지연(latency)은 늘어나도 괜찮습니다. 반대로 PS 쪽 소프트웨어는 샘플이 아니라 버퍼와 패킷 단위로 생각합니다. 이 경계를 어디에 긋느냐가 9장의 주제입니다.

dB 감각: 신호처리의 공용 단위

RF와 신호처리에서는 거의 모든 크기를 데시벨로 말합니다. 곱셈이 덧셈이 되고, 10−12 같은 숫자가 −120처럼 다룰 만한 숫자가 되기 때문입니다. 규칙은 단 하나입니다. 전력의 비는 10 log10, 진폭(전압)의 비는 20 log10. 전력은 진폭의 제곱이므로 두 식은 같은 dB 값을 냅니다.

dB는 원래 비율이라 단위가 없습니다. 기준을 붙이면 절대량이 됩니다.

  • dBm: 1 mW 기준 전력. 0 dBm = 1 mW, 30 dBm = 1 W, −100 dBm = 0.1 pW. 수신기 감도와 송신 출력이 이 단위입니다.
  • dBFS: ADC 풀스케일(full scale) 기준. 0 dBFS가 ADC가 표현할 수 있는 최대 크기이고, 디지털 영역의 신호는 전부 음수 dBFS로 표시됩니다. 스펙트럼 분석(5장)과 고정소수점(9장)의 기본 단위입니다.
  • dBc: 반송파(carrier) 기준. "스퓨리어스가 −60 dBc"는 주 신호보다 60 dB 낮다는 뜻입니다.

체인 전체의 이득은 각 단의 dB를 더하면 됩니다. LNA +15 dB, 믹서 −6 dB, 기저대역 증폭 +40 dB라면 합계 +49 dB입니다. −90 dBm의 신호가 −41 dBm으로 ADC에 도착합니다. 이 계산이 암산으로 되기 시작하면 RF 문서가 읽히기 시작합니다.

db_basics.py · 실행 검증됨
import numpy as np

def db_power(ratio):  return 10 * np.log10(ratio)
def db_amp(ratio):    return 20 * np.log10(ratio)
def dbm_to_mw(dbm):   return 10 ** (dbm / 10)

print(f"power x2      -> {db_power(2):5.2f} dB")
print(f"amplitude x2  -> {db_amp(2):5.2f} dB")
print(f"-90 dBm       -> {dbm_to_mw(-90):.1e} mW")
# Cascade gain is a sum in dB: LNA, mixer loss, baseband amplifier
print(f"chain gain    -> {15 - 6 + 40} dB, so -90 dBm arrives at {-90 + 15 - 6 + 40} dBm")

이 조합은 ADI가 공식 지원하는 캐리어가 아니므로 참조 설계를 보드에 맞게 옮기는 작업이 한 번 필요합니다. 다행히 ADI가 지원하는 ZedBoard가 같은 XC7Z020-CLG484 칩을 쓰기 때문에 출발점이 분명하고, 이 작업은 임베디드 BSP 일과 거의 같습니다. 구체적인 순서는 9장 끝에서 다룹니다. 더 큰 플랫폼으로 가면 Zynq UltraScale+ RFSoC처럼 기가샘플급 RF-ADC를 칩 안에 넣고 믹서 없이 RF를 바로 샘플링하는 구조도 있습니다. 원리는 이 책과 같고, 2장의 나이퀴스트 존과 8장의 DDC가 그 구조를 이해하는 열쇠입니다.

핵심 정리
  • LTI 시스템은 사인파를 사인파로 바꾼다. 그래서 주파수 응답 하나로 완전히 기술된다.
  • 수신 체인은 "주파수를 내리고 → 샘플링하고 → 거르고 → 샘플률을 줄이고 → 동기를 맞춰 → 판정"하는 파이프라인이다.
  • dB는 전력이면 10 log, 진폭이면 20 log. dBm은 1 mW 기준, dBFS는 ADC 풀스케일 기준이다.

샘플링과 앨리어싱

이 장을 마치면: 임의의 주파수가 주어진 샘플률에서 어떤 주파수로 보일지 계산할 수 있고, 나이퀴스트 조건과 안티앨리어싱 필터가 왜 필요한지 설명하며, 나이퀴스트 존을 이용한 대역통과 샘플링을 이해할 수 있습니다.

사인파 하나를 완전히 기술하는 세 숫자

모든 이야기는 사인파에서 시작합니다. 진폭 A, 주파수 f, 위상 φ, 이 세 숫자면 사인파 하나가 완전히 정해집니다.

x(t) = A cos(2πf t + φ) 각주파수 ω = 2πf [rad/s], 주기 T = 1/f

주파수 f는 1초에 몇 바퀴 도는가, 2πf t는 지금까지 몇 라디안 돌았는가입니다. 3장에서 이 "돈다"는 표현이 비유가 아니라 문자 그대로라는 것을 보게 됩니다.

샘플링은 시간축을 일정 간격으로 자른다

ADC는 Ts = 1/fs 간격으로 신호 값을 읽습니다. n번째 샘플은 t = nTs에서의 값이므로 식에 그대로 넣으면 됩니다.

x[n] = x(nTs) = A cos(2π ffs n + φ)

여기서 놀라운 사실이 드러납니다. 샘플열에는 f와 fs가 따로 남지 않고 비율 f/fs만 남습니다. 이 비율을 정규화 주파수(normalized frequency)라고 하고 단위는 "샘플당 사이클"입니다. 숫자열만 보고는 1 MSPS로 받은 100 kHz인지, 10 MSPS로 받은 1 MHz인지 알 수 없습니다. 둘 다 0.1 사이클/샘플입니다.

더 중요한 성질이 있습니다. 주파수에 fs의 정수배를 더해 보세요.

cos(2π f + k fsfs n + φ) = cos(2π ffs n + 2πkn + φ) = cos(2π ffs n + φ) k와 n이 정수이므로 2πkn은 정확히 몇 바퀴. 각도가 제자리로 돌아온다.

샘플만 보면 f와 f + fs와 f + 2fs는 완전히 같은 숫자열입니다. 이것이 앨리어싱(aliasing)입니다. 이산 시간 세계에서 주파수는 직선이 아니라 둘레가 fs인 원 위에 있습니다. 게다가 실수 코사인은 cos(−θ) = cos θ이므로 −f와 f도 구분되지 않습니다. 둘을 합치면 실수 신호에서 보이는 주파수는 항상 0부터 fs/2 사이로 "접혀" 들어옵니다.

falias = | f − k fs |,   k = round(f / fs) 결과는 항상 0 ≤ falias ≤ fs/2

실제 연속 신호샘플샘플이 보여 주는 신호 (앨리어스)

슬라이더를 500 Hz 너머로 밀어 보세요. 연속 파형은 점점 빨리 흔들리는데 샘플 점들이 그리는 주황색 곡선은 오히려 느려집니다. 1000 Hz에서는 샘플이 매번 같은 위상을 찍어 직류(0 Hz)처럼 보이고, 1300 Hz는 300 Hz와 점 하나하나까지 똑같습니다. 아래 그래프의 지그재그가 "주파수가 접힌다"는 말의 모양입니다.

나이퀴스트 조건: 대역폭의 두 배보다 빠르게

접힘이 문제가 되지 않으려면 신호의 모든 성분이 처음부터 0 ~ fs/2 안에 있어야 합니다. 최고 주파수가 B인 실수 신호라면 fs > 2B. 이것이 나이퀴스트-섀넌 샘플링 정리의 실무적 요약이고, fs/2를 나이퀴스트 주파수라고 부릅니다. 이 조건을 만족하면 샘플로부터 원래 연속 신호를 정확히 복원할 수 있습니다.

부등호가 엄격하다는 점에 주의하세요. f = fs/2를 정확히 샘플링하면 cos(πn + φ) = cos φ · (−1)n이 됩니다. 크기가 위상에 따라 달라지고, φ = 90°면 모든 샘플이 0입니다. 신호가 통째로 사라집니다.

3장에서 다룰 복소(IQ) 샘플링에서는 같은 조건이 fs > B로 바뀝니다. AD9361이 채널당 61.44 MSPS의 복소 샘플로 최대 56 MHz 대역폭을 다룰 수 있는 이유입니다.

alias.py · 실행 검증됨
import numpy as np

fs = 1000.0
n = np.arange(12)

def samples(f, phase=0.0):
    return np.cos(2 * np.pi * f / fs * n + phase)

# 300 Hz and its aliases produce identical sample sequences
for f in (1300, 700, 1700):
    print(f"{f:5.0f} Hz equals 300 Hz at fs=1 kHz: {np.allclose(samples(f), samples(300))}")

def alias(f, fs):
    return abs(f - round(f / fs) * fs)

print("alias of 2310 Hz:", alias(2310, fs), "Hz")
# Sampling exactly at 2*f: the result depends on phase and can vanish
print("f = fs/2, phase 90 deg:", np.round(samples(500, np.pi / 2)[:6], 12))

안티앨리어싱 필터와 오버샘플링

앨리어싱은 샘플링 이후에는 되돌릴 수 없습니다. 1300 Hz 간섭이 300 Hz로 접혀 들어오면, 진짜 300 Hz 신호와 구분할 정보가 샘플 안에 아예 없습니다. 그래서 ADC 앞에는 반드시 아날로그 저역통과 필터, 즉 안티앨리어싱 필터를 둡니다. 원하는 신호만이 아니라 잡음도 접힌다는 점이 특히 중요합니다. 나이퀴스트 주파수 위의 광대역 잡음을 걸러 내지 않으면 그 잡음이 전부 대역 안으로 포개져 들어와 잡음 바닥을 올립니다.

현실의 필터는 통과대역에서 저지대역으로 순간적으로 바뀌지 못하고 전이대역(transition band)이 필요합니다. 그래서 실무에서는 fs를 2B보다 넉넉하게 잡습니다. 오디오 CD가 20 kHz 대역에 44.1 kHz를 쓰는 것은 2.05 kHz 폭의 전이대역을 확보하기 위해서입니다.

현대 RF 트랜시버는 이 문제를 반대 방향으로 풉니다. AD9361 계열의 ADC는 연속 시간 시그마-델타 방식으로 수백 MSPS(FMCOMMS2 문서 기준 640 MSPS)라는 아주 높은 속도로 샘플링하고, 그 뒤에 디지털 데시메이션 필터로 날카로운 필터링을 하면서 샘플률을 내립니다. 아날로그 필터는 느슨해도 되고, 어려운 일은 정확하고 재현 가능한 디지털 필터가 맡습니다. 이 구조는 7장에서 자세히 뜯어봅니다.

일부러 접기: 나이퀴스트 존과 대역통과 샘플링

앨리어싱이 항상 적은 아닙니다. 주파수 축을 fs/2 폭의 구간으로 나누면 각 구간이 나이퀴스트 존(zone)입니다. 1존은 0 ~ fs/2, 2존은 fs/2 ~ fs, 3존은 fs ~ 1.5fs입니다. 신호가 한 존 안에만 들어 있다면, 그 존 전체가 1존으로 고스란히 접혀 들어오므로 정보가 겹치지 않습니다. 짝수 존은 거울에 비친 것처럼 주파수가 뒤집혀(spectral inversion) 들어온다는 점만 기억하면 됩니다.

이것이 대역통과 샘플링(언더샘플링)입니다. 예를 들어 fs = 1000 Hz에서 1200–1400 Hz 대역은 3존이고, 200–400 Hz로 뒤집힘 없이 나타납니다. 최고 주파수의 두 배보다 훨씬 낮은 샘플률로 받은 셈입니다. 대신 앞단에 그 존만 남기는 아날로그 대역통과 필터가 꼭 있어야 합니다. 다른 존의 신호도 똑같이 접혀 들어오기 때문입니다. Zynq UltraScale+ RFSoC의 RF-ADC처럼 기가샘플급 ADC가 믹서 없이 RF를 직접 샘플링할 때 이 원리를 씁니다.

흔한 함정
  • "2배면 충분하다": 정확히 2배에서는 위상에 따라 신호가 사라질 수 있고, 현실의 필터에는 전이대역이 필요합니다. 여유를 두세요.
  • 샘플률만 바꾸고 필터는 그대로: AD9361에서도(pyadi-iio 기준) sample_rate와 아날로그 필터 대역폭 rx_rf_bandwidth는 별개의 설정입니다. 샘플률을 낮추고 필터를 넓게 두면 대역 밖 신호가 접혀 들어옵니다.
  • 디지털 처리 중의 앨리어싱: 샘플을 솎아 내는 데시메이션도 샘플링입니다. 미리 거르지 않고 버리면 ADC 앞에서 막았던 앨리어싱이 디지털 영역에서 다시 일어납니다(7장).
핵심 정리
  • 샘플열에는 f/fs만 남는다. f와 f + k fs는 구분할 수 없다.
  • 실수 신호는 fs > 2B, 복소 신호는 fs > B.
  • 앨리어싱은 샘플링 뒤에는 되돌릴 수 없다. 반드시 샘플링 전에 거른다.

그런데 실수 신호에서 왜 f와 −f가 구분되지 않는지, "음의 주파수"란 도대체 무엇인지는 아직 설명하지 않았습니다. 다음 장에서 사인파를 회전하는 화살표로 바꿔 보면 이 질문과 함께 RF 수신기가 왜 I와 Q 두 채널을 쓰는지가 한꺼번에 풀립니다.

복소수와 IQ: 음의 주파수의 정체

이 장을 마치면: 오일러 공식으로 사인파를 회전하는 화살표로 바꿔 생각할 수 있고, 음의 주파수가 무엇인지 설명하며, RF 신호가 I/Q 복소 기저대역으로 표현되는 원리와 복소 샘플링이 실수 샘플링보다 유리한 이유를 말할 수 있습니다.

회전하는 화살표, ejθ

복소수 z = a + jb는 평면 위의 점, 또는 원점에서 그 점까지의 화살표입니다(전기공학에서는 전류 i와 헷갈리지 않게 허수 단위로 j를 씁니다). 같은 화살표를 길이 r와 각도 θ로도 쓸 수 있고, 이 둘을 잇는 것이 오일러 공식입니다.

ejθ = cos θ + j sin θ   ⇒   z = r ejθ = r cos θ + j r sin θ

이 표기의 힘은 곱셈에서 나옵니다. 두 복소수를 곱하면 길이는 곱해지고 각도는 더해집니다. r1ejθ1 · r2ejθ2 = r1r2ej(θ1+θ2). 길이 1짜리 복소수를 곱하는 것은 곧 회전입니다. 신호처리에서 주파수를 옮기는 일(8장), 위상을 보정하는 일(11장)이 전부 이 곱셈 한 번입니다.

곱셈(ac−bd) + j(ad+bc)길이 곱, 각도 합 (실수 곱셈 4번, 덧셈 2번)

실수 코사인은 반대로 도는 두 화살표의 합이다

오일러 공식을 두 번 쓰면 코사인을 복소 지수로 풀 수 있습니다.

cos(2πft) = ej2πft + e−j2πft2

반시계로 도는 반 길이 화살표와 시계로 도는 반 길이 화살표를 더하면, 허수 성분은 서로 상쇄되고 실수축 위에서 왕복하는 점만 남습니다. 그것이 코사인입니다. 그래서 실수 신호의 스펙트럼에는 언제나 +f와 −f에 같은 크기의 선이 짝으로 나타나고, 양쪽 절반이 같은 정보를 중복해서 담습니다. 2장에서 실수 샘플링에 2B가 필요했던 이유, −f와 f가 구분되지 않았던 이유가 이것입니다.

신호 종류

복소 모드에서 f의 부호를 바꾸면 화살표의 회전 방향과 스펙트럼 선의 위치가 함께 바뀝니다. I 파형(파랑)만 보면 +f와 −f가 똑같지만 Q 파형(주황)은 부호가 뒤집힙니다. 실수 모드로 바꾸면 반대로 도는 두 화살표가 나타나고 스펙트럼이 좌우 대칭이 됩니다. 이때는 f의 부호를 바꿔도 아무것도 달라지지 않습니다.

I와 Q: 두 방향에서 봐야 회전이 보인다

돌아가는 화살표를 옆에서만(코사인 투영) 보면 왼쪽으로 도는지 오른쪽으로 도는지 알 수 없습니다. 90° 돌린 위치에서 한 번 더 보면(사인 투영) 방향이 드러납니다. 이 두 투영이 I(In-phase, 동상)와 Q(Quadrature, 직교)입니다.

반송파 주파수 fc에 실린 RF 신호는 진폭과 위상이 천천히 변하는 사인파입니다. 이 변화를 두 개의 기저대역 신호 I(t), Q(t)로 쓰면 다음과 같습니다.

xRF(t) = I(t) cos(2πfct) − Q(t) sin(2πfct) = Re{ s(t) · ej2πfct },   s(t) = I(t) + j Q(t)

s(t)를 복소 기저대역(complex baseband) 신호, 또는 복소 포락선이라고 부릅니다. 반송파는 단지 s(t)를 fc만큼 회전시켜 옮겨 놓은 것일 뿐이고, 정보는 전부 s(t)에 있습니다. 수신기가 할 일은 그 회전을 되돌리는 것입니다.

왜 이렇게 하면 I와 Q가 나올까요? 곱셈의 삼각함수 공식 cosA cosB = ½[cos(A−B) + cos(A+B)]를 쓰면 위쪽 경로는 ½I(t)와 2fc 근처의 성분으로 나뉩니다. LPF가 2fc 성분을 지우면 ½I(t)만 남습니다. 아래쪽도 같은 방식으로 ½Q(t)가 나옵니다. 복소수로 한 줄에 쓰면 더 간단합니다. 수신 신호에 e−j2πfct를 곱해 반송파의 회전을 되감고, 저역통과로 거르면 s(t)가 남습니다. 송신기는 정확히 반대로, s(t)에 e+j2πfct를 곱하고 실수부를 내보냅니다.

복소 샘플링: fs 하나로 대역폭 B = fs를 본다

복소 기저대역 신호에는 +f와 −f를 구분할 정보가 있습니다. 그래서 스펙트럼의 양쪽 절반이 서로 다른 내용을 담을 수 있고, 샘플률 fs로 −fs/2 ~ +fs/2, 즉 폭 fs의 대역을 앨리어싱 없이 볼 수 있습니다. 숫자 개수로 따지면 복소 샘플 하나가 실수 두 개이므로 데이터량은 실수 샘플링과 같지만, 대역을 반송파 주위 양쪽으로 쓸 수 있다는 것이 결정적인 차이입니다.

예를 들어 AD9361의 LO를 2.44 GHz에, 샘플률을 20 MSPS에 두면 2.43–2.45 GHz가 한 번에 보입니다. FFT에서 음의 주파수 칸은 LO보다 낮은 주파수, 양의 칸은 높은 주파수입니다. 이 "LO가 0 Hz가 된다"는 감각이 SDR 작업의 출발점입니다.

iq_spectrum.py · 실행 검증됨
import numpy as np

fs, N = 1_000_000, 1000          # 1 MSPS, 1 kHz FFT bins
n = np.arange(N)
f0 = -200_000                    # 200 kHz below the LO

complex_tone = np.exp(2j * np.pi * f0 / fs * n)       # what an IQ receiver delivers
real_tone = np.cos(2 * np.pi * f0 / fs * n)           # what a single real ADC delivers

freqs = np.fft.fftshift(np.fft.fftfreq(N, 1 / fs))
for name, x in (("complex", complex_tone), ("real", real_tone)):
    X = np.abs(np.fft.fftshift(np.fft.fft(x))) / N
    peaks = freqs[X > 0.1]
    print(f"{name:8s} peaks at {peaks / 1e3} kHz, height {X.max():.2f}")

임베디드 엔지니어의 눈으로

메모리에서 IQ 샘플은 정수 두 개짜리 구조체입니다. AD9361의 12비트 ADC 값은 보통 16비트 정수 두 개(I, Q)로 담겨 32비트 워드 하나가 복소 샘플 하나가 되고, DMA와 AXI-Stream도 이 단위로 움직입니다. pyadi-iio는 이것을 numpy 복소 배열로 돌려줍니다. 한 가지 주의할 점은 I와 Q의 비트 위치나 순서, 부호 확장 방식이 인터페이스마다 다를 수 있다는 것입니다. 새 데이터 경로를 만들면 알려진 주파수의 톤을 넣고 스펙트럼 피크가 올바른 부호 쪽에 나타나는지부터 확인하세요. I와 Q가 뒤바뀌면 스펙트럼이 좌우로 뒤집힙니다.

흔한 함정: 현실의 IQ는 완벽하지 않다
  • DC 오프셋: LO가 새어 들어와 스펙트럼 한가운데(0 Hz)에 뾰족한 선이 생깁니다. 관심 신호를 일부러 0 Hz에서 비켜 두는 이유입니다(8장).
  • IQ 불균형: I와 Q 경로의 이득이 조금 다르거나 위상이 정확히 90°가 아니면, +f의 신호가 −f에 희미한 거울상(image)을 만듭니다. AD936x는 이를 줄이는 직교 보정 기능을 내장하고 있고, ADI 문서는 실수 신호만 받을 때는 이 추적 보정을 꺼야 한다고 안내합니다.
핵심 정리
  • ej2πft는 회전하는 화살표다. 음의 주파수는 반대 방향 회전이다.
  • 실수 신호는 ±f 쌍으로만 존재한다. I와 Q를 함께 가져야 방향(부호)이 보인다.
  • RF 신호 = Re{s(t) ej2πfct}. 수신기는 회전을 되감아 s(t)를 꺼낸다.

Part I을 마쳤습니다. 이제 신호를 숫자열로, 그것도 복소 숫자열로 다룰 수 있습니다. Part II에서는 이 숫자열을 가공하는 기본 연산 세 가지, 컨볼루션·푸리에 변환·필터를 차례로 익힙니다. 첫 번째는 모든 필터의 정체인 컨볼루션입니다.

LTI 시스템과 컨볼루션

이 장을 마치면: 임펄스 응답으로 LTI 시스템을 기술하고, 컨볼루션을 손으로 계산할 수 있으며, 탭 수와 샘플률로 필요한 연산량(MAC/s)을 추정하고, 임펄스 응답에서 주파수 응답을 구할 수 있습니다.

임펄스 하나로 시스템 전체를 안다

가장 단순한 신호를 생각해 봅시다. n = 0에서만 1이고 나머지는 모두 0인 단위 임펄스 δ[n]입니다. 어떤 LTI 시스템에 δ[n]을 넣었을 때 나오는 출력을 임펄스 응답 h[n]이라고 부릅니다. 놀랍게도 이것 하나만 알면 그 시스템이 어떤 입력에 어떻게 반응할지 전부 계산할 수 있습니다.

이유는 1장의 두 성질에 있습니다. 아무 신호나 크기가 다른 임펄스들을 시간축에 줄 세운 것으로 볼 수 있습니다. x[n] = Σk x[k] δ[n − k]. 시불변이므로 k만큼 늦은 임펄스에는 k만큼 늦은 h가 나오고, 선형이므로 크기를 곱하고 전부 더하면 됩니다.

y[n] = Σk x[k] · h[n − k] = (x ∗ h)[n] 이산 컨볼루션(convolution). 교환 법칙이 성립해 x ∗ h = h ∗ x

FIR 필터에서는 이 h[n]이 곧 필터 계수, 흔히 탭(tap)이라 부르는 숫자들입니다. "64탭 FIR"은 임펄스 응답이 64샘플 길이인 필터라는 뜻입니다.

뒤집고, 밀고, 곱하고, 더한다

식을 손으로 계산하는 절차는 네 단계입니다. h를 좌우로 뒤집고(h[−k]), 출력 위치 n만큼 밀고(h[n−k]), 겹치는 자리끼리 곱하고, 전부 더하면 y[n] 하나가 나옵니다. x = [1, 2, 3], h = [1, 1]로 해 보겠습니다.

n겹치는 곱y[n]
0x[0]h[0] = 1·11
1x[0]h[1] + x[1]h[0] = 1 + 23
2x[1]h[1] + x[2]h[0] = 2 + 35
3x[2]h[1] = 33

길이 L인 입력과 길이 M인 임펄스 응답의 컨볼루션은 길이 L + M − 1입니다. 처음 M−1개와 마지막 M−1개 출력은 필터가 입력과 "반만 겹친" 과도 구간입니다.

실습 벤치 4-A · 컨볼루션 한 칸씩CONVOLUTION STEPPER

이동 평균을 고르고 n을 천천히 늘려 보세요. 입력의 계단이 완만한 경사로 바뀝니다. 고주파(급격한 변화)가 깎였다는 뜻입니다. 차분은 정반대로, 입력이 일정한 구간에서는 0이 되고 변하는 순간에만 값이 나옵니다. 저주파를 지우고 고주파만 남기는 것입니다.

컨볼루션은 MAC의 반복이다

구현 관점에서 컨볼루션은 곱셈-누산(MAC, multiply-accumulate)의 반복입니다. 출력 하나마다 탭 수만큼 곱하고 더합니다. 임베디드 개발자라면 아래 코드가 낯설지 않을 것입니다. MCU에서 센서 값을 다듬던 이동 평균이 바로 FIR 필터입니다.

fir.c 
#include <stdint.h>
#define NTAPS 32

/* Direct-form FIR with a circular delay line.
 * Q15 coefficients and samples, 64-bit accumulator to avoid overflow. */
typedef struct {
    int16_t h[NTAPS];      /* impulse response = filter taps */
    int16_t z[NTAPS];      /* delay line: last NTAPS input samples */
    unsigned pos;
} fir_t;

int16_t fir_step(fir_t *f, int16_t x)
{
    f->z[f->pos] = x;
    int64_t acc = 0;
    unsigned idx = f->pos;
    for (unsigned k = 0; k < NTAPS; k++) {          /* y[n] = sum h[k] * x[n-k] */
        acc += (int32_t)f->h[k] * f->z[idx];
        idx = (idx == 0) ? NTAPS - 1 : idx - 1;
    }
    f->pos = (f->pos + 1) % NTAPS;
    acc += 1 << 14;                                  /* round, then Q30 -> Q15 */
    acc >>= 15;
    if (acc > INT16_MAX) acc = INT16_MAX;            /* saturate instead of wrapping */
    if (acc < INT16_MIN) acc = INT16_MIN;
    return (int16_t)acc;
}

필요한 연산량은 탭 수 × 샘플률입니다. 실수 계수 64탭 필터를 20 MSPS 복소 신호(I와 Q 각각)에 적용하면 2 × 64 × 20 M = 2.56 GMAC/s가 필요합니다. 667 MHz CPU 코어가 매 사이클 MAC 하나를 해내도 0.67 GMAC/s이니 턱없이 부족합니다. 반면 FPGA의 DSP 슬라이스는 클록마다 MAC 하나씩을 병렬로 해냅니다. 예를 들어 200 MHz로 돌린다면 Z-7010의 80개 슬라이스로 이론상 초당 160억 번입니다. 이 차이가 "샘플 단위 연산은 PL로"라는 원칙의 근거이고, 9장에서 구체적인 매핑 방법을 다룹니다.

사인파를 넣으면 사인파가 나온다: 주파수 응답

1장에서 LTI 시스템은 사인파를 같은 주파수의 사인파로 바꾼다고 했습니다. 이제 증명할 수 있습니다. 복소 사인파 x[n] = ejωn를 컨볼루션 식에 넣어 보세요.

y[n] = Σk h[k] ejω(n−k) = ejωn · Σk h[k] e−jωk = H(ejω) · x[n]

출력은 입력에 복소수 하나 H(ejω)를 곱한 것입니다. 이 복소수의 크기 |H|가 그 주파수에서의 이득, 각도 ∠H가 위상 변화입니다. ω를 0(직류)부터 π(나이퀴스트, fs/2)까지 훑으며 H를 그린 것이 주파수 응답입니다. 임펄스 응답에 복소 사인파를 곱해 더한 이 식은 5장의 푸리에 변환과 정확히 같은 모양입니다. 즉 주파수 응답은 임펄스 응답의 푸리에 변환입니다.

freq_response.py · 실행 검증됨
import numpy as np

filters = {
    "moving avg [1/4]*4": np.ones(4) / 4,
    "difference [1,-1]":  np.array([1.0, -1.0]),
}
nfft = 512
for name, h in filters.items():
    H = np.fft.fft(h, nfft)                          # H(e^jw) sampled on 0..fs
    gain = lambda frac: abs(H[int(frac * nfft)])     # frac = f / fs
    print(f"{name:20s} |H| at DC={gain(0):.2f}  fs/4={gain(0.25):.2f}  fs/2={gain(0.5):.2f}")

# Convolution by hand vs numpy
print("[1,2,3] * [1,1] =", np.convolve([1, 2, 3], [1, 1]))

흔한 함정
  • 가장자리 처리: np.convolve의 기본값은 길이 L+M−1인 full입니다. 블록 단위로 처리할 때 각 블록의 과도 구간을 무시하면 블록 경계마다 잡음이 생깁니다. 지연선(앞 코드의 z)을 블록 사이에 유지하거나 overlap-save 방식을 쓰세요.
  • 지연: 대칭 계수 M탭 FIR은 (M−1)/2 샘플만큼 신호를 늦춥니다. I와 Q, 또는 두 신호 경로를 다시 합칠 때 지연을 맞추지 않으면 위상이 어긋납니다.
  • 누산기 오버플로: 16비트 곱을 여러 개 더하면 비트 수가 늘어납니다. 위 C 코드가 64비트 누산기와 포화(saturation)를 쓰는 이유이며, 9장에서 필요한 비트 수를 정확히 계산합니다.
핵심 정리
  • LTI 시스템 = 임펄스 응답 h[n]. 출력은 x ∗ h.
  • 컨볼루션 = 뒤집고, 밀고, 곱하고, 더하기. 구현은 MAC의 반복이고 비용은 탭 수 × 샘플률.
  • 주파수 응답 H(ejω)는 h의 푸리에 변환. 시간의 컨볼루션은 주파수의 곱.

임펄스 응답에 복소 사인파를 곱해 더하는 식이 두 번이나 등장했습니다. 다음 장에서는 이 식 자체를 주인공으로 삼아, 신호 속에 어떤 주파수가 얼마나 들어 있는지 재는 도구인 DFT와 FFT를 다룹니다.

푸리에 변환과 FFT

이 장을 마치면: DFT의 각 빈이 어떤 주파수인지 계산하고, 길이 N과 창함수를 목적에 맞게 고르며, 스펙트럼을 dBFS로 올바르게 정규화해 신호 크기와 잡음 바닥을 읽을 수 있습니다.

DFT는 "이 회전이 들어 있나?"를 묻는 질문 N개다

푸리에의 생각은 단순합니다. 어떤 신호든 여러 주파수의 사인파를 적당한 크기와 위상으로 더해 만들 수 있다는 것입니다. 그렇다면 신호가 주어졌을 때 "주파수 f의 성분이 얼마나 들어 있는가"를 재는 방법이 필요합니다. 3장의 회전하는 화살표로 생각하면 답이 보입니다. 신호에 반대 방향으로 도는 화살표 e−j2πfn을 곱하면, 신호 안에 주파수 f로 도는 성분이 있을 때 그 성분만 회전이 풀려 제자리에 멈춥니다. 멈춘 화살표는 더할수록 커지고, 계속 도는 나머지 성분은 더하면 서로 상쇄되어 0 근처에 머뭅니다.

X[k] = Σn=0N−1 x[n] · e−j2πkn/N,   k = 0, 1, …, N−1 이산 푸리에 변환(DFT). k번째 탐침은 샘플당 k/N 사이클로 돈다

즉 DFT는 N개의 탐침 주파수 각각에 대해 "이 회전이 신호에 얼마나 들어 있나"를 계산한 결과입니다. X[k]의 크기는 그 성분의 세기, 각도는 위상입니다. 역변환(IDFT)으로 N개의 X[k]에서 원래 x[n]을 정확히 되돌릴 수 있으므로 정보는 하나도 사라지지 않습니다. 같은 신호를 다른 좌표계로 본 것뿐입니다.

빈(bin)을 주파수로 읽는 법

k번째 결과를 빈이라고 부르고, 빈 하나의 폭이 주파수 해상도입니다.

Δf = fsN = 1Tobs 해상도는 관측 시간 Tobs = N/fs의 역수. 더 가까운 두 주파수를 구분하려면 더 오래 봐야 한다
빈 번호 k주파수복소 IQ 신호에서의 의미

FFT 출력은 0 Hz부터 시작해 양의 주파수, 그다음 음의 주파수 순서로 나옵니다. 화면에 −fs/2 … +fs/2 순서로 그리려면 앞뒤 절반을 맞바꾸는 fftshift가 필요합니다. 예를 들어 AD9361을 4 MSPS로 두고 N = 8192 FFT를 하면 빈 폭은 약 488 Hz, 한 번의 FFT가 보는 시간은 약 2 ms입니다.

FFT는 같은 답을 훨씬 빨리 낸다

DFT를 식 그대로 계산하면 빈 N개 × 샘플 N개로 N²번의 복소 곱셈이 필요합니다. FFT(고속 푸리에 변환)는 짝수 번째와 홀수 번째 샘플로 나눠 각각 절반 크기의 DFT를 하고 합치는 일을 재귀적으로 반복해, 약 (N/2) log2N번으로 줄입니다. N = 1024라면 1,048,576번 대신 5,120번, 200배 이상 빠릅니다. 결과는 DFT와 완전히 같습니다. FFT는 근사가 아니라 계산 순서를 바꾼 것입니다.

fft_from_scratch.py · 실행 검증됨
import numpy as np

def fft(x):
    """Radix-2 decimation-in-time FFT. len(x) must be a power of two."""
    n = len(x)
    if n == 1:
        return x.astype(complex)
    even, odd = fft(x[0::2]), fft(x[1::2])           # two half-size DFTs
    tw = np.exp(-2j * np.pi * np.arange(n // 2) / n) * odd   # twiddle factors
    return np.concatenate([even + tw, even - tw])    # the "butterfly"

x = np.random.default_rng(0).standard_normal(1024) + 0j
print("matches numpy:", np.allclose(fft(x), np.fft.fft(x)))
N = 1024
print(f"direct DFT {N * N:,} mults vs FFT {N // 2 * int(np.log2(N)):,} mults")

누설과 창함수: 끝을 부드럽게 접는다

DFT는 암묵적으로 N개 샘플이 무한히 반복된다고 가정합니다. 신호가 관측 구간 안에 정수 번 반복되면 이음매가 매끄럽고, 톤은 빈 하나에 깔끔하게 담깁니다. 그렇지 않으면 이음매에서 파형이 뚝 끊기고, 그 불연속이 모든 주파수로 에너지를 흘려보냅니다. 이것이 스펙트럼 누설(leakage)입니다. 현실의 신호는 빈 정중앙에 떨어지는 일이 거의 없으므로 누설은 항상 있다고 보아야 합니다.

해결책은 샘플에 양 끝이 0으로 내려가는 창함수(window)를 곱해 이음매를 없애는 것입니다. 대가는 주엽(main lobe)이 넓어져 가까운 두 주파수를 구분하는 능력이 떨어진다는 점입니다. 사이드로브를 낮출수록 주엽이 넓어지는, 피할 수 없는 맞바꿈입니다.

dBFS로 읽기: 잡음 바닥은 N에 따라 움직인다

FFT 결과의 크기는 N과 창함수에 따라 달라집니다. 풀스케일 복소 톤이 0 dBFS로 읽히게 하려면 N × (창의 코히어런트 이득)으로 나눠야 합니다. 그러면 톤의 높이는 N과 상관없이 일정해집니다.

잡음은 다르게 행동합니다. 잡음 전력은 모든 빈에 고르게 나뉘므로 빈 하나에 담기는 잡음은 N이 두 배가 될 때마다 절반, 즉 3 dB씩 내려갑니다. 이것을 FFT의 처리 이득이라고 하고 크기는 10 log10(N)입니다. 벤치에서 N을 바꾸면 톤은 그대로인데 잡음 바닥만 오르내리는 것을 볼 수 있습니다. 그래서 "잡음 바닥이 −100 dBFS"라는 말은 빈 폭(정확히는 분해능 대역폭 RBW = ENBW × fs/N)을 함께 말하지 않으면 의미가 없습니다.

spectrum_dbfs.py · 실행 검증됨
import numpy as np

def spectrum_dbfs(x, window=np.hanning):
    """Magnitude spectrum in dBFS: a full-scale complex tone reads 0 dBFS."""
    w = window(len(x))
    X = np.fft.fftshift(np.fft.fft(x * w)) / np.sum(w)   # divide by N * coherent gain
    return 20 * np.log10(np.abs(X) + 1e-15)

rng = np.random.default_rng(1)
fs = 2e6
for N in (1024, 4096):
    n = np.arange(N)
    tone = 0.5 * np.exp(2j * np.pi * 250e3 / fs * n)                  # -6 dBFS
    noise = 10 ** (-60 / 20) / np.sqrt(2) * (rng.standard_normal(N) + 1j * rng.standard_normal(N))
    S = spectrum_dbfs(tone + noise)
    f = np.fft.fftshift(np.fft.fftfreq(N, 1 / fs))
    away = np.abs(f - 250e3) > 50e3                                  # exclude the tone's own bins
    floor = 10 * np.log10(np.mean(10 ** (S[away] / 10)))             # average noise per bin
    print(f"N={N:5d}: tone {S.max():6.1f} dBFS, noise floor {floor:6.1f} dBFS/bin, RBW {1.5 * fs / N:6.0f} Hz")

흔한 함정
  • 제로 패딩은 해상도를 올리지 않는다: 샘플 뒤에 0을 붙여 N을 키우면 빈 간격은 촘촘해지지만, 두 톤을 구분하는 능력은 실제 관측 시간 Tobs로 정해집니다. 제로 패딩은 같은 곡선을 더 촘촘하게 보간해 그릴 뿐입니다.
  • 스캘럽 손실: 톤이 빈 사이에 떨어지면 피크가 실제보다 낮게 읽힙니다. 최악의 경우 사각 창은 약 3.9 dB, Hann은 약 1.4 dB입니다. 진폭을 정밀하게 재야 하면 플랫톱(flat-top) 창을 씁니다.
  • 한 번의 FFT를 믿지 말 것: 잡음 스펙트럼은 FFT마다 요동칩니다. 여러 번의 FFT 전력을 평균(Welch 방법)하면 잡음 바닥이 매끄러워져 약한 신호가 잘 보입니다.
핵심 정리
  • 빈 k의 주파수는 k fs/N. 해상도는 관측 시간의 역수다.
  • 누설은 항상 있다. 창함수는 사이드로브를 낮추는 대신 주엽을 넓힌다.
  • dBFS 정규화는 N × 코히어런트 이득으로. 잡음 바닥은 N이 두 배가 되면 3 dB 내려간다.

이제 신호를 주파수로 볼 수 있습니다. 다음 장에서는 그 주파수 축 위에서 원하는 부분만 남기고 나머지를 깎아 내는 도구, 디지털 필터를 설계합니다. 4장의 "컨볼루션 = 주파수 곱셈"이 설계의 출발점입니다.

디지털 필터: FIR와 IIR

이 장을 마치면: 필터 사양(통과대역, 저지대역, 전이폭, 감쇠량)을 읽고 필요한 탭 수를 추정하며, 창 방식으로 FIR을 직접 설계하고, z변환의 극점·영점으로 IIR 필터의 안정성을 판단하며, 상황에 맞게 FIR과 IIR을 고를 수 있습니다.

필터 사양은 주파수 축 위의 허용 범위다

필터를 설계한다는 것은 주파수 응답 |H(f)|가 지나갈 수 있는 통로를 정하고, 그 통로 안을 지나는 가장 싼 필터를 찾는 일입니다. 사양은 보통 다섯 숫자로 적습니다.

  • 통과대역 끝 fp와 저지대역 시작 fst: 둘 사이가 전이폭 Δf.
  • 통과대역 리플: 통과대역 안에서 이득이 얼마나 출렁여도 되는가 (예: ±0.1 dB).
  • 저지대역 감쇠 A: 막아야 할 대역을 최소 몇 dB 깎는가 (예: 60 dB).

비용을 가장 크게 좌우하는 것은 전이폭과 감쇠량입니다. 오래 쓰여 온 경험식(fred harris의 어림법)이 꽤 잘 맞습니다.

Ntaps ≈ A [dB]22 × fsΔf 예: 60 dB 감쇠, 전이폭 0.05fs → 약 55탭. 전이폭을 절반으로 줄이면 탭 수는 두 배. 최적(등리플) 설계 기준이며, 창 방식은 이보다 많이 든다

FIR 설계: 이상적인 필터를 잘라 창을 씌운다

차단 주파수 fc(fs로 정규화)에서 칼같이 끊기는 이상적 저역통과 필터의 임펄스 응답은 sinc 함수입니다. 4장의 결론, "임펄스 응답의 푸리에 변환이 주파수 응답"을 거꾸로 쓴 것입니다.

hideal[n] = 2fc · sinc(2fcn),   sinc(x) = sin(πx)πx

문제는 이 sinc가 양쪽으로 무한히 길다는 것입니다. 그래서 가운데 N개만 잘라 내고, (N−1)/2만큼 늦춰 인과적으로 만들고, 잘린 가장자리의 충격을 줄이려고 창함수를 곱합니다. 5장에서 스펙트럼 누설을 줄이던 바로 그 창입니다. 이것이 창 방식(windowed-sinc) FIR 설계이고, 창의 종류가 얻을 수 있는 감쇠량을, 탭 수가 전이폭을 결정합니다.

대칭 계수의 두 가지 선물: 선형 위상과 곱셈 절반

창 방식으로 설계한 FIR은 계수가 좌우 대칭입니다(h[k] = h[N−1−k]). 이 대칭에서 두 가지 좋은 성질이 나옵니다.

  • 선형 위상: 모든 주파수가 똑같이 (N−1)/2 샘플만큼 지연됩니다(군지연 일정). 주파수마다 지연이 다르면 파형 모양이 일그러지고, 디지털 변조 신호에서는 심볼끼리 번지는 간섭(ISI)이 됩니다. 통신 수신기에서 FIR을 선호하는 가장 큰 이유입니다.
  • 곱셈 절반: 같은 계수를 곱할 두 샘플을 먼저 더하고(x[n−k] + x[n−N+1+k]) 한 번만 곱하면 됩니다. Zynq의 DSP48E1 슬라이스에 곱셈기 앞의 전치 가산기(pre-adder)가 들어 있는 이유가 정확히 이것입니다.

실무에서는 창 방식 외에 Parks-McClellan(등리플, remez) 같은 최적화 설계를 많이 씁니다. 오차를 통과대역과 저지대역 전체에 고르게 퍼뜨려서, 같은 사양을 훨씬 적은 탭으로 만족시킵니다. 위의 어림식도 이런 최적 설계를 기준으로 한 것입니다. 창 방식은 직관적이고 항상 동작하지만, 탭 수는 앞 표의 전이폭 식(예: Blackman이면 5.5 / 전이폭)으로 계산해야 합니다. 아래 예제가 같은 사양으로 세 방식을 비교합니다.

fir_design.py · 실행 검증됨
import numpy as np
from scipy import signal

fs = 1.0
fp, fst, atten = 0.10, 0.15, 60          # passband edge, stopband edge, required dB

def stopband_db(h):
    w, H = signal.freqz(h, worN=4096, fs=fs)
    return -20 * np.log10(np.max(np.abs(H[w >= fst])))

def smallest(design):
    """Smallest odd tap count whose design meets the stopband spec."""
    for n in range(11, 301, 2):
        h = design(n)
        if stopband_db(h) >= atten:
            return h

print(f"rule of thumb (optimal design): {int(np.ceil(atten / 22 * fs / (fst - fp)))} taps")
h_pm = smallest(lambda n: signal.remez(n, [0, fp, fst, 0.5], [1, 0], weight=[1, 10], fs=fs))
print(f"remez (equiripple)   : {len(h_pm):3d} taps -> {stopband_db(h_pm):.1f} dB")
h_bk = smallest(lambda n: signal.firwin(n, (fp + fst) / 2, window="blackman", fs=fs))
print(f"firwin + blackman    : {len(h_bk):3d} taps -> {stopband_db(h_bk):.1f} dB")
# Hamming's sidelobes cap the attenuation, so more taps do not help much
h_hm = signal.firwin(101, (fp + fst) / 2, window="hamming", fs=fs)
print(f"firwin + hamming     : 101 taps -> {stopband_db(h_hm):.1f} dB (window-limited)")
print("symmetric:", np.allclose(h_pm, h_pm[::-1]))

z변환 한 페이지: 지연은 z−1이다

필터를 블록도로 그리면 상자는 세 종류뿐입니다. 곱셈, 덧셈, 그리고 한 샘플 지연. 이 한 샘플 지연을 z−1이라고 씁니다. 하드웨어로는 클록 하나 늦게 값을 내놓는 레지스터, 즉 플립플롭입니다. 이렇게 쓰면 FIR 필터는 z−1의 다항식이 됩니다.

H(z) = Y(z)X(z) = b0 + b1z−1 + b2z−2 + …1 + a1z−1 + a2z−2 + … 분자가 0이 되는 z는 영점(zero), 분모가 0이 되는 z는 극점(pole). FIR은 분모가 1

z = ejω, 즉 복소 평면의 단위원 위를 따라 H(z)를 계산하면 주파수 응답이 됩니다. 단위원 위에 영점이 있으면 그 주파수가 완전히 막히고(이동 평균의 fs/4, fs/2 영점), 단위원 가까이에 극점이 있으면 그 주파수가 크게 증폭됩니다. 그리고 가장 중요한 규칙 하나. 모든 극점이 단위원 안쪽에 있어야 필터가 안정하다. 밖에 있으면 출력이 발산합니다.

IIR: 되먹임으로 적은 계수, 대신 조심해야 할 것들

분모가 있는 필터는 과거의 출력을 다시 입력으로 씁니다. 임펄스 응답이 이론적으로 영원히 이어지므로 IIR(Infinite Impulse Response)이라고 부릅니다. 임베디드 개발자에게 가장 익숙한 IIR은 지수 이동 평균(EMA)입니다.

y[n] = y[n−1] + α (x[n] − y[n−1])  ⇔  H(z) = α1 − (1−α)z−1 극점은 z = 1 − α. 0 < α < 2이면 단위원 안쪽이라 안정. α가 작을수록 극점이 1에 가까워지고 더 좁은 저역통과가 된다

곱셈 한 번으로 꽤 좋은 저역통과가 됩니다. 같은 날카로움을 FIR로 얻으려면 수십 탭이 필요할 수 있습니다. 실무에서 높은 차수의 IIR은 2차 섹션(biquad)을 여러 개 직렬로 이어서 만듭니다. 고차 다항식 하나로 구현하면 계수 반올림만으로도 극점이 크게 움직여 불안정해질 수 있기 때문입니다.

biquad.c 
/* Direct Form I biquad: one second-order section.
 * Cascade several sections for higher-order IIR filters. */
typedef struct { float b0, b1, b2, a1, a2; float x1, x2, y1, y2; } biquad_t;

float biquad_step(biquad_t *s, float x)
{
    float y = s->b0 * x + s->b1 * s->x1 + s->b2 * s->x2
            - s->a1 * s->y1 - s->a2 * s->y2;      /* feedback terms make it IIR */
    s->x2 = s->x1; s->x1 = x;
    s->y2 = s->y1; s->y1 = y;
    return y;
}

FIR의 블록도는 그대로 회로도입니다. z−1은 레지스터 체인, 계수 곱은 DSP 슬라이스, 덧셈은 가산기 트리나 DSP 슬라이스끼리의 캐스케이드 경로입니다. 되먹임이 없으니 레지스터를 추가해 클록을 올려도 결과는 지연만 늘어날 뿐 똑같습니다. IIR은 y[n−1]이 나와야 y[n]을 계산할 수 있어서 루프 안의 곱셈-덧셈이 샘플 주기 하나 안에 끝나야 합니다. 샘플률이 클록에 가까워질수록 IIR이 FPGA에서 불리해지는 이유입니다.

흔한 함정
  • 정규화 주파수 단위 혼동: 도구마다 1이 fs인지 fs/2(나이퀴스트)인지 다릅니다. MATLAB과 예전 scipy 관례는 나이퀴스트 = 1입니다. 위 예제처럼 fs=를 명시하면 헷갈릴 일이 없습니다.
  • 통과대역 이득: 창 방식 FIR은 계수 합을 1로 맞춰야 직류 이득이 0 dB입니다. 고정소수점으로 옮길 때 이 합이 풀스케일을 넘지 않는지도 확인하세요.
  • IIR을 쓴 뒤 심볼이 번진다: 비선형 위상 때문입니다. 변조 신호 경로에는 선형 위상 FIR을 쓰세요.
핵심 정리
  • 탭 수 ≈ (감쇠 dB / 22) × (fs / 전이폭). 감쇠는 창이, 전이폭은 탭 수가 정한다.
  • 대칭 FIR = 선형 위상 + 곱셈 절반. 통신 체인의 기본 부품.
  • z−1은 레지스터. 극점이 단위원 안에 있어야 안정. IIR은 싸지만 위상과 정밀도에 조심.

Part II를 마쳤습니다. 컨볼루션, FFT, 필터라는 세 도구가 손에 들어왔습니다. Part III에서는 이 도구로 실제 RF 수신 체인을 조립합니다. 첫 번째 과제는 61.44 MSPS로 쏟아지는 샘플을, 정보를 잃지 않고 필요한 만큼으로 줄이는 일입니다.

데시메이션과 인터폴레이션

이 장을 마치면: 앨리어싱 없이 샘플률을 낮추고 올리는 절차를 설명하고, 폴리페이즈 구조로 연산량을 M배 줄이며, CIC와 하프밴드 필터를 언제 쓰는지 판단하고, AD9361 계열 트랜시버의 수신 디지털 체인과 샘플률 제약을 읽을 수 있습니다.

데시메이션: 거르고 나서 버린다

61.44 MSPS로 받았는데 관심 신호의 대역폭이 200 kHz라면 샘플 대부분은 쓸모없는 대역을 담고 있습니다. 샘플률을 M배 낮추는 것을 데시메이션(decimation)이라고 합니다. M개 중 하나만 남기면 되지만, 2장의 마지막 경고를 떠올리세요. 샘플을 솎아 내는 것은 fs/M으로 다시 샘플링하는 것과 같아서, 새 나이퀴스트 범위 밖의 모든 것이 안쪽으로 접혀 들어옵니다.

x[n] → LPF (차단 ≈ fs/2M) → ↓M (M개 중 1개) → y[m] at fs/M

그래서 데시메이션은 항상 "거르고 나서 버리기"입니다. 거르기를 잘하면 보너스도 있습니다. 관심 대역 밖의 잡음을 함께 걸러 내므로, 신호가 좁은 대역에 있고 잡음이 원래 대역 전체에 퍼져 있었다면 데시메이션 후의 SNR은 그대로이면서 데이터율은 M배 줄어듭니다. 원래 대역 전체로 따진 SNR과 비교하면 10 log10M dB의 처리 이득을 얻은 셈입니다.

필터 사양을 정할 때 알아 두면 좋은 요령이 하나 있습니다. 출력에서 실제로 쓰는 대역이 fp까지라면, 저지대역은 fs/2M이 아니라 fs/M − fp부터 시작해도 됩니다. 그 사이의 성분은 접혀서 쓰지 않는 전이대역 위로 떨어지기 때문입니다. 전이폭이 넓어지는 만큼 탭 수가 줄어듭니다.

인터폴레이션: 0을 끼우고 거른다

반대로 샘플률을 L배 올리려면 샘플 사이에 0을 L−1개씩 끼웁니다. 그러면 원래 스펙트럼이 새 샘플률 안에서 L번 반복된 모양(이미지)이 생기는데, 저역통과 필터로 첫 번째 것만 남기면 매끄럽게 보간된 신호가 됩니다. 0을 끼우면서 평균 크기가 1/L로 줄었으므로 필터 이득을 L로 잡습니다. 송신 체인의 DUC(디지털 업컨버터)와 DAC 앞단이 이 구조이고, 12장의 송신기도 0을 끼운 뒤 펄스 성형 필터를 통과시키는 인터폴레이션입니다.

폴리페이즈: 버릴 출력은 계산하지 않는다

데시메이션을 곧이곧대로 구현하면 필터가 원래 샘플률로 모든 출력을 계산하고, 그중 M−1개를 버립니다. 낭비입니다. 컨볼루션 식을 들여다보면 남길 출력만 계산할 수 있습니다. 계수를 M개의 묶음으로 나눠, p번째 부분 필터가 h[p], h[p+M], h[p+2M], …을 맡게 하면, 각 부분 필터는 입력의 p번째 위상 샘플만 받아 낮은 샘플률로 동작합니다. 이것이 폴리페이즈(polyphase) 분해입니다.

polyphase.py · 실행 검증됨
import numpy as np
from scipy import signal

M = 4
h = signal.firwin(48, 0.8 / M)                 # anti-alias filter for decimate-by-4
x = np.random.default_rng(3).standard_normal(4000)

# Naive: filter at the input rate, then keep every M-th output
naive = np.convolve(x, h)[::M]

# Polyphase: sub-filter p sees input phase p; all work happens at fs/M
L = len(x) // M + len(h) // M + 1
xp = np.zeros(L * M); xp[:len(x)] = x
y = np.zeros(L)
for p in range(M):
    hp = h[p::M]                               # p-th polyphase component
    xph = np.concatenate([np.zeros(1), xp[M - p::M]]) if p else xp[0::M]
    y += np.convolve(xph[:L], hp)[:L]

n = min(len(naive), len(y)) - 20
print("identical output:", np.allclose(naive[:n], y[:n]))
print(f"MACs per input sample: naive {len(h)}, polyphase {len(h) / M:.0f}")

하드웨어가 좋아하는 필터: CIC와 하프밴드

큰 데시메이션 비율을 FIR 하나로 처리하면 전이폭이 좁아 탭 수가 폭발합니다. 그래서 실제 체인은 값싼 단계 여러 개로 나눠 조금씩 줄입니다. 그때 자주 쓰는 두 가지가 있습니다.

  • CIC(Cascaded Integrator-Comb) 필터: 높은 샘플률에서 적분기(누산기) N개, ↓R, 낮은 샘플률에서 미분기(comb) N개. 곱셈기가 하나도 없고 덧셈과 레지스터뿐이라 수십~수백 배 데시메이션의 첫 단계로 이상적입니다. 대가는 두 가지입니다. 응답이 sincN 모양이라 통과대역 끝이 처지므로(droop) 뒤에 보상 FIR이 필요하고, 적분기에서 비트가 N log2(R·D)만큼 늘어나므로(D는 comb 지연, 보통 1) 레지스터를 넉넉히 잡아야 합니다. 2의 보수 산술에서는 적분기가 중간에 오버플로해도 최종 결과가 맞게 나온다는 재미있는 성질이 있습니다.
  • 하프밴드(half-band) 필터: 차단 주파수가 정확히 fs/4인 대칭 FIR. 응답이 fs/4를 중심으로 점대칭이 되도록 설계하면 가운데를 뺀 계수의 절반이 정확히 0이 됩니다. 대칭까지 활용하면 같은 길이의 일반 FIR보다 곱셈이 약 4분의 1입니다. ↓2 단계를 여러 개 이어 붙이는 구조에 딱 맞습니다.

원칙은 하나입니다. 비싼 필터일수록 낮은 샘플률에 둔다. 날카로운 필터는 탭이 많지만, 샘플률이 이미 충분히 낮아진 마지막 단계에 두면 초당 연산량은 작습니다.

AD9361 계열의 수신 디지털 체인 읽기

AD9361을 비롯한 AD936x 트랜시버는 ADC 뒤에 정확히 이 원칙대로 만든 데시메이션 체인을 내장하고 있습니다.

이 그림에서 AD936x 드라이버의 이상해 보이던 샘플률 제약이 풀립니다. ADC가 내려갈 수 있는 최저 속도를 25 MSPS로 보고, 하프밴드만으로 최대 12배를 줄이면 25 / 12 ≈ 2.083 MSPS입니다. GNU Radio의 AD936x 계열 문서가 "2.083 MSPS 아래에서는 FIR 필터를 적재하거나 auto로 두어야 한다"고 안내하는 이유입니다. FIR의 ÷4까지 쓰면 25 / 48 ≈ 520.8 kSPS가 되는데, 이것이 같은 문서에 적힌 샘플률 하한입니다. 그보다 낮은 샘플률은 트랜시버 밖, 즉 PL에서 직접 줄여야 합니다. 같은 칩 계열의 PlutoSDR이 최저 65.1 kSPS(정확히 520.8 kSPS의 8분의 1)를 내는 것도 FPGA 쪽에 데시메이션 단계를 하나 더 두었기 때문입니다. RK-ZYNQ7020-F에서도 트랜시버 안에서 할 수 있는 만큼 줄이고 나머지는 PL에서 줄이는 구조가 되며, 여러분이 만들 데시메이터가 바로 그 자리에 들어갑니다.

프로그래머블 FIR의 계수는 ADI가 제공하는 필터 설계 도구(AD9361 Filter Design Wizard)나 드라이버의 자동 설계로 만듭니다. ADI 문서가 강조하듯 이 FIR은 단순한 저역통과가 아니라, 앞단 아날로그 필터와 하프밴드들이 통과대역에 남긴 크기·위상 왜곡을 되돌리는 보상기이기도 합니다.

흔한 함정
  • 버리고 나서 거르기: 순서를 바꾸면 앨리어싱이 이미 일어난 뒤입니다. 어떤 최적화를 하든 "필터 → ↓M"과 수학적으로 같은지 확인하세요. 폴리페이즈는 같습니다.
  • 단계별 지연 누적: 각 필터의 군지연이 서로 다른 샘플률에서 쌓입니다. 송수신 왕복 지연이나 타임스탬프가 중요하면 단계마다 계산해 합산하세요.
  • CIC 이득: CIC의 직류 이득은 (RD)N입니다. R = 64, N = 4면 224배. 출력 비트를 그만큼 잘라 내야 합니다.
핵심 정리
  • 데시메이션은 반드시 거르고 나서 버린다. 인터폴레이션은 0을 끼우고 이미지를 거른다.
  • 폴리페이즈는 같은 결과를 M분의 1의 초당 연산으로 낸다.
  • CIC → 하프밴드 → FIR 순서로, 비싼 필터일수록 낮은 샘플률에 둔다.

데시메이션은 대역의 한가운데(0 Hz 주변)만 남깁니다. 그런데 관심 채널이 광대역 캡처의 가장자리에 있다면? 먼저 그 채널을 0 Hz로 옮겨 와야 합니다. 다음 장에서 그 일을 하는 NCO와 DDC를 만듭니다.

믹싱, NCO, DDC

이 장을 마치면: 복소 곱셈으로 스펙트럼을 원하는 만큼 옮기고, 위상 누산기 NCO를 설계해 주파수 해상도와 스퓨리어스를 계산하며, NCO·믹서·데시메이터를 묶은 DDC를 구현하고, 직접 변환 수신기의 DC 오프셋과 IQ 불균형을 진단할 수 있습니다.

곱하면 주파수가 움직인다

3장에서 복소수 곱셈은 각도의 덧셈이라고 했습니다. 주파수 f1로 도는 신호에 e−j2πf0n/fs를 곱하면 각도가 매 샘플 그만큼씩 덜 늘어나므로 결과는 f1 − f0로 돕니다. 신호 하나가 아니라 스펙트럼 전체에 똑같이 적용되므로 스펙트럼이 통째로 −f0만큼 평행 이동합니다. 다른 성분은 생기지 않습니다.

y[n] = x[n] · e−j2πf0n/fs  ⇔  Y(f) = X(f + f0)

실수 코사인을 곱하면 이야기가 다릅니다. cos는 반대로 도는 두 화살표의 합이므로 스펙트럼이 +f0와 −f0 두 방향으로 동시에 옮겨집니다. 합 주파수와 차 주파수가 함께 나오고, 원치 않는 쪽(이미지)을 필터로 제거해야 합니다. 아날로그 믹서가 겪는 이미지 문제의 근원이고, 디지털 영역에서 복소 믹싱을 쓰면 이 문제가 처음부터 없습니다. 비용은 복소 곱셈 하나, 즉 실수 곱셈 4번(입력이 실수면 2번)입니다.

NCO: 위상 누산기 하나와 사인 표 하나

믹싱에 쓸 e−j2πf0n/fs는 FPGA 안에서 수치 제어 발진기(NCO, Numerically Controlled Oscillator)가 만듭니다. 구조는 놀랄 만큼 단순합니다. N비트 누산기가 매 클록 주파수 튜닝 워드(FTW)를 더하고, 누산기 값의 윗부분을 주소로 사인·코사인 표를 읽습니다. 누산기가 넘쳐 0으로 돌아가는 것이 정확히 한 바퀴(2π)입니다. 2의 보수 오버플로가 위상의 랩어라운드와 일치한다는 점이 이 설계의 아름다움입니다.

FTW = round( f0 · 2Nfs ),   해상도 Δf = fs2N 예: N = 32, fs = 61.44 MHz → 약 0.0143 Hz 간격으로 튜닝. 음의 FTW(2의 보수)는 음의 주파수

누산기는 32비트라도 표를 232칸으로 만들 수는 없으니 상위 P비트(예: 10비트, 1024칸)만 주소로 씁니다. 버린 하위 비트 때문에 위상이 계단처럼 오차를 갖고, 이 오차가 주기적이라서 스펙트럼에 스퓨리어스로 나타납니다. 널리 쓰는 어림값은 위상 비트 1개당 약 6 dB, 즉 최악의 스퓨리어스가 대략 −6.02P dBc입니다. 10비트 주소면 약 −60 dBc입니다. 사인파의 대칭을 이용해 4분의 1 주기만 저장하면 같은 메모리로 2비트를 더 얻습니다. 메모리 대신 곱셈 없이 시프트와 덧셈만으로 회전을 계산하는 CORDIC 알고리즘을 쓰기도 합니다.

nco.v 
// Phase-accumulator NCO: 32-bit phase, 10-bit LUT address, 16-bit signed outputs.
// cos_lut.hex / sin_lut.hex hold round(32767*cos(2*pi*k/1024)), k = 0..1023 (two's complement hex).
module nco #(
    parameter PHASE_W = 32,
    parameter ADDR_W  = 10,
    parameter OUT_W   = 16
)(
    input  wire                      clk,
    input  wire                      rst,
    input  wire [PHASE_W-1:0]        ftw,      // frequency tuning word = round(f0 * 2^32 / fs)
    output reg  signed [OUT_W-1:0]   cos_o,
    output reg  signed [OUT_W-1:0]   msin_o    // -sin, ready for down-conversion
);
    reg [PHASE_W-1:0] phase;
    reg signed [OUT_W-1:0] cos_lut [0:(1<<ADDR_W)-1];
    reg signed [OUT_W-1:0] sin_lut [0:(1<<ADDR_W)-1];
    initial begin
        $readmemh("cos_lut.hex", cos_lut);
        $readmemh("sin_lut.hex", sin_lut);
    end

    wire [ADDR_W-1:0] addr = phase[PHASE_W-1 -: ADDR_W];   // keep the top bits only

    always @(posedge clk) begin
        if (rst) phase <= 0;
        else     phase <= phase + ftw;                      // wraps exactly at 2*pi
        cos_o  <= cos_lut[addr];                            // registered ROM read (block RAM)
        msin_o <= -sin_lut[addr];
    end
endmodule

DDC: 옮기고, 거르고, 줄인다

디지털 다운컨버터(DDC)는 지금까지 배운 것을 한 줄로 이은 것입니다. 광대역으로 캡처한 IQ 신호에 NCO를 곱해 원하는 채널을 0 Hz로 옮기고(8장), 저역통과로 그 채널만 남기고(6장), 샘플률을 채널 폭에 맞게 줄입니다(7장). 수신 체인에서 하드웨어 LO가 대략적인 튜닝을, DDC가 정밀한 채널 선택을 맡습니다. RFSoC의 RF-ADC 타일에도 NCO와 복소 믹서, 데시메이션 필터로 된 DDC가 하드 블록으로 들어 있습니다.

광대역 캡처에 세 개의 "방송국" A(−600 kHz), B(+250 kHz, 가장 약함), C(+700 kHz)가 있습니다. NCO를 250 kHz에 두면 B가 0 Hz로 옮겨지고, 필터와 ↓8을 거치면 250 kHz 폭의 출력에 B만 남습니다. 이제 필터를 끄세요. 버려진 대역에 있던 A와 C가 접혀 들어와 B를 덮습니다. 7장의 "거르고 나서 버린다"를 눈으로 확인하는 순간입니다. NCO를 −600 kHz로 옮기면 A가 선택됩니다.

ddc.py · 실행 검증됨
import numpy as np
from scipy import signal

fs, N = 2e6, 1 << 15
n = np.arange(N)
rng = np.random.default_rng(5)
# Wideband capture: three narrowband "stations" plus noise
x = (1.00 * np.exp(2j * np.pi * -600e3 / fs * n)
     + 0.10 * np.exp(2j * np.pi * (250e3 + 3e3) / fs * n)     # station B sits 3 kHz above 250 kHz
     + 0.30 * np.exp(2j * np.pi * 700e3 / fs * n)
     + 1e-3 * (rng.standard_normal(N) + 1j * rng.standard_normal(N)))

def ddc(x, f0, fs, M, ntaps=129):
    nco = np.exp(-2j * np.pi * f0 / fs * np.arange(len(x)))   # NCO
    y = x * nco                                                 # complex mixer: shift by -f0
    h = signal.firwin(ntaps, 0.8 / M)                           # anti-alias, cutoff 0.4 * fs/M
    return signal.lfilter(h, 1, y)[::M], fs / M                 # filter, then decimate

y, fs_out = ddc(x, 250e3, fs, M=8)
Y = np.fft.fftshift(np.abs(np.fft.fft(y[200:] * np.hanning(len(y) - 200))))
f = np.fft.fftshift(np.fft.fftfreq(len(y) - 200, 1 / fs_out))
print(f"output rate {fs_out / 1e3:.0f} kSPS, strongest component at {f[np.argmax(Y)] / 1e3:+.2f} kHz")
Ydb = 20 * np.log10(Y / Y.max())
print(f"worst other component: {np.max(Ydb[np.abs(f) > 10e3]):.1f} dB relative to station B")

직접 변환 수신기의 흠과 오프셋 튜닝

AD9361 같은 직접 변환(zero-IF) 수신기는 RF를 한 번에 0 Hz로 내리므로 구조가 단순하고 집적하기 좋지만, 아날로그 IQ 믹서의 불완전함이 0 Hz 주변에 그대로 드러납니다.

  • DC 오프셋과 LO 누설: LO 신호가 자기 자신과 섞이거나 회로의 오프셋이 더해져 정확히 0 Hz에 스파이크가 생깁니다. 트랜시버의 DC 보정이 대부분 지우지만 완벽하지는 않습니다.
  • IQ 불균형: I 경로 이득이 Q 경로보다 ε만큼 크거나, 두 LO의 위상차가 90°에서 φ만큼 어긋나면 +f의 신호가 −f에 거울상을 만듭니다. 오차가 작을 때 이미지 제거비(IRR)는 대략 다음과 같습니다.
IRR ≈ 10 log10 4ε² + φ²  [dB] ε는 이득 오차 비율, φ는 위상 오차(라디안). 이득 1%, 위상 1°면 약 40 dB

해결책은 대개 디지털에서 찾습니다. 첫째, 하드웨어 LO를 관심 신호에서 일부러 조금 비켜(오프셋 튜닝) 신호가 0 Hz가 아닌 곳에 오게 하고, 마지막 정밀 튜닝은 DDC의 NCO로 합니다. 그러면 DC 스파이크는 DDC의 저역통과 필터 밖으로 밀려나 사라집니다. 둘째, 이미지는 대역 안의 다른 신호 위치에 따라 문제가 되기도 하고 안 되기도 하니, 강한 신호의 거울 위치에 약한 관심 신호가 오지 않도록 LO를 고릅니다. 셋째, 남은 불균형은 트랜시버의 직교 보정이나 디지털 IQ 보정 블록으로 줄입니다.

import numpy as np

def image_rejection_db(eps, phi_deg, N=4096):
    """Measure the image of a +f tone after a receiver with IQ gain/phase error."""
    n = np.arange(N); phi = np.deg2rad(phi_deg)
    th = 2 * np.pi * 300 / N * n                      # tone exactly on bin +300
    i = (1 + eps / 2) * np.cos(th)                    # I path a bit hot
    q = (1 - eps / 2) * np.sin(th + phi)              # Q path a bit cold and skewed
    X = np.abs(np.fft.fft(i + 1j * q))
    return 20 * np.log10(X[300] / X[-300])            # wanted (+f) over image (-f)

for eps, ph in ((0.01, 1.0), (0.05, 3.0)):
    approx = 10 * np.log10(4 / (eps ** 2 + np.deg2rad(ph) ** 2))
    print(f"gain {eps:.0%}, phase {ph} deg: measured {image_rejection_db(eps, ph):.1f} dB, approx {approx:.1f} dB")

FPGA 엔지니어의 눈으로

DDC는 PL에서 가장 먼저 만들어 볼 만한 블록입니다. 입력은 트랜시버 인터페이스 코어가 내놓는 IQ 스트림, 출력은 DMA로 가는 낮은 샘플률 IQ 스트림, 제어는 PS가 AXI-Lite 레지스터로 쓰는 FTW와 데시메이션 비율 하나씩입니다. NCO는 블록 RAM 하나, 복소 믹서는 DSP 슬라이스 3~4개, 데시메이터는 CIC나 하프밴드 몇 단으로 Z-7020에 넉넉히 들어갑니다. 레지스터 맵, 스트림 핸드셰이크(tvalid/tready), 리셋 순서처럼 익숙한 문제들이 신호처리 블록에서도 그대로 중요합니다.

흔한 함정
  • 부호 반대: 다운컨버전에는 e−j…가 필요합니다. e+j…를 곱하면 신호가 0 Hz가 아니라 2f0 쪽으로 갑니다. 테스트 톤으로 방향부터 확인하세요.
  • NCO 출력 크기: 표를 32767로 채우면 곱셈 결과가 정확히 215배가 되지 않습니다(32767 ≠ 32768). 이득 오차가 문제가 되는 곳에서는 스케일을 명시적으로 보정하세요.
  • 필터를 넉넉히: 데시메이션 필터의 저지대역이 약하면 인접 채널의 강한 신호가 접혀 들어옵니다. 사양은 가장 강한 인접 신호를 기준으로 정합니다.
핵심 정리
  • 복소 지수를 곱하면 스펙트럼이 평행 이동한다. 실수 코사인은 양쪽으로 옮겨 이미지를 만든다.
  • NCO = 위상 누산기 + 사인 표. 해상도 fs/2N, 위상 비트 1개당 스퓨리어스 약 6 dB.
  • DDC = NCO × 입력 → 저역통과 → ↓M. LO는 비켜 두고 DDC로 정밀 튜닝하면 DC 문제를 피한다.

지금까지는 모든 계산을 실수로 했습니다. 하지만 FPGA에는 부동소수점이 기본으로 없고, 비트 하나하나가 자원입니다. 다음 장에서는 이 모든 블록을 정수로 옮기는 방법, 그리고 PL과 PS 사이에 일을 나누는 방법을 다룹니다.

FPGA에는 실수가 없다: Q 형식

FPGA의 기본 재료는 정수 덧셈기와 곱셈기입니다. 신호처리는 −1과 1 사이의 실수로 설계하므로 둘을 잇는 약속이 필요한데, 그것이 고정소수점(fixed-point)입니다. 정수 하나를 쓰되 "이 정수를 2n으로 나눈 값으로 읽자"고 약속하는 것입니다. 정수부 m비트(부호 포함)와 소수부 n비트를 쓰는 형식을 Qm.n이라고 씁니다.

형식전체 비트범위최소 단위쓰임
Q1.1112−1 ~ +0.99952−1112비트 ADC 샘플 (AD9361)
Q1.1516−1 ~ +0.999972−15DSP 표준 샘플·계수 형식

곱셈의 규칙은 단순합니다. Qa.b × Qc.d = Q(a+c).(b+d). 두 Q1.15를 곱하면 Q2.30이 되는데, 정수부가 2비트로 늘어나는 이유는 단 하나의 경우, (−1) × (−1) = +1 때문입니다. 이 값은 Q1.15로 표현할 수 없어서, 결과를 다시 15비트 시프트해 16비트로 줄일 때 포화 처리를 하지 않으면 +1이 −1로 뒤집힙니다. 4장 C 코드가 마지막에 포화를 한 이유입니다.

양자화 잡음: 비트 하나에 6 dB

실수를 정수로 반올림하면 매번 최대 반 단위(Δ/2)의 오차가 생깁니다. 신호가 충분히 복잡하면 이 오차는 −Δ/2 ~ +Δ/2에 고르게 퍼진 잡음처럼 행동하고, 그 전력은 Δ²/12입니다. 풀스케일 사인파의 전력과 비교하면 신호 대 양자화 잡음비가 나옵니다.

SQNR = 6.02 · b + 1.76  [dB] b비트로 풀스케일 사인파를 표현할 때. 신호가 풀스케일보다 X dB 작으면 SQNR도 X dB 줄어든다

12비트 ADC의 이상적인 SQNR은 약 74 dB, 16비트 데이터 경로는 약 98 dB입니다. 실무 규칙도 여기서 나옵니다. 데이터 경로의 비트 수는 ADC보다 몇 비트 더 넉넉하게 잡아, 처리 과정의 반올림 잡음이 ADC 자체의 잡음보다 충분히 작게 합니다. 그리고 반올림 방식도 중요합니다. 하위 비트를 그냥 잘라 내는 버림(truncation)은 오차가 항상 음수 쪽(−Δ ~ 0)이라 평균이 −Δ/2인 DC 편향을 만듭니다. 한 번은 작아도 적분기나 IIR 되먹임 안에서는 누적됩니다.

비트 성장: 곱하면 더해지고, 더하면 늘어난다

정밀도를 유지하려면 연산 중간 결과의 비트 수를 계산해 둬야 합니다. 규칙은 두 가지입니다. b1비트와 b2비트의 곱은 b1 + b2비트, K개 값의 합은 ⌈log2K⌉비트가 더 필요합니다. 그래서 FIR 누산기의 최악 폭은 다음과 같습니다.

누산기 비트 = b입력 + b계수 + ⌈log2 Ntaps⌉ 예: 12비트 입력, 16비트 계수, 64탭 → 12 + 16 + 6 = 34비트. DSP48E1의 48비트 누산기에 여유 있게 들어간다

이 식은 모든 입력이 동시에 최댓값이고 부호가 계수와 맞아떨어지는 최악의 경우입니다. 계수 절댓값의 합 Σ|h|이 1 근처인 저역통과 필터라면 실제로는 log2Σ|h|비트만큼만 자라므로 더 줄일 수 있습니다. 어느 쪽이든 원칙은 같습니다. 중간에는 넉넉하게, 출력에서 한 번만 반올림하고 포화한다.

fixed_point_fir.py · 실행 검증됨
import numpy as np
from scipy import signal

def quantize(x, frac_bits, total_bits):
    """Round to nearest and saturate: what the hardware will do."""
    q = np.round(x * 2 ** frac_bits)
    lim = 2 ** (total_bits - 1)
    return np.clip(q, -lim, lim - 1).astype(np.int64)

h = signal.firwin(63, 0.2)
x = 0.9 * np.sin(2 * np.pi * 0.0123 * np.arange(20000))      # input in [-1, 1)

ref = np.convolve(x, h)                                      # floating-point reference

xq = quantize(x, 11, 12)                                     # Q1.11 ADC samples
for cb in (16, 12, 8):
    hq = quantize(h, cb - 1, cb)                             # Q1.(cb-1) coefficients
    acc = np.convolve(xq, hq)                                # exact integer accumulate
    print(f"coef {cb:2d}-bit: accumulator needs {int(np.abs(acc).max()).bit_length() + 1} bits", end=", ")
    y = quantize(acc / 2 ** (11 + cb - 1), 15, 16) / 2 ** 15  # round + saturate to Q1.15 output
    err = y - ref
    sqnr = 10 * np.log10(np.sum(ref[100:-100] ** 2) / np.sum(err[100:-100] ** 2))
    print(f"output SQNR {sqnr:5.1f} dB")
print(f"ideal 12-bit ADC SQNR for this level: {6.02 * 12 + 1.76 + 20 * np.log10(0.9):.1f} dB")

DSP 슬라이스에 FIR 올리기

Zynq-7000의 DSP48E1 슬라이스는 FIR을 위해 만든 것처럼 생겼습니다. 핵심만 그리면 다음과 같습니다.

각 부품이 FIR의 한 조각과 정확히 대응합니다. 전치 가산기는 대칭 계수의 두 샘플을 먼저 더하고(6장), 곱셈기는 계수를 곱하고, 48비트 ALU는 이전 슬라이스의 부분합(PCIN)을 더해 다음 슬라이스로 넘깁니다(PCOUT). 슬라이스를 사슬처럼 이으면 범용 로직을 거의 쓰지 않는 FIR이 됩니다. 이렇게 매 단계의 출력에 레지스터를 두는 전치형(transposed) 구조는 클록을 높이기 좋습니다.

fir_transposed.v 
// Transposed-form FIR: one multiplier per tap, partial sums move through registers.
// Infers a DSP48 cascade: every stage is "multiply + add previous partial sum".
module fir_transposed #(
    parameter NTAPS = 16,
    parameter IW = 12, parameter CW = 18, parameter AW = 48,
    parameter signed [CW*NTAPS-1:0] COEF = 0      // packed taps, h[0] in the low bits
)(
    input  wire                 clk,
    input  wire                 ce,               // one input sample per enabled clock
    input  wire signed [IW-1:0] x,
    output wire signed [AW-1:0] y
);
    reg signed [AW-1:0] acc [0:NTAPS-1];
    integer k;
    initial for (k = 0; k < NTAPS; k = k + 1) acc[k] = 0;   // FPGA registers power up at 0
    always @(posedge clk) if (ce) begin
        // the newest sample meets every coefficient at once
        for (k = 0; k < NTAPS - 1; k = k + 1)
            acc[k] <= acc[k+1] + x * $signed(COEF[CW*k +: CW]);       // h[k]
        acc[NTAPS-1] <= x * $signed(COEF[CW*(NTAPS-1) +: CW]);       // h[N-1]
    end
    assign y = acc[0];                            // round + saturate downstream
endmodule

HDL 대신 C++로 기술하고 Vitis HLS로 합성하는 방법도 있습니다. 고정소수점 타입 ap_fixed가 비트 폭과 반올림·포화 모드를 타입에 담아 주므로, 위의 비트 정확 모델과 거의 같은 코드가 됩니다.

#include <hls_stream.h>

typedef ap_fixed<12, 1> sample_t;                       // Q1.11 input
typedef ap_fixed<18, 1> coef_t;                         // Q1.17 coefficients

typedef ap_fixed<16, 1, AP_RND_CONV, AP_SAT> out_t;     // convergent rounding + saturation

const int N = 63;
const coef_t H[N] = { /* paste firwin() output here */ };

void fir(hls::stream<sample_t> &in, hls::stream<out_t> &out)
{
#pragma HLS INTERFACE axis port=in
#pragma HLS INTERFACE axis port=out
#pragma HLS PIPELINE II=1
    static sample_t z[N];                               // delay line
#pragma HLS ARRAY_PARTITION variable=z complete
    acc_t acc = 0;
    for (int k = N - 1; k > 0; k--) {
        z[k] = z[k - 1];
        acc += z[k] * H[k];
    }
    z[0] = in.read();
    acc += z[0] * H[0];
    out.write(acc);                                     // quantization happens in this cast
}

자원 추정은 클록과 샘플률의 비율에서 시작합니다. R = fclk / fs라면 DSP 슬라이스 하나가 샘플 하나당 R번의 MAC을 할 수 있으므로, 시간 다중화(folding)로 슬라이스 하나를 여러 탭이 나눠 쓸 수 있습니다.

비트를 평면 위의 점으로

3장에서 IQ 신호 하나는 매 순간 복소 평면의 한 점이었습니다. 디지털 변조는 이 평면에 미리 정해 둔 점 몇 개를 찍어 두고, 보내려는 비트에 따라 그중 하나를 고르는 일입니다. 이 점들의 배치를 성상도(constellation), 고른 점 하나를 심볼이라고 부릅니다. 점이 M개면 심볼 하나가 log2M비트를 나릅니다.

비트 배정에는 그레이 코드(Gray code)를 씁니다. 이웃한 점끼리는 한 비트만 다르게 배정해 두면, 잡음 때문에 옆 점으로 잘못 판정해도 비트 오류는 하나뿐입니다. 비트율과 심볼률의 관계는 Rb = Rs · log2M입니다. 1 Msym/s의 QPSK는 2 Mbps입니다.

펄스 성형: 점과 점 사이를 어떻게 잇나

심볼을 한 샘플씩 찍고 그 사이를 그냥 유지하면(직사각형 펄스) 파형에 급격한 계단이 생기고, 스펙트럼은 sinc 모양으로 멀리까지 퍼져 옆 채널을 침범합니다. 그래서 심볼마다 부드러운 펄스 모양을 입혀 대역폭을 제한하는데, 이것을 펄스 성형(pulse shaping)이라고 합니다. 구현은 7장의 인터폴레이션 그대로입니다. 심볼 사이에 0을 끼우고(심볼당 샘플 수 sps만큼) 성형 필터를 통과시킵니다.

펄스를 아무렇게나 고를 수는 없습니다. 이웃 심볼의 펄스 꼬리가 현재 심볼의 판정 시점에 겹치면 심볼 간 간섭(ISI)이 생깁니다. 나이퀴스트가 찾은 조건은 "펄스가 다른 모든 심볼의 판정 시점에서 정확히 0일 것"이고, 이를 만족하면서 대역폭을 조절할 수 있는 것이 상승 코사인(raised cosine) 펄스입니다. 롤오프 계수 β(0~1)가 대역폭과 꼬리 길이를 맞바꿉니다.

점유 대역폭 = Rs (1 + β) RF에서의 폭. β = 0.35인 1 Msym/s 신호는 1.35 MHz를 쓴다. β가 작을수록 좁지만 꼬리가 길어 타이밍 오차에 민감하다

실제로는 상승 코사인을 반으로 나눈 루트 상승 코사인(RRC) 필터를 송신기와 수신기에 하나씩 둡니다. 두 RRC를 이으면 상승 코사인이 되어 ISI가 없고, 동시에 수신 RRC는 송신 펄스와 같은 모양이라 정합 필터(matched filter)가 됩니다. 정합 필터는 백색 잡음 속에서 판정 시점의 SNR을 최대로 만드는 필터로, 직관적으로는 "기다리는 모양과 가장 닮은 것을 찾는 상관기"입니다. 송신 성형과 수신 잡음 제거를 한 쌍의 필터로 동시에 해결하는 셈입니다.

pulse_shaping.py · 실행 검증됨
import numpy as np
from math import erfc, sqrt
from mini_rx import rrc, qpsk_map, qpsk_demap   # book code: signal-processing-for-rf/code/

SPS = 4
h = rrc(beta=0.35, sps=SPS, span=8)
rng = np.random.default_rng(10)

def run(ebn0_db, nsym=100_000):
    bits = rng.integers(0, 2, 2 * nsym)
    up = np.zeros(nsym * SPS, complex); up[::SPS] = qpsk_map(bits)
    tx = np.convolve(up, h)                                   # TX pulse shaping
    n0 = 10 ** (-(ebn0_db + 10 * np.log10(2)) / 10)           # Es/N0 = Eb/N0 + 3 dB for QPSK
    rx = tx + np.sqrt(n0 / 2) * (rng.standard_normal(len(tx)) + 1j * rng.standard_normal(len(tx)))
    y = np.convolve(rx, h)                                    # RX matched filter
    d = len(h) - 1                                            # total delay of RRC + RRC
    sym = y[d: d + nsym * SPS: SPS]                           # sample at the eye opening
    return np.mean(qpsk_demap(sym) != bits)

print(f"{'Eb/N0':>6} {'simulated':>10} {'theory':>10}")
for e in (2, 4, 6, 8):
    print(f"{e:4d} dB {run(e):10.2e} {0.5 * erfc(sqrt(10 ** (e / 10))):10.2e}")

  • Es/N0와 Eb/N0: 심볼(비트) 하나의 에너지 대 잡음 전력 밀도. Eb/N0 = Es/N0 − 10 log10(log2M). QPSK는 3 dB 차이입니다. 변조 방식끼리 공정하게 비교할 때는 Eb/N0를 씁니다.

  • BER/SER: 비트(심볼) 오류율. 최종 성능이지만 재는 데 많은 비트가 필요합니다. 10−6을 확인하려면 수백만 비트를 보내야 합니다.

성상도는 RF 신호용 로직 분석기입니다. 디지털 버스를 디버깅할 때 오실로스코프로 눈(eye) 패턴부터 보듯, 수신기를 디버깅할 때는 성상도와 EVM부터 봅니다. 그리고 숫자로 남기세요. "그림이 좀 지저분하다"가 아니라 "EVM −18 dB, 회전 속도 0.002 사이클/심볼"이라고 기록해야 수정 전후를 비교할 수 있습니다.

흔한 함정
  • SNR 정의 혼동: 샘플당 SNR, Es/N0, Eb/N0는 서로 다릅니다. sps = 4로 오버샘플링하면 샘플당 SNR은 Es/N0보다 약 6 dB 낮습니다. 시뮬레이션 잡음을 넣을 때 무엇을 기준으로 했는지 반드시 적으세요.
  • 필터 지연 계산: RRC 두 개의 지연은 필터 길이 − 1 샘플입니다. 이걸 틀리면 판정 시점이 어긋나 ISI가 생기고, BER 곡선이 이론에서 멀어집니다.
  • 그레이 코드 생략: 자연 이진 순서로 배정하면 이웃 점 오판정이 2비트 오류가 되어 BER이 나빠집니다.
핵심 정리

  • RRC 송신 + RRC 수신 = ISI 없는 상승 코사인 + 정합 필터. 대역폭 Rs(1+β).
  • EVM² ≈ 1/SNR. 성상도의 모양이 결함의 종류를 알려 준다.

두 개의 시계가 만드는 오차들

송신기와 수신기는 각자의 수정 발진기로 LO와 샘플 클록을 만듭니다. 두 발진기는 절대 똑같지 않습니다. 흔한 수정 발진기의 정확도가 ±20 ppm이라고 하면, 2.4 GHz에서 20 ppm은 48 kHz입니다. 송신기가 +20 ppm, 수신기가 −20 ppm이면 상대 오차는 96 kHz가 됩니다. 심볼률 1 Msym/s라면 매 심볼 약 0.1 사이클, 즉 35°씩 성상도가 돌아갑니다. FMC-9361 기준 클록의 실제 ppm은 판매처 자료로 확인하세요(같은 계열 PlutoSDR의 사양은 ±25 ppm입니다). 10장의 벤치에서 본 링 모양은 극히 일부에 불과합니다.

AGC가 먼저인 이유는 뒤의 모든 오차 검출기의 출력이 신호 크기에 비례하기 때문입니다. 크기가 들쭉날쭉하면 같은 루프 이득이 어떤 때는 너무 세고 어떤 때는 너무 약합니다. 거친 CFO가 정합 필터보다 먼저인 이유는, 주파수 오차가 크면 신호가 정합 필터 통과대역에서 비켜나 에너지를 잃고, PLL의 끌어당김 범위(pull-in range)도 넘기 때문입니다. 타이밍이 위상보다 먼저인 이유는 위상 검출기가 눈의 정중앙 샘플을 필요로 하고, 가드너 검출기는 반송파 위상과 상관없이 동작하기 때문입니다. 프레임 동기가 마지막인 이유는 깨끗한 심볼이 있어야 상관 피크가 선명하기 때문입니다.

거친 주파수 추정: 4제곱으로 변조를 지운다

QPSK 심볼은 네 각도 45°, 135°, 225°, 315° 중 하나입니다. 이를 4제곱하면 각도가 4배가 되어 모두 180°, 즉 −1이 됩니다. 변조가 사라지는 것입니다. 그런데 신호에 주파수 오프셋 Δf가 있으면 4제곱한 신호는 4Δf로 도는 순수한 톤이 됩니다. FFT로 그 톤의 위치를 찾아 4로 나누면 Δf가 나옵니다.

Δf̂ = 14 · argmaxf | FFT{ x[n]4 } | 모호함 없이 잴 수 있는 범위: |4Δf| < fs/2, 즉 |Δf| < fs/8

단순하고 데이터에 의존하지 않지만, 4제곱이 잡음도 함께 키우므로 낮은 SNR에서는 긴 FFT가 필요하고, 정밀도는 FFT 빈 폭의 4분의 1 정도입니다. 남은 작은 오차는 다음 단계의 PLL이 따라잡습니다. 패킷 통신에서는 반복되는 프리앰블 두 개의 위상 차이로 오프셋을 재는 방법도 많이 씁니다.

PLL: 위상 검출기, 루프 필터, NCO

위상 고정 루프(PLL)는 세 부품의 되먹임 루프입니다. 위상 검출기가 "지금 얼마나 어긋났나"를 재고, 루프 필터가 그 값을 다듬고, 8장의 NCO가 그만큼 회전을 되돌립니다. QPSK용 PLL을 코스타스 루프라고 부르고, 위상 검출기는 판정한 심볼과 받은 심볼의 각도 차이를 근사합니다.

e = sign(I) · Q − sign(Q) · I 보정된 심볼 z = I + jQ가 가장 가까운 이상적인 점보다 반시계로 앞서 있으면 양수, 뒤처져 있으면 음수

루프 필터는 비례-적분(PI) 구조입니다. 비례항(kp)이 위상을 즉시 당기고, 적분항(ki)이 남은 오차를 누적해 주파수 오프셋 자체를 학습합니다. 적분기가 있는 2차 루프는 일정한 주파수 오프셋을 위상 오차 없이 따라갑니다. 두 이득은 정규화 루프 대역폭 BnTs와 감쇠비 ζ(보통 0.707)로 정합니다.

θ = BnTsζ + 1/(4ζ),   kp = 4ζθ1 + 2ζθ + θ²,   ki = 4θ²1 + 2ζθ + θ² 위상 검출기 이득이 1일 때. 다르면 그 이득으로 나눈다
costas_demo.py · 실행 검증됨
import numpy as np
from mini_rx import costas, qpsk_map

rng = np.random.default_rng(4)
nsym = 1500
s = qpsk_map(rng.integers(0, 2, 2 * nsym))
k = np.arange(nsym)
esn0 = 15
noise = np.sqrt(10 ** (-esn0 / 10) / 2) * (rng.standard_normal(nsym) + 1j * rng.standard_normal(nsym))
r = s * np.exp(1j * (2 * np.pi * 0.004 * k + 0.7)) + noise     # CFO 0.004 cycles/symbol, phase 0.7 rad

true_phase = 2 * np.pi * 0.004 * k + 0.7
for bn in (0.003, 0.01, 0.02, 0.08):
    z = costas(r, bn_ts=bn)
    est = np.angle(r * np.conj(z))                                  # the loop's phase estimate
    err = (est - true_phase + np.pi / 4) % (np.pi / 2) - np.pi / 4  # wrap; ignore 90-degree ambiguity
    locked = np.abs(err) < 0.2
    lock_at = next((i for i in range(nsym - 100) if locked[i:i + 100].all()), None)
    if lock_at is None:
        print(f"BnTs={bn:5.3f}: not locked within {nsym} symbols")
    else:
        print(f"BnTs={bn:5.3f}: locked after {lock_at:4d} symbols, "
              f"phase jitter {np.degrees(np.std(err[-500:])):.2f} deg")

타이밍 복구: 눈의 한가운데를 찾아서

정합 필터를 지난 신호는 심볼당 여러 샘플(sps)로 되어 있고, 그중 정확히 눈이 가장 크게 열린 순간의 값을 골라야 합니다. 그런데 그 순간은 대개 샘플 사이에 있고, 송수신 클록 차이 때문에 천천히 흘러갑니다. 현대 SDR은 ADC 클록을 건드리지 않고, 샘플 사이 값을 보간기(interpolator)로 계산해 원하는 순간의 값을 만듭니다. 12장 코드는 4점 3차 보간을 씁니다.

"언제가 한가운데인가"를 재는 대표적인 검출기가 가드너(Gardner) 타이밍 오차 검출기입니다. 심볼 사이의 중간 샘플을 함께 봅니다.

e[k] = Re{ ( y[k−1] − y[k] ) · y*[k−½] } y[k]: 이번 심볼 판정 시점, y[k−1]: 이전 심볼, y[k−½]: 둘 사이 중간

두 심볼의 부호가 다르면 그 사이 어딘가에서 파형이 0을 지납니다. 정확히 가운데서 샘플링하고 있다면 중간 샘플이 바로 그 0 지점이라 오차가 0입니다. 너무 일찍 혹은 늦게 샘플링하면 중간 샘플이 0에서 벗어나고, 그 부호가 어느 쪽으로 옮겨야 하는지 알려 줍니다. 판정이 필요 없고 반송파 위상에도 영향을 받지 않아서, 코스타스 루프보다 앞에 둘 수 있습니다. 이 오차를 PLL과 똑같은 PI 루프 필터로 다듬어 다음 판정 시점을 앞당기거나 늦춥니다.

되먹임 루프에는 약점이 하나 있습니다. 정확히 반 심볼 어긋난 지점에서는 검출기 출력이 거의 0이라 루프가 한참 머뭇거립니다(hang-up). 그래서 루프를 시작하기 전에 피드포워드 추정으로 출발점을 잡아 주면 좋습니다. 정합 필터 출력의 크기 제곱 |y|²은 심볼 중심에서 커지므로 심볼률 주기의 성분을 갖는데, 5장의 DFT로 그 한 주파수 성분의 위상만 구하면 눈의 중심 위치가 나옵니다(Oerder-Meyr 방식). 12장 수신기가 이렇게 출발점을 잡고 가드너로 추적합니다.

프레임 동기와 90° 모호성

코스타스 루프는 성상도를 90°만큼 돌려도 똑같아 보이는 QPSK의 대칭 때문에, 네 각도 중 어디에든 잠길 수 있습니다. 그러면 비트가 체계적으로 뒤바뀝니다. 해결책은 둘입니다. 송신기가 패킷 앞에 수신기도 아는 심볼열(프리앰블)을 넣고, 수신기는 그것과의 상관 피크 위치로 패킷의 시작을, 피크의 위상으로 회전 각도를 알아냅니다. 이때 가장 큰 피크보다 처음 나타난 충분히 강한 피크를 고르는 편이 안전합니다. 데이터가 우연히 프리앰블과 비슷하면 뒤쪽에 비슷한 크기의 피크가 하나 더 생길 수 있기 때문입니다. 또는 비트를 절대 위상이 아니라 이전 심볼과의 위상 차이에 싣는 차분 부호화를 씁니다. 12장 수신기는 프리앰블 방식을 씁니다.

제어 엔지니어의 눈으로

PLL은 PI 제어기입니다. 위상 검출기는 센서, 루프 필터는 제어기, NCO는 적분 특성을 가진 액추에이터입니다. 루프 대역폭은 응답 속도, 감쇠비는 오버슈트입니다. 모터 속도 제어기를 튜닝해 본 경험이 그대로 통하고, 불안정해지는 방식도 같습니다. 이득이 너무 크면 진동하고, 지연(파이프라인 레지스터)이 루프 안에 많으면 위상 여유가 줄어듭니다. FPGA에서 루프를 구현할 때 파이프라인을 마음껏 넣을 수 없는 이유입니다.

흔한 함정
  • 단위 혼동: 주파수 오프셋을 샘플당 사이클로 쟀는지 심볼당 사이클로 쟀는지에 따라 sps배 차이가 납니다. 거친 CFO는 샘플률에서, 코스타스 루프는 심볼률에서 동작합니다.
  • 사이클 슬립: SNR이 낮으면 잡음이 루프를 옆 잠금점(90° 옆)으로 밀어 넘깁니다. 그 순간부터 비트가 뒤바뀝니다. 긴 패킷에는 프리앰블 외에 중간 중간 파일럿 심볼을 넣어 확인합니다.
  • ppm은 양쪽에 있다: 송신기와 수신기의 오차가 더해집니다. 설계는 최악의 합으로 합니다.
핵심 정리
  • ppm × 반송파 주파수 = 주파수 오프셋. 2.4 GHz에서 20 ppm은 48 kHz.
  • AGC → 거친 CFO → 정합 필터 → 타이밍 → 위상 → 프레임. 큰 오차부터 거칠게.
  • PLL = 검출기 + PI 루프 필터 + NCO. 대역폭은 잠금 속도와 지터의 맞바꿈이다.

이제 모든 부품이 준비되었습니다. 마지막 장에서는 이 책의 모든 장을 한 파일에 조립해, 손상된 채널을 통과한 QPSK 신호에서 비트를 오류 없이 꺼내는 수신기를 완성하고, 그것을 PlutoSDR과 FPGA로 옮기는 길을 그립니다.

"""Mini QPSK receiver: TX -> impaired channel -> full sync chain -> BER.
Pure numpy so it runs anywhere."""
import numpy as np

SPS, BETA, SPAN = 4, 0.35, 8          # samples/symbol, RRC roll-off, filter span (symbols)


def rrc(beta=BETA, sps=SPS, span=SPAN):
    """Root-raised-cosine taps normalized to unit energy."""
    t = np.arange(-span * sps // 2, span * sps // 2 + 1) / sps
    h = np.empty_like(t)
    for i, ti in enumerate(t):
        if abs(ti) < 1e-9:
            h[i] = 1 - beta + 4 * beta / np.pi
        elif abs(abs(4 * beta * ti) - 1) < 1e-9:
            h[i] = beta / np.sqrt(2) * ((1 + 2 / np.pi) * np.sin(np.pi / (4 * beta))
                                        + (1 - 2 / np.pi) * np.cos(np.pi / (4 * beta)))
        else:
            h[i] = (np.sin(np.pi * ti * (1 - beta)) + 4 * beta * ti * np.cos(np.pi * ti * (1 + beta))) \
                   / (np.pi * ti * (1 - (4 * beta * ti) ** 2))
    return h / np.sqrt(np.sum(h ** 2))


def qpsk_map(bits):
    """Gray-coded QPSK: bit pair (b0, b1) -> ((1-2*b0) + j(1-2*b1)) / sqrt(2)."""
    b = bits.reshape(-1, 2)
    return ((1 - 2 * b[:, 0]) + 1j * (1 - 2 * b[:, 1])) / np.sqrt(2)


def qpsk_demap(sym):
    return np.column_stack([sym.real < 0, sym.imag < 0]).astype(int).ravel()


SYNC = np.tile([1 + 1j, -1 - 1j], 32) / np.sqrt(2)                  # 64 symbols: lets the loops lock
PREAMBLE = qpsk_map(np.random.default_rng(7).integers(0, 2, 64))   # 32 known symbols: marks frame start
H = rrc()


def transmit(bits):
    sym = np.concatenate([SYNC, PREAMBLE, qpsk_map(bits)])
    up = np.zeros(len(sym) * SPS, complex)
    up[::SPS] = sym                                  # zero-stuff to SPS samples/symbol
    return np.convolve(up, H)                        # pulse shaping


def channel(x, esn0_db, cfo=0.0, phase=0.0, delay=0.0, gain=1.0, rng=None):
    """cfo is normalized to the sample rate (cycles/sample); delay is in samples (fractional ok)."""
    rng = rng or np.random.default_rng()
    n = np.arange(len(x))
    # fractional delay with a windowed-sinc interpolator
    k = np.arange(-16, 17)
    d = np.sinc(k - delay % 1) * np.hamming(len(k))
    x = np.convolve(x, d / d.sum(), mode="same")
    x = np.concatenate([np.zeros(int(delay)), x])
    n = np.arange(len(x))
    x = gain * x * np.exp(1j * (2 * np.pi * cfo * n + phase))
    n0 = gain ** 2 * 10 ** (-esn0_db / 10)                     # unit-energy pulses: Es = 1 per symbol
    noise = np.sqrt(n0 / 2) * (rng.standard_normal(len(x)) + 1j * rng.standard_normal(len(x)))
    return x + noise


def loop_gains(bn_ts, zeta=0.707, kd=1.0):
    """Second-order loop filter gains (proportional, integral) from normalized bandwidth."""
    th = bn_ts / (zeta + 1 / (4 * zeta))
    den = 1 + 2 * zeta * th + th ** 2
    return 4 * zeta * th / den / kd, 4 * th ** 2 / den / kd


def agc(x, target=1.0 / SPS):
    return x * np.sqrt(target / np.mean(np.abs(x) ** 2))


def coarse_cfo(x, nfft=1 << 16):
    """QPSK^4 removes the modulation and leaves a tone at 4*cfo."""
    spec = np.abs(np.fft.fft(x ** 4, nfft))
    f = np.fft.fftfreq(nfft)[np.argmax(spec)] / 4
    return x * np.exp(-2j * np.pi * f * np.arange(len(x))), f


def interp(x, t):
    """Cubic (Catmull-Rom) interpolation of x at fractional index t."""
    i = int(np.floor(t)); mu = t - i
    p0, p1, p2, p3 = x[i - 1], x[i], x[i + 1], x[i + 2]
    return p1 + 0.5 * mu * (p2 - p0 + mu * (2 * p0 - 5 * p1 + 4 * p2 - p3 + mu * (3 * (p1 - p2) + p3 - p0)))


def timing_estimate(y, sps=SPS):
    """Feed-forward (Oerder-Meyr) estimate: |y|^2 peaks at symbol centers, so the phase
    of its symbol-rate spectral line tells where the eye opening is (0..sps samples)."""
    n = np.arange(len(y))
    c = np.sum(np.abs(y) ** 2 * np.exp(-2j * np.pi * n / sps))
    return (-np.angle(c) / (2 * np.pi) * sps) % sps


def gardner(y, sps=SPS, bn_ts=0.01):
    """Gardner timing recovery: returns one sample per symbol at the eye opening."""
    kp, ki = loop_gains(bn_ts, kd=2.7)
    t, v, prev, out = sps + timing_estimate(y, sps), 0.0, 0j, []   # start near the right phase
    while t + sps + 2 < len(y):
        cur = interp(y, t)
        mid = interp(y, t - sps / 2)
        e = np.real((prev - cur) * np.conj(mid))     # timing error detector
        v += ki * e
        t += sps + sps * (kp * e + v)                # advance to next symbol, nudged by the loop
        prev = cur
        out.append(cur)
    return np.array(out)


def costas(s, bn_ts=0.02):
    """QPSK Costas loop: removes residual frequency and phase."""
    kp, ki = loop_gains(bn_ts)
    phase, freq, out = 0.0, 0.0, np.empty_like(s)
    for i, x in enumerate(s):
        z = x * np.exp(-1j * phase)
        e = np.sign(z.real) * z.imag - np.sign(z.imag) * z.real
        freq += ki * e
        phase += freq + kp * e
        out[i] = z
    return out


def frame_sync(s):
    """Find the preamble and undo the 90-degree ambiguity of QPSK."""
    c = np.correlate(s, PREAMBLE, mode="valid")
    k = int(np.argmax(np.abs(c) > 0.7 * np.max(np.abs(c))))    # first strong peak, not the largest
    rot = np.exp(-1j * np.round(np.angle(c[k]) / (np.pi / 2)) * np.pi / 2)
    return s[k + len(PREAMBLE):] * rot


def receive(r):
    r = agc(r)
    r, f_est = coarse_cfo(r)
    y = np.convolve(r, H)                            # matched filter
    y = y / np.sqrt(np.mean(np.abs(y) ** 2))
    s = gardner(y)
    s = costas(s)
    return frame_sync(s), f_est


if __name__ == "__main__":
    rng = np.random.default_rng(2026)
    bits = rng.integers(0, 2, 2 * 4000)
    tx = transmit(bits)
    rx = channel(tx, esn0_db=15, cfo=0.004, phase=1.0, delay=37.4, gain=0.3, rng=rng)
    sym, f_est = receive(rx)
    n = min(len(sym), len(bits) // 2)
    ref = qpsk_map(bits[: 2 * n])
    errors = int(np.sum(qpsk_demap(sym[:n]) != bits[: 2 * n]))
    evm = np.sqrt(np.mean(np.abs(sym[100:n] - ref[100:n]) ** 2))   # skip loop settling
    print(f"coarse CFO estimate : {f_est:+.5f} cycles/sample (true +0.00400)")
    print(f"symbols / bit errors: {n} / {errors}  (BER {errors / (2 * n):.1e})")
    print(f"EVM                 : {20 * np.log10(evm):.1f} dB")

단계 2: 합격 시험은 한 번이 아니라 여러 번

한 번 성공한 수신기는 아직 믿을 수 없습니다. 지연, CFO, 위상, 크기를 매번 무작위로 바꿔 가며 합격 기준을 기계적으로 확인합니다. 하네스 엔지니어링 교본에서 말한 "검증 게이트"를 신호처리에 적용한 것입니다.

acceptance.py · 실행 검증됨
import numpy as np
import mini_rx as m

def trial(seed, esn0_db, nbits=6000):
    rng = np.random.default_rng(seed)
    bits = rng.integers(0, 2, nbits)
    rx = m.channel(m.transmit(bits), esn0_db,
                   cfo=rng.uniform(-0.01, 0.01), phase=rng.uniform(-np.pi, np.pi),
                   delay=rng.uniform(0, 80), gain=rng.uniform(0.1, 5), rng=rng)
    sym, _ = m.receive(rx)
    got = m.qpsk_demap(sym)[:nbits]
    n = len(got)
    return int(np.sum(got != bits[:n])), n

for esn0 in (12, 9):
    results = [trial(s, esn0) for s in range(20)]
    frame_fail = sum(e / n > 0.05 for e, n in results)
    errs = sum(e for e, n in results if e / n <= 0.05)
    total = sum(n for e, n in results if e / n <= 0.05)
    ber = errs / total
    verdict = "PASS" if esn0 != 12 or (frame_fail == 0 and ber < 1e-3) else "FAIL"
    print(f"Es/N0 {esn0:2d} dB: frame failures {frame_fail}/20, BER {ber:.1e}  {verdict if esn0 == 12 else '(margin check)'}")

이 시험은 실제로 버그 두 개를 잡아냈습니다. 첫째, 초기 타이밍이 반 심볼 어긋난 채 시작하면 가드너 루프가 오차 검출기의 이득이 0에 가까운 지점에서 수백 심볼 동안 머뭇거리다가 그사이 한 심볼을 건너뛰었습니다. 그래서 루프를 시작하기 전에 |y|²의 심볼률 성분 위상으로 눈의 중심을 한 번에 추정하는 피드포워드 단계(timing_estimate())를 넣었습니다. 둘째, 특정 시드에서 데이터의 첫 32심볼이 우연히 프리앰블과 같아 상관 피크가 두 개 생겼고, 더 큰 쪽을 고르다 32심볼 늦게 프레임을 잡았습니다. 그래서 "가장 큰 피크"가 아니라 "처음 나타난 강한 피크"를 고르도록 바꿨습니다. 둘 다 한두 번 돌려서는 절대 보이지 않는 문제입니다.

수정 후 12 dB에서 합격입니다. 9 dB 결과는 여유(margin)를 보기 위한 것으로, BER이 이론값보다 조금 나쁜 것은 루프가 잠기는 동안의 오류와 루프 지터 때문입니다. 이 차이를 구현 손실(implementation loss)이라고 부르고, 좋은 수신기는 1 dB 안쪽으로 줄입니다. 루프 대역폭을 바꿔 가며 이 숫자를 개선해 보는 것이 첫 번째 연습입니다.

단계 3: 진짜 전파로, FMC-9361 루프백

9장 끝의 포팅을 마쳐 보드에서 iio_info가 AD9361을 보여 주면, 이제 channel()을 진짜 하드웨어로 바꿉니다. PC의 pyadi-iio가 이더넷으로 보드의 IIO 서버에 접속하는 구조입니다. 처음에는 안테나 대신 SMA 케이블과 30 dB 이상의 감쇠기로 TX1과 RX1을 직접 잇는 것을 권합니다. FMC-9361은 송신단에 증폭기가 더 붙어 있어 특히 중요합니다. 수신단 과입력을 막고, 전파를 밖으로 내보내지 않으며, 결과가 재현 가능합니다. 2.4 GHz ISM 대역이라도 무선 출력과 용도에는 각 나라의 전파 규정이 적용된다는 점을 기억하세요.

import numpy as np
import adi                                   # pip install pyadi-iio
from mini_rx import transmit, receive, qpsk_demap

fs = 2_500_000                               # above 2.083 MSPS: no FIR load needed (chapter 7)
sdr = adi.ad9361(uri="ip:192.168.1.10")      # the board's IP; its Linux runs the IIO server
sdr.rx_enabled_channels = [0]                # AD9361 is 2T2R; use RX1/TX1 for now
sdr.tx_enabled_channels = [0]
sdr.sample_rate = fs
sdr.tx_lo = 2_440_000_000
sdr.rx_lo = 2_440_000_000                    # try tx_lo + 5000 later: a known 0.002 cycles/sample CFO
sdr.tx_rf_bandwidth = fs
sdr.rx_rf_bandwidth = fs
sdr.tx_hardwaregain_chan0 = -40              # dB; FMC-9361 adds a TX amplifier, so start low
sdr.gain_control_mode_chan0 = "slow_attack"  # hardware AGC (chapter 11)

rng = np.random.default_rng(1)
bits = rng.integers(0, 2, 2 * 2000)
frame = transmit(bits)
frame = frame / np.max(np.abs(frame)) * 0.5 * 2 ** 14   # TX samples are scaled to about +/-2^14

sdr.tx_cyclic_buffer = True                  # repeat the frame forever
sdr.tx(frame)
sdr.rx_buffer_size = 3 * len(frame)          # at least two whole frames per capture
for _ in range(5):
    sdr.rx()                                 # flush stale buffers
r = sdr.rx()

sym, f_est = receive(r)
got = qpsk_demap(sym)[: len(bits)]

sdr.tx_destroy_buffer()

같은 칩의 TX와 RX는 같은 기준 클록을 쓰므로 CFO가 거의 0으로 나올 것입니다. 수신기를 시험하려면 tx_lo를 수 kHz 비켜 알려진 오프셋을 만드세요. 5 kHz면 2.5 MSPS에서 0.002 사이클/샘플이고, 거친 CFO 추정이 정확히 그 값을 보고해야 합니다. 서로 다른 보드 두 대(예: 이 보드와 PlutoSDR)로 하면 11장에서 계산한 수십 kHz 단위의 실제 ppm 오차를 직접 만나게 됩니다.

하드웨어에서 처음 만나는 문제들
  • DC 스파이크: 8장의 LO 누설이 0 Hz에 나타납니다. 이 신호는 대역 중앙을 쓰므로 영향이 있다면 rx_lo를 대역폭 밖으로 비키고 소프트웨어 NCO로 되돌리는 오프셋 튜닝을 적용하세요.
  • 포화: 수신 성상도의 바깥 점이 눌리거나 BER이 이유 없이 나쁘면 TX 이득을 더 낮추거나 감쇠를 늘리세요. r의 최댓값이 12비트 풀스케일(±2048) 근처면 포화입니다.
  • 버퍼 경계: 순환 송신 버퍼의 경계와 수신 버퍼의 경계는 맞지 않습니다. 수신 버퍼가 프레임 두 개 이상이어야 프레임 하나가 온전히 들어옵니다.

단계 4: 정합 필터를 PL로 옮기기

호스트에서 동작을 확인했다면 가장 무거운 샘플 단위 블록부터 FPGA로 옮깁니다. 이 수신기에서는 정합 필터입니다. 9장의 절차를 그대로 따릅니다.

  1. 비트 정확 모델: RRC 계수를 Q1.17로, 입력을 Q1.11로 양자화한 정수 모델을 만들고, 부동소수점 수신기 대신 이 모델을 끼워 단계 2의 합격 시험을 다시 통과시킵니다.
  2. 자원 계산: 33탭 대칭 필터는 곱셈 17개입니다. 1 MSPS 데이터를 100 MHz 클록으로 처리하면 fclk/fs = 100이므로 DSP 슬라이스 하나로 충분하고, 61.44 MSPS 원신호에 바로 건다면 슬라이스 수십 개가 필요합니다. 데시메이션 뒤에 둘 이유가 다시 확인됩니다.
  3. HLS 또는 HDL 구현: 9장의 fir_hls.cpp에 아래 스크립트가 만든 계수를 붙여 넣고, AXI-Stream 입출력으로 합성합니다.
  4. 비트 정확 대조: 같은 입력 벡터로 HDL 시뮬레이션 출력과 정수 모델 출력이 한 비트도 다르지 않은지 확인합니다.

확장 과제

  1. 16-QAM으로: 매핑·판정을 바꾸고 코스타스 위상 검출기를 판정 기반(decision-directed)으로 일반화합니다. 크기 정보가 의미를 갖기 때문에 AGC 정확도가 갑자기 중요해집니다.
  2. 실시간 스펙트럼 모니터: PL에 FFT IP와 전력 평균기를 두고, PS의 Linux에서 웹 페이지로 워터폴을 그립니다. 5장의 dBFS 정규화와 Welch 평균을 그대로 씁니다.
  3. FM 방송 수신기: AD9361의 수신 범위가 70 MHz부터라서 FM 방송 대역(88–108 MHz)을 바로 받을 수 있습니다. FM 복조는 순간 주파수, 즉 angle(x[n] · x*[n−1])이고, 앞에 8장의 DDC, 뒤에 7장의 데시메이션을 붙이면 소리가 나옵니다. 처음 만들기에 가장 보람 있는 확장입니다.
  4. 2채널 활용: AD9361은 2T2R이고 두 수신 채널이 같은 LO를 공유합니다. 두 안테나의 위상 차이로 전파가 오는 방향을 추정하거나(방향 탐지), 두 경로를 합쳐 SNR을 올리는 다이버시티 수신을 해 볼 수 있습니다.
  5. 패킷과 오류 정정: 페이로드에 길이·CRC를 붙이고 오류 정정 부호를 더합니다. RFSoC 계열에는 SD-FEC 하드 블록이 들어 있는 제품도 있습니다.
  6. RFSoC로 이식: 믹서 없는 직접 RF 샘플링(2장의 나이퀴스트 존)과 하드 DDC(8장)를 쓰면 AD9361의 아날로그 앞단 대신 무엇이 달라지는지 비교해 봅니다.

  • NCO의 FTW, 해상도, 스퓨리어스를 계산하고 DDC를 구현할 수 있다 (8장)
  • 비트 정확 모델로 고정소수점 설계를 검증할 수 있다 (9장)
