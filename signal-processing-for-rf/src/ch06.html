Part II · 핵심 도구 — 6장

디지털 필터: FIR와 IIR

이 장을 마치면: 필터 사양(통과대역, 저지대역, 전이폭, 감쇠량)을 읽고 필요한 탭 수를 추정하며, 창 방식으로 FIR을 직접 설계하고, z변환의 극점·영점으로 IIR 필터의 안정성을 판단하며, 상황에 맞게 FIR과 IIR을 고를 수 있습니다.

필터 사양은 주파수 축 위의 허용 범위다

필터를 설계한다는 것은 주파수 응답 |H(f)|가 지나갈 수 있는 통로를 정하고, 그 통로 안을 지나는 가장 싼 필터를 찾는 일입니다. 사양은 보통 다섯 숫자로 적습니다.

  • 통과대역 끝 fp와 저지대역 시작 fst: 둘 사이가 전이폭 Δf.
  • 통과대역 리플: 통과대역 안에서 이득이 얼마나 출렁여도 되는가 (예: ±0.1 dB).
  • 저지대역 감쇠 A: 막아야 할 대역을 최소 몇 dB 깎는가 (예: 60 dB).

비용을 가장 크게 좌우하는 것은 전이폭과 감쇠량입니다. 오래 쓰여 온 경험식(fred harris의 어림법)이 꽤 잘 맞습니다.

Ntaps ≈ A [dB]22 × fsΔf 예: 60 dB 감쇠, 전이폭 0.05fs → 약 55탭. 전이폭을 절반으로 줄이면 탭 수는 두 배. 최적(등리플) 설계 기준이며, 창 방식은 이보다 많이 든다

FIR 설계: 이상적인 필터를 잘라 창을 씌운다

차단 주파수 fc(fs로 정규화)에서 칼같이 끊기는 이상적 저역통과 필터의 임펄스 응답은 sinc 함수입니다. 4장의 결론, "임펄스 응답의 푸리에 변환이 주파수 응답"을 거꾸로 쓴 것입니다.

hideal[n] = 2fc · sinc(2fcn),   sinc(x) = sin(πx)πx

문제는 이 sinc가 양쪽으로 무한히 길다는 것입니다. 그래서 가운데 N개만 잘라 내고, (N−1)/2만큼 늦춰 인과적으로 만들고, 잘린 가장자리의 충격을 줄이려고 창함수를 곱합니다. 5장에서 스펙트럼 누설을 줄이던 바로 그 창입니다. 이것이 창 방식(windowed-sinc) FIR 설계이고, 창의 종류가 얻을 수 있는 감쇠량을, 탭 수가 전이폭을 결정합니다.

사각 창으로 바꾸면 저지대역이 약 −21 dB에서 더 내려가지 않습니다. 탭 수를 아무리 늘려도 전이폭만 좁아질 뿐 바닥은 그대로입니다. 감쇠량은 창이, 전이폭은 탭 수가 정한다는 뜻입니다. 계수를 8비트, 6비트로 줄여 보세요. 저지대역 바닥이 위로 올라옵니다. 설계는 맞는데 구현의 정밀도가 사양을 망치는 경우로, 9장의 주제입니다.

대칭 계수의 두 가지 선물: 선형 위상과 곱셈 절반

창 방식으로 설계한 FIR은 계수가 좌우 대칭입니다(h[k] = h[N−1−k]). 이 대칭에서 두 가지 좋은 성질이 나옵니다.

  • 선형 위상: 모든 주파수가 똑같이 (N−1)/2 샘플만큼 지연됩니다(군지연 일정). 주파수마다 지연이 다르면 파형 모양이 일그러지고, 디지털 변조 신호에서는 심볼끼리 번지는 간섭(ISI)이 됩니다. 통신 수신기에서 FIR을 선호하는 가장 큰 이유입니다.
  • 곱셈 절반: 같은 계수를 곱할 두 샘플을 먼저 더하고(x[n−k] + x[n−N+1+k]) 한 번만 곱하면 됩니다. Zynq의 DSP48E1 슬라이스에 곱셈기 앞의 전치 가산기(pre-adder)가 들어 있는 이유가 정확히 이것입니다.

실무에서는 창 방식 외에 Parks-McClellan(등리플, remez) 같은 최적화 설계를 많이 씁니다. 오차를 통과대역과 저지대역 전체에 고르게 퍼뜨려서, 같은 사양을 훨씬 적은 탭으로 만족시킵니다. 위의 어림식도 이런 최적 설계를 기준으로 한 것입니다. 창 방식은 직관적이고 항상 동작하지만, 탭 수는 앞 표의 전이폭 식(예: Blackman이면 5.5 / 전이폭)으로 계산해야 합니다. 아래 예제가 같은 사양으로 세 방식을 비교합니다.

import numpy as np from scipy import signal fs = 1.0 fp, fst, atten = 0.10, 0.15, 60 # passband edge, stopband edge, required dB def stopband_db(h): w, H = signal.freqz(h, worN=4096, fs=fs) return -20 * np.log10(np.max(np.abs(H[w >= fst]))) def smallest(design): """Smallest odd tap count whose design meets the stopband spec.""" for n in range(11, 301, 2): h = design(n) if stopband_db(h) >= atten: return h print(f"rule of thumb (optimal design): {int(np.ceil(atten / 22 * fs / (fst - fp)))} taps") h_pm = smallest(lambda n: signal.remez(n, [0, fp, fst, 0.5], [1, 0], weight=[1, 10], fs=fs)) print(f"remez (equiripple) : {len(h_pm):3d} taps -> {stopband_db(h_pm):.1f} dB") h_bk = smallest(lambda n: signal.firwin(n, (fp + fst) / 2, window="blackman", fs=fs)) print(f"firwin + blackman : {len(h_bk):3d} taps -> {stopband_db(h_bk):.1f} dB") # Hamming's sidelobes cap the attenuation, so more taps do not help much h_hm = signal.firwin(101, (fp + fst) / 2, window="hamming", fs=fs) print(f"firwin + hamming : 101 taps -> {stopband_db(h_hm):.1f} dB (window-limited)") print("symmetric:", np.allclose(h_pm, h_pm[::-1]))

z변환 한 페이지: 지연은 z−1이다

필터를 블록도로 그리면 상자는 세 종류뿐입니다. 곱셈, 덧셈, 그리고 한 샘플 지연. 이 한 샘플 지연을 z−1이라고 씁니다. 하드웨어로는 클록 하나 늦게 값을 내놓는 레지스터, 즉 플립플롭입니다. 이렇게 쓰면 FIR 필터는 z−1의 다항식이 됩니다.

H(z) = Y(z)X(z) = b0 + b1z−1 + b2z−2 + …1 + a1z−1 + a2z−2 + … 분자가 0이 되는 z는 영점(zero), 분모가 0이 되는 z는 극점(pole). FIR은 분모가 1

z = ejω, 즉 복소 평면의 단위원 위를 따라 H(z)를 계산하면 주파수 응답이 됩니다. 단위원 위에 영점이 있으면 그 주파수가 완전히 막히고(이동 평균의 fs/4, fs/2 영점), 단위원 가까이에 극점이 있으면 그 주파수가 크게 증폭됩니다. 그리고 가장 중요한 규칙 하나. 모든 극점이 단위원 안쪽에 있어야 필터가 안정하다. 밖에 있으면 출력이 발산합니다.

IIR: 되먹임으로 적은 계수, 대신 조심해야 할 것들

분모가 있는 필터는 과거의 출력을 다시 입력으로 씁니다. 임펄스 응답이 이론적으로 영원히 이어지므로 IIR(Infinite Impulse Response)이라고 부릅니다. 임베디드 개발자에게 가장 익숙한 IIR은 지수 이동 평균(EMA)입니다.

y[n] = y[n−1] + α (x[n] − y[n−1])  ⇔  H(z) = α1 − (1−α)z−1 극점은 z = 1 − α. 0 < α < 2이면 단위원 안쪽이라 안정. α가 작을수록 극점이 1에 가까워지고 더 좁은 저역통과가 된다

곱셈 한 번으로 꽤 좋은 저역통과가 됩니다. 같은 날카로움을 FIR로 얻으려면 수십 탭이 필요할 수 있습니다. 실무에서 높은 차수의 IIR은 2차 섹션(biquad)을 여러 개 직렬로 이어서 만듭니다. 고차 다항식 하나로 구현하면 계수 반올림만으로도 극점이 크게 움직여 불안정해질 수 있기 때문입니다.

/* Direct Form I biquad: one second-order section. * Cascade several sections for higher-order IIR filters. */ typedef struct { float b0, b1, b2, a1, a2; float x1, x2, y1, y2; } biquad_t; float biquad_step(biquad_t *s, float x) { float y = s->b0 * x + s->b1 * s->x1 + s->b2 * s->x2 - s->a1 * s->y1 - s->a2 * s->y2; /* feedback terms make it IIR */ s->x2 = s->x1; s->x1 = x; s->y2 = s->y1; s->y1 = y; return y; }

FPGA 엔지니어의 눈으로

FIR의 블록도는 그대로 회로도입니다. z−1은 레지스터 체인, 계수 곱은 DSP 슬라이스, 덧셈은 가산기 트리나 DSP 슬라이스끼리의 캐스케이드 경로입니다. 되먹임이 없으니 레지스터를 추가해 클록을 올려도 결과는 지연만 늘어날 뿐 똑같습니다. IIR은 y[n−1]이 나와야 y[n]을 계산할 수 있어서 루프 안의 곱셈-덧셈이 샘플 주기 하나 안에 끝나야 합니다. 샘플률이 클록에 가까워질수록 IIR이 FPGA에서 불리해지는 이유입니다.

흔한 함정
  • 정규화 주파수 단위 혼동: 도구마다 1이 fs인지 fs/2(나이퀴스트)인지 다릅니다. MATLAB과 예전 scipy 관례는 나이퀴스트 = 1입니다. 위 예제처럼 fs=를 명시하면 헷갈릴 일이 없습니다.
  • 통과대역 이득: 창 방식 FIR은 계수 합을 1로 맞춰야 직류 이득이 0 dB입니다. 고정소수점으로 옮길 때 이 합이 풀스케일을 넘지 않는지도 확인하세요.
  • IIR을 쓴 뒤 심볼이 번진다: 비선형 위상 때문입니다. 변조 신호 경로에는 선형 위상 FIR을 쓰세요.
핵심 정리
  • 탭 수 ≈ (감쇠 dB / 22) × (fs / 전이폭). 감쇠는 창이, 전이폭은 탭 수가 정한다.
  • 대칭 FIR = 선형 위상 + 곱셈 절반. 통신 체인의 기본 부품.
  • z−1은 레지스터. 극점이 단위원 안에 있어야 안정. IIR은 싸지만 위상과 정밀도에 조심.
