Part IV · 고급 + 실전 — 12장

실전: 미니 QPSK 수신기 만들기

이 장을 마치면: 펄스 성형부터 프레임 동기까지 갖춘 QPSK 송수신기를 직접 돌려 보고 정량적 합격 기준으로 검증하며, 같은 코드를 RK-ZYNQ7020-F + FMC-9361 루프백에 연결하고, 수신 체인의 첫 블록을 Zynq PL로 옮기는 계획을 세울 수 있습니다.

사양: 무엇을 만들고 어떻게 합격을 판정하나

지금까지의 모든 장을 한 파일로 조립합니다. 의존성은 numpy 하나이고, 채널은 처음에는 시뮬레이션으로, 다음에는 진짜 RF로 바꿉니다. 수신기는 송신기의 상태를 전혀 모른다고 가정합니다. 주파수, 위상, 지연, 크기 모두 모릅니다.

단계 1: 수신기 전체 코드

아래가 완성된 송수신기 전체입니다. 150줄 남짓에 이 책의 3·6·7·8·10·11장이 모두 들어 있습니다. 파일은 저장소의 code/mini_rx.py로도 받을 수 있고, 이 책의 다른 예제들도 이 파일을 불러 씁니다.

결과를 읽어 봅시다. 거친 CFO 추정이 4제곱 FFT로 참값을 정확히 찾았고, 4000심볼에서 오류가 없으며, EVM은 Es/N0 = 15 dB에서 기대할 수 있는 약 −15 dB 근처입니다(10장의 EVM² ≈ 1/SNR). 함수와 장의 대응은 다음과 같습니다.

단계 2: 합격 시험은 한 번이 아니라 여러 번

한 번 성공한 수신기는 아직 믿을 수 없습니다. 지연, CFO, 위상, 크기를 매번 무작위로 바꿔 가며 합격 기준을 기계적으로 확인합니다. 하네스 엔지니어링 교본에서 말한 "검증 게이트"를 신호처리에 적용한 것입니다.

import numpy as np import mini_rx as m def trial(seed, esn0_db, nbits=6000): rng = np.random.default_rng(seed) bits = rng.integers(0, 2, nbits) rx = m.channel(m.transmit(bits), esn0_db, cfo=rng.uniform(-0.01, 0.01), phase=rng.uniform(-np.pi, np.pi), delay=rng.uniform(0, 80), gain=rng.uniform(0.1, 5), rng=rng) sym, _ = m.receive(rx) got = m.qpsk_demap(sym)[:nbits] n = len(got) return int(np.sum(got != bits[:n])), n for esn0 in (12, 9): results = [trial(s, esn0) for s in range(20)] frame_fail = sum(e / n > 0.05 for e, n in results) errs = sum(e for e, n in results if e / n <= 0.05) total = sum(n for e, n in results if e / n <= 0.05) ber = errs / total verdict = "PASS" if esn0 != 12 or (frame_fail == 0 and ber < 1e-3) else "FAIL" print(f"Es/N0 {esn0:2d} dB: frame failures {frame_fail}/20, BER {ber:.1e} {verdict if esn0 == 12 else '(margin check)'}")

이 시험은 실제로 버그 두 개를 잡아냈습니다. 첫째, 초기 타이밍이 반 심볼 어긋난 채 시작하면 가드너 루프가 오차 검출기의 이득이 0에 가까운 지점에서 수백 심볼 동안 머뭇거리다가 그사이 한 심볼을 건너뛰었습니다. 그래서 루프를 시작하기 전에 |y|²의 심볼률 성분 위상으로 눈의 중심을 한 번에 추정하는 피드포워드 단계(timing_estimate())를 넣었습니다. 둘째, 특정 시드에서 데이터의 첫 32심볼이 우연히 프리앰블과 같아 상관 피크가 두 개 생겼고, 더 큰 쪽을 고르다 32심볼 늦게 프레임을 잡았습니다. 그래서 "가장 큰 피크"가 아니라 "처음 나타난 강한 피크"를 고르도록 바꿨습니다. 둘 다 한두 번 돌려서는 절대 보이지 않는 문제입니다.

수정 후 12 dB에서 합격입니다. 9 dB 결과는 여유(margin)를 보기 위한 것으로, BER이 이론값보다 조금 나쁜 것은 루프가 잠기는 동안의 오류와 루프 지터 때문입니다. 이 차이를 구현 손실(implementation loss)이라고 부르고, 좋은 수신기는 1 dB 안쪽으로 줄입니다. 루프 대역폭을 바꿔 가며 이 숫자를 개선해 보는 것이 첫 번째 연습입니다.

단계 3: 진짜 전파로, FMC-9361 루프백

9장 끝의 포팅을 마쳐 보드에서 iio_info가 AD9361을 보여 주면, 이제 channel()을 진짜 하드웨어로 바꿉니다. PC의 pyadi-iio가 이더넷으로 보드의 IIO 서버에 접속하는 구조입니다. 처음에는 안테나 대신 SMA 케이블과 30 dB 이상의 감쇠기로 TX1과 RX1을 직접 잇는 것을 권합니다. FMC-9361은 송신단에 증폭기가 더 붙어 있어 특히 중요합니다. 수신단 과입력을 막고, 전파를 밖으로 내보내지 않으며, 결과가 재현 가능합니다. 2.4 GHz ISM 대역이라도 무선 출력과 용도에는 각 나라의 전파 규정이 적용된다는 점을 기억하세요.

import numpy as np import adi # pip install pyadi-iio from mini_rx import transmit, receive, qpsk_demap fs = 2_500_000 # above 2.083 MSPS: no FIR load needed (chapter 7) sdr = adi.ad9361(uri="ip:192.168.1.10") # the board's IP; its Linux runs the IIO server sdr.rx_enabled_channels = [0] # AD9361 is 2T2R; use RX1/TX1 for now sdr.tx_enabled_channels = [0] sdr.sample_rate = fs sdr.tx_lo = 2_440_000_000 sdr.rx_lo = 2_440_000_000 # try tx_lo + 5000 later: a known 0.002 cycles/sample CFO sdr.tx_rf_bandwidth = fs sdr.rx_rf_bandwidth = fs sdr.tx_hardwaregain_chan0 = -40 # dB; FMC-9361 adds a TX amplifier, so start low sdr.gain_control_mode_chan0 = "slow_attack" # hardware AGC (chapter 11) rng = np.random.default_rng(1) bits = rng.integers(0, 2, 2 * 2000) frame = transmit(bits) frame = frame / np.max(np.abs(frame)) * 0.5 * 2 ** 14 # TX samples are scaled to about +/-2^14 sdr.tx_cyclic_buffer = True # repeat the frame forever sdr.tx(frame) sdr.rx_buffer_size = 3 * len(frame) # at least two whole frames per capture for _ in range(5): sdr.rx() # flush stale buffers r = sdr.rx() sym, f_est = receive(r) got = qpsk_demap(sym)[: len(bits)] n = len(got) print(f"CFO estimate {f_est * fs:+.0f} Hz, bit errors {np.sum(got != bits[:n])} / {n}") sdr.tx_destroy_buffer()

같은 칩의 TX와 RX는 같은 기준 클록을 쓰므로 CFO가 거의 0으로 나올 것입니다. 수신기를 시험하려면 tx_lo를 수 kHz 비켜 알려진 오프셋을 만드세요. 5 kHz면 2.5 MSPS에서 0.002 사이클/샘플이고, 거친 CFO 추정이 정확히 그 값을 보고해야 합니다. 서로 다른 보드 두 대(예: 이 보드와 PlutoSDR)로 하면 11장에서 계산한 수십 kHz 단위의 실제 ppm 오차를 직접 만나게 됩니다.

하드웨어에서 처음 만나는 문제들
  • DC 스파이크: 8장의 LO 누설이 0 Hz에 나타납니다. 이 신호는 대역 중앙을 쓰므로 영향이 있다면 rx_lo를 대역폭 밖으로 비키고 소프트웨어 NCO로 되돌리는 오프셋 튜닝을 적용하세요.
  • 포화: 수신 성상도의 바깥 점이 눌리거나 BER이 이유 없이 나쁘면 TX 이득을 더 낮추거나 감쇠를 늘리세요. r의 최댓값이 12비트 풀스케일(±2048) 근처면 포화입니다.
  • 버퍼 경계: 순환 송신 버퍼의 경계와 수신 버퍼의 경계는 맞지 않습니다. 수신 버퍼가 프레임 두 개 이상이어야 프레임 하나가 온전히 들어옵니다.

단계 4: 정합 필터를 PL로 옮기기

호스트에서 동작을 확인했다면 가장 무거운 샘플 단위 블록부터 FPGA로 옮깁니다. 이 수신기에서는 정합 필터입니다. 9장의 절차를 그대로 따릅니다.

  1. 비트 정확 모델: RRC 계수를 Q1.17로, 입력을 Q1.11로 양자화한 정수 모델을 만들고, 부동소수점 수신기 대신 이 모델을 끼워 단계 2의 합격 시험을 다시 통과시킵니다.
  2. 자원 계산: 33탭 대칭 필터는 곱셈 17개입니다. 1 MSPS 데이터를 100 MHz 클록으로 처리하면 fclk/fs = 100이므로 DSP 슬라이스 하나로 충분하고, 61.44 MSPS 원신호에 바로 건다면 슬라이스 수십 개가 필요합니다. 데시메이션 뒤에 둘 이유가 다시 확인됩니다.
  3. HLS 또는 HDL 구현: 9장의 fir_hls.cpp에 아래 스크립트가 만든 계수를 붙여 넣고, AXI-Stream 입출력으로 합성합니다.
  4. 비트 정확 대조: 같은 입력 벡터로 HDL 시뮬레이션 출력과 정수 모델 출력이 한 비트도 다르지 않은지 확인합니다.
  5. 통합: 9장에서 이 보드로 옮긴 fmcomms2 HDL 프로젝트에서 트랜시버 인터페이스 코어와 DMA 사이에 블록을 끼우고, 정합 필터가 빠진 receive()로 같은 합격 시험을 돌립니다.
import numpy as np from mini_rx import rrc h = rrc() / np.max(np.abs(rrc())) * 0.5 # leave headroom: peak tap = 0.5 q = np.round(h * 2 ** 17).astype(int) # Q1.17 for the 18-bit DSP48 B port assert np.array_equal(q, q[::-1]), "RRC must stay symmetric after rounding" print(f"// {len(q)} taps, Q1.17, sum = {q.sum()} ({q.sum() / 2 ** 17:.3f})") print("const coef_t H[N] = {") for i in range(0, len(q), 8): print(" " + ", ".join(f"{v / 2 ** 17:.8f}" for v in q[i:i + 8]) + ",") print("};")

확장 과제

  1. 16-QAM으로: 매핑·판정을 바꾸고 코스타스 위상 검출기를 판정 기반(decision-directed)으로 일반화합니다. 크기 정보가 의미를 갖기 때문에 AGC 정확도가 갑자기 중요해집니다.
  2. 실시간 스펙트럼 모니터: PL에 FFT IP와 전력 평균기를 두고, PS의 Linux에서 웹 페이지로 워터폴을 그립니다. 5장의 dBFS 정규화와 Welch 평균을 그대로 씁니다.
  3. FM 방송 수신기: AD9361의 수신 범위가 70 MHz부터라서 FM 방송 대역(88–108 MHz)을 바로 받을 수 있습니다. FM 복조는 순간 주파수, 즉 angle(x[n] · x*[n−1])이고, 앞에 8장의 DDC, 뒤에 7장의 데시메이션을 붙이면 소리가 나옵니다. 처음 만들기에 가장 보람 있는 확장입니다.
  4. 2채널 활용: AD9361은 2T2R이고 두 수신 채널이 같은 LO를 공유합니다. 두 안테나의 위상 차이로 전파가 오는 방향을 추정하거나(방향 탐지), 두 경로를 합쳐 SNR을 올리는 다이버시티 수신을 해 볼 수 있습니다.
  5. 패킷과 오류 정정: 페이로드에 길이·CRC를 붙이고 오류 정정 부호를 더합니다. RFSoC 계열에는 SD-FEC 하드 블록이 들어 있는 제품도 있습니다.
  6. RFSoC로 이식: 믹서 없는 직접 RF 샘플링(2장의 나이퀴스트 존)과 하드 DDC(8장)를 쓰면 AD9361의 아날로그 앞단 대신 무엇이 달라지는지 비교해 봅니다.
최종 체크리스트
  • 임의의 주파수가 주어진 샘플률에서 어디로 접히는지 계산할 수 있다 (2장)
  • IQ 스펙트럼의 음의 주파수가 LO 아래라는 것을 설명할 수 있다 (3장)
  • 탭 수 × 샘플률로 필요한 MAC/s와 DSP 슬라이스 수를 추정할 수 있다 (4, 9장)
  • FFT 결과를 dBFS로 정규화하고 RBW와 함께 잡음 바닥을 말할 수 있다 (5장)
  • 사양에서 FIR 탭 수를 추정하고 설계해 검증할 수 있다 (6장)
  • 데시메이션 체인을 비싼 필터가 낮은 샘플률에 오도록 설계할 수 있다 (7장)
  • NCO의 FTW, 해상도, 스퓨리어스를 계산하고 DDC를 구현할 수 있다 (8장)
  • 비트 정확 모델로 고정소수점 설계를 검증할 수 있다 (9장)
  • 성상도 모양으로 결함을 진단하고 EVM을 잴 수 있다 (10장)
  • 동기화 체인의 순서를 근거와 함께 설계하고 루프 대역폭을 고를 수 있다 (11장)
  • 위의 모든 것을 합쳐 합격 시험을 통과하는 수신기를 만들었다 (12장)

여기까지 왔다면 신호처리는 더 이상 잊어버린 교과목이 아니라 손에 쥔 도구입니다. 다음은 하드웨어 위에서 이 도구들을 하나씩 PL로 옮기며, 시뮬레이션에서 본 숫자가 실제 전파에서도 나오는지 확인하는 일입니다.
