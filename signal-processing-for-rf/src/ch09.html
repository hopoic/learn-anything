Part III · RF 수신 체인 실무 — 9장

고정소수점과 FPGA 구현

이 장을 마치면: 신호에 맞는 Q 형식을 고르고, 비트 수로 양자화 잡음(SQNR)을 예측하며, 필터의 비트 성장을 계산해 누산기 폭을 정하고, FIR을 DSP 슬라이스에 매핑해 필요한 자원을 추정하며, 수신 체인의 기능을 PL과 PS에 합리적으로 나눌 수 있습니다.

FPGA에는 실수가 없다: Q 형식

FPGA의 기본 재료는 정수 덧셈기와 곱셈기입니다. 신호처리는 −1과 1 사이의 실수로 설계하므로 둘을 잇는 약속이 필요한데, 그것이 고정소수점(fixed-point)입니다. 정수 하나를 쓰되 "이 정수를 2n으로 나눈 값으로 읽자"고 약속하는 것입니다. 정수부 m비트(부호 포함)와 소수부 n비트를 쓰는 형식을 Qm.n이라고 씁니다.

형식전체 비트범위최소 단위쓰임
Q1.1112−1 ~ +0.99952−1112비트 ADC 샘플 (AD9363)
Q1.1516−1 ~ +0.999972−15DSP 표준 샘플·계수 형식

곱셈의 규칙은 단순합니다. Qa.b × Qc.d = Q(a+c).(b+d). 두 Q1.15를 곱하면 Q2.30이 되는데, 정수부가 2비트로 늘어나는 이유는 단 하나의 경우, (−1) × (−1) = +1 때문입니다. 이 값은 Q1.15로 표현할 수 없어서, 결과를 다시 15비트 시프트해 16비트로 줄일 때 포화 처리를 하지 않으면 +1이 −1로 뒤집힙니다. 4장 C 코드가 마지막에 포화를 한 이유입니다.

양자화 잡음: 비트 하나에 6 dB

실수를 정수로 반올림하면 매번 최대 반 단위(Δ/2)의 오차가 생깁니다. 신호가 충분히 복잡하면 이 오차는 −Δ/2 ~ +Δ/2에 고르게 퍼진 잡음처럼 행동하고, 그 전력은 Δ²/12입니다. 풀스케일 사인파의 전력과 비교하면 신호 대 양자화 잡음비가 나옵니다.

SQNR = 6.02 · b + 1.76  [dB] b비트로 풀스케일 사인파를 표현할 때. 신호가 풀스케일보다 X dB 작으면 SQNR도 X dB 줄어든다

12비트 ADC의 이상적인 SQNR은 약 74 dB, 16비트 데이터 경로는 약 98 dB입니다. 실무 규칙도 여기서 나옵니다. 데이터 경로의 비트 수는 ADC보다 몇 비트 더 넉넉하게 잡아, 처리 과정의 반올림 잡음이 ADC 자체의 잡음보다 충분히 작게 합니다. 그리고 반올림 방식도 중요합니다. 하위 비트를 그냥 잘라 내는 버림(truncation)은 오차가 항상 음수 쪽(−Δ ~ 0)이라 평균이 −Δ/2인 DC 편향을 만듭니다. 한 번은 작아도 적분기나 IIR 되먹임 안에서는 누적됩니다.

비트를 하나 늘릴 때마다 측정 SQNR이 약 6 dB씩 오르는 것을 확인하세요. 버림으로 바꾸면 오차 그래프 전체가 아래로 내려가고 DC 편향 값이 반 단위만큼 생깁니다. 크기를 +3 dBFS로 올리고 오버플로 처리를 랩어라운드로 바꿔 보세요. 파형 꼭대기가 반대편 끝으로 뒤집히며 SQNR이 무너집니다. 포화는 꼭대기를 평평하게 깎을 뿐이라 훨씬 덜 나쁩니다. FPGA 데이터 경로에서 출력 비트를 줄이는 곳마다 "반올림 후 포화"가 기본인 이유입니다.

비트 성장: 곱하면 더해지고, 더하면 늘어난다

정밀도를 유지하려면 연산 중간 결과의 비트 수를 계산해 둬야 합니다. 규칙은 두 가지입니다. b1비트와 b2비트의 곱은 b1 + b2비트, K개 값의 합은 ⌈log2K⌉비트가 더 필요합니다. 그래서 FIR 누산기의 최악 폭은 다음과 같습니다.

누산기 비트 = b입력 + b계수 + ⌈log2 Ntaps⌉ 예: 12비트 입력, 16비트 계수, 64탭 → 12 + 16 + 6 = 34비트. DSP48E1의 48비트 누산기에 여유 있게 들어간다

이 식은 모든 입력이 동시에 최댓값이고 부호가 계수와 맞아떨어지는 최악의 경우입니다. 계수 절댓값의 합 Σ|h|이 1 근처인 저역통과 필터라면 실제로는 log2Σ|h|비트만큼만 자라므로 더 줄일 수 있습니다. 어느 쪽이든 원칙은 같습니다. 중간에는 넉넉하게, 출력에서 한 번만 반올림하고 포화한다.

import numpy as np from scipy import signal def quantize(x, frac_bits, total_bits): """Round to nearest and saturate: what the hardware will do.""" q = np.round(x * 2 ** frac_bits) lim = 2 ** (total_bits - 1) return np.clip(q, -lim, lim - 1).astype(np.int64) h = signal.firwin(63, 0.2) x = 0.9 * np.sin(2 * np.pi * 0.0123 * np.arange(20000)) # input in [-1, 1) ref = np.convolve(x, h) # floating-point reference xq = quantize(x, 11, 12) # Q1.11 ADC samples for cb in (16, 12, 8): hq = quantize(h, cb - 1, cb) # Q1.(cb-1) coefficients acc = np.convolve(xq, hq) # exact integer accumulate print(f"coef {cb:2d}-bit: accumulator needs {int(np.abs(acc).max()).bit_length() + 1} bits", end=", ") y = quantize(acc / 2 ** (11 + cb - 1), 15, 16) / 2 ** 15 # round + saturate to Q1.15 output err = y - ref sqnr = 10 * np.log10(np.sum(ref[100:-100] ** 2) / np.sum(err[100:-100] ** 2)) print(f"output SQNR {sqnr:5.1f} dB") print(f"ideal 12-bit ADC SQNR for this level: {6.02 * 12 + 1.76 + 20 * np.log10(0.9):.1f} dB")

결과를 읽어 봅시다. 계수가 16비트일 때 출력 SQNR이 12비트 ADC의 이론값보다 오히려 높습니다. 저역통과 필터가 대역 밖의 양자화 잡음까지 걸러 냈기 때문입니다(7장의 처리 이득). 12비트로 줄이면 ADC 한계 수준으로 내려오고, 8비트에서는 계수 오차가 출력 잡음을 완전히 지배합니다. 누산기는 최악 공식(12 + 16 + 6 = 34비트)보다 훨씬 적게 쓰였는데, 앞에서 말한 Σ|h| 효과입니다. 이것이 비트 정확(bit-true) 모델의 쓰임새입니다. 부동소수점 모델 → 비트 정확 정수 모델 → HDL 순서로 내려가고, HDL 시뮬레이션 결과가 정수 모델과 한 비트도 다르지 않은지 비교합니다.

DSP 슬라이스에 FIR 올리기

Zynq-7000의 DSP48E1 슬라이스는 FIR을 위해 만든 것처럼 생겼습니다. 핵심만 그리면 다음과 같습니다.

각 부품이 FIR의 한 조각과 정확히 대응합니다. 전치 가산기는 대칭 계수의 두 샘플을 먼저 더하고(6장), 곱셈기는 계수를 곱하고, 48비트 ALU는 이전 슬라이스의 부분합(PCIN)을 더해 다음 슬라이스로 넘깁니다(PCOUT). 슬라이스를 사슬처럼 이으면 범용 로직을 거의 쓰지 않는 FIR이 됩니다. 이렇게 매 단계의 출력에 레지스터를 두는 전치형(transposed) 구조는 클록을 높이기 좋습니다.

// Transposed-form FIR: one multiplier per tap, partial sums move through registers. // Infers a DSP48 cascade: every stage is "multiply + add previous partial sum". module fir_transposed #( parameter NTAPS = 16, parameter IW = 12, parameter CW = 18, parameter AW = 48, parameter signed [CW*NTAPS-1:0] COEF = 0 // packed taps, h[0] in the low bits )( input wire clk, input wire ce, // one input sample per enabled clock input wire signed [IW-1:0] x, output wire signed [AW-1:0] y ); reg signed [AW-1:0] acc [0:NTAPS-1]; integer k; initial for (k = 0; k < NTAPS; k = k + 1) acc[k] = 0; // FPGA registers power up at 0 always @(posedge clk) if (ce) begin // the newest sample meets every coefficient at once for (k = 0; k < NTAPS - 1; k = k + 1) acc[k] <= acc[k+1] + x * $signed(COEF[CW*k +: CW]); // h[k] acc[NTAPS-1] <= x * $signed(COEF[CW*(NTAPS-1) +: CW]); // h[N-1] end assign y = acc[0]; // round + saturate downstream endmodule

HDL 대신 C++로 기술하고 Vitis HLS로 합성하는 방법도 있습니다. 고정소수점 타입 ap_fixed가 비트 폭과 반올림·포화 모드를 타입에 담아 주므로, 위의 비트 정확 모델과 거의 같은 코드가 됩니다.

#include #include typedef ap_fixed<12, 1> sample_t; // Q1.11 input typedef ap_fixed<18, 1> coef_t; // Q1.17 coefficients typedef ap_fixed<48, 8> acc_t; // wide accumulator typedef ap_fixed<16, 1, AP_RND_CONV, AP_SAT> out_t; // convergent rounding + saturation const int N = 63; const coef_t H[N] = { /* paste firwin() output here */ }; void fir(hls::stream &in, hls::stream &out) { #pragma HLS INTERFACE axis port=in #pragma HLS INTERFACE axis port=out #pragma HLS PIPELINE II=1 static sample_t z[N]; // delay line #pragma HLS ARRAY_PARTITION variable=z complete acc_t acc = 0; for (int k = N - 1; k > 0; k--) { z[k] = z[k - 1]; acc += z[k] * H[k]; } z[0] = in.read(); acc += z[0] * H[0]; out.write(acc); // quantization happens in this cast }

자원 추정은 클록과 샘플률의 비율에서 시작합니다. R = fclk / fs라면 DSP 슬라이스 하나가 샘플 하나당 R번의 MAC을 할 수 있으므로, 시간 다중화(folding)로 슬라이스 하나를 여러 탭이 나눠 쓸 수 있습니다.

Z-7010의 DSP 슬라이스가 80개이므로, 샘플률이 높은 앞단에서는 금방 빠듯해집니다. 7장의 원칙, "먼저 싸게 줄이고 비싼 필터는 낮은 샘플률에"가 자원 계산에서도 그대로 답입니다.

PL과 PS에 일 나누기

Zynq의 장점은 FPGA와 Linux가 한 칩에 있다는 것입니다. 경계를 긋는 기준은 "샘플마다 하는 일인가, 패킷마다 하는 일인가"입니다.

FFT 스펙트럼 감시, 프리앰블 상관PL연속 스트림에 대한 대량 MAC

PlutoSDR의 데이터 경로는 AD9363 → FPGA의 트랜시버 인터페이스 코어 → (데시메이션) → DMA → DDR → Linux IIO 드라이버 → libiio → USB 또는 네트워크 순서입니다. 직접 만든 신호처리 블록은 보통 인터페이스 코어와 DMA 사이에 AXI-Stream으로 끼워 넣습니다. 1장에서 본 USB 2.0의 약 4 MSPS 한계를 생각하면, PL에서 샘플률을 충분히 낮춰 보내야 호스트로 손실 없이 스트리밍할 수 있습니다.

BSP 엔지니어의 눈으로

PlutoSDR 펌웨어는 U-Boot, Linux 커널, Buildroot 기반의 오픈소스이고, ADI의 HDL 저장소에 Pluto용 FPGA 프로젝트가 있습니다. 새 블록을 넣는 작업은 익숙한 순서를 따릅니다. HDL 프로젝트에 IP를 추가하고, 디바이스 트리에 레지스터 영역을 기술하고, 제어는 UIO나 IIO 드라이버 확장으로 노출합니다. 주의할 점은 ADI HDL 릴리스마다 맞는 Vivado 버전이 정해져 있다는 것, 그리고 트랜시버 데이터 클록과 AXI 클록이 다른 도메인이라 클록 도메인 교차(CDC)를 정석대로 처리해야 한다는 것입니다.

흔한 함정
  • 부동소수점 모델만 검증: 실수 모델이 완벽해도 고정소수점에서 포화 한 번, 버림 한 번이 사양을 깨뜨립니다. 비트 정확 모델을 만들고 HDL 시뮬레이션과 대조하세요.
  • (−1) × (−1): Q1.15 곱셈 결과를 줄일 때 포화하지 않으면 유일하게 넘치는 이 경우가 부호를 뒤집습니다.
  • DSP 추론 실패: 곱셈 앞뒤에 레지스터가 없거나 리셋이 특이하면 합성기가 DSP 슬라이스 대신 범용 로직으로 곱셈기를 만듭니다. 합성 보고서에서 DSP 사용량을 확인하세요.
핵심 정리
  • Qm.n 곱은 Q(m+m′).(n+n′). 출력에서 한 번, 반올림 후 포화.
  • 비트 하나 = 약 6 dB. 버림은 DC 편향을 만든다.
  • DSP 수 ≈ (곱셈 수) / (fclk/fs). 샘플마다 하는 일은 PL, 패킷마다 하는 일은 PS.
