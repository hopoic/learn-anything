unsafe·FFI·메모리 레이아웃

이 장을 마치면: unsafe가 허용하는 다섯 가지 일과 허용하지 않는 것을 구분할 수 있고, unsafe 내부를 safe API로 감싸며 // SAFETY: 근거를 쓸 수 있으며, repr(C)로 C와 호환되는 레이아웃을 만들고 C 함수를 호출·노출하고, Miri로 정의되지 않은 동작을 잡을 수 있습니다.

13장까지 우리는 컴파일러가 모든 안전성을 증명하는 세계에 있었습니다. 하지만 하드웨어 레지스터, C 라이브러리, 새로운 자료구조의 내부처럼 컴파일러가 증명할 수 없지만 사람이 증명할 수 있는 코드가 있습니다. unsafe는 그 경계선입니다.

unsafe는 검사를 끄지 않는다, 다섯 가지 능력을 연다

unsafe 블록 안에서도 빌림 검사기와 타입 검사는 그대로 동작합니다. 추가로 허용되는 것은 딱 다섯 가지입니다.

  1. 원시 포인터(*const T, *mut T) 역참조
  2. unsafe fn 호출(FFI 함수 포함)
  3. static mut 접근
  4. unsafe trait 구현(예: Send, Sync 수동 구현)
  5. union 필드 읽기

그 대가로 프로그래머가 약속해야 하는 것이 있습니다. 매달린 포인터를 역참조하지 않는다, 같은 메모리에 &mut를 둘 만들지 않는다, 유효하지 않은 값(bool에 2, 범위 밖 열거형 태그)을 만들지 않는다, 데이터 경쟁을 만들지 않는다. 이 약속이 깨지면 C와 똑같이 정의되지 않은 동작(UB)이고, 그 영향은 unsafe 블록 밖 safe 코드로도 번집니다.

핵심 기술: unsafe 내부, safe 외부

실무 원칙은 "unsafe를 작게 만들고, 안전한 API로 감싸고, 왜 안전한지 적는다"입니다. 표준 라이브러리의 split_at_mut가 좋은 예입니다. 한 슬라이스에서 겹치지 않는 두 &mut를 만드는 일은 빌림 검사기가 증명하지 못하지만(같은 슬라이스를 두 번 가변으로 빌리니까), 인덱스 계산으로 사람이 증명할 수 있습니다.

/// Our own split_at_mut: two non-overlapping &mut views into one slice. fn split_mut(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) { let len = v.len(); assert!(mid <= len, "mid out of range"); // the safety check lives in SAFE code let p = v.as_mut_ptr(); // SAFETY: `mid <= len`, so [0, mid) and [mid, len) are both inside the allocation // and do not overlap; both borrows are tied to the lifetime of `v`. unsafe { (std::slice::from_raw_parts_mut(p, mid), std::slice::from_raw_parts_mut(p.add(mid), len - mid)) } } fn main() { let mut buf = [1, 2, 3, 4, 5, 6]; let (left, right) = split_mut(&mut buf, 2); left[0] = 100; right[0] = 300; right.reverse(); println!("{buf:?}"); // Raw pointers are fine to CREATE in safe code; only dereferencing needs unsafe. let x = 7u32; let p = &x as *const u32; let addr_mod_4 = p as usize % 4; // SAFETY: p comes from a live reference to x. println!("x via raw pointer = {}, aligned = {}", unsafe { *p }, addr_mod_4 == 0); }

이 예제의 Miri 버튼을 눌러 보세요. Miri는 Rust의 중간 표현(MIR)을 한 줄씩 해석하며 모든 메모리 접근이 규칙을 지키는지 검사하는 도구입니다. 문제가 없으면 정상 출력이 나옵니다. 이번엔 일부러 규칙을 깨 보겠습니다.

fn main() { let mut x = 10u32; let p = &mut x as *mut u32; // Two live &mut to the same place: the compiler is allowed to assume this never happens. let a = unsafe { &mut *p }; let b = unsafe { &mut *p }; *b += 1; *a += 1; // UB: `a` was invalidated when `b` was created and used println!("x = {x} (looks fine when run normally; press Miri)"); }

일반 실행은 아무 문제 없이 12를 출력합니다. 이것이 UB의 무서운 점입니다. 오늘은 동작하고, 컴파일러 버전이나 최적화 수준이 바뀌면 다르게 동작할 수 있습니다. Miri로 실행하면 "Undefined Behavior: attempting a write access ... but that tag does not exist in the borrow stack" 같은 오류로 정확한 줄을 짚어 줍니다. unsafe 코드가 있는 크레이트는 CI에서 cargo +nightly miri test를 돌리는 것이 좋은 습관입니다.

메모리 레이아웃: repr(Rust)는 재배치, repr(C)는 선언 순서

기본 레이아웃(repr(Rust))에서 컴파일러는 필드 순서를 바꿀 수 있고, 실제로 패딩을 줄이려 재배치합니다. 배치는 보장되지 않으므로 하드웨어 레지스터 맵, 네트워크 패킷, C 구조체와 메모리를 공유할 때는 #[repr(C)]로 C와 같은 규칙(선언 순서 + 정렬 패딩)을 요구합니다. #[repr(u8)]는 열거형 태그 크기를, #[repr(transparent)]는 "필드 하나짜리 래퍼가 그 필드와 같은 ABI"임을 보장합니다.

use std::mem::{align_of, offset_of, size_of};

#[allow(dead_code)]
#[repr(C)]
struct ImuPacketC { flags: u8, accel: [f32; 3], seq: u16, ts_us: u64 }

#[allow(dead_code)]
struct ImuPacketRust { flags: u8, accel: [f32; 3], seq: u16, ts_us: u64 }

#[allow(dead_code)]
#[repr(u8)]
#[derive(Debug, Clone, Copy)]
enum Cmd { Stop = 0, Move = 1, Dock = 0x10 }

#[repr(transparent)]
struct Millis(u32);

fn main() {
    println!("repr(C)    size {:>2} align {}  offsets: flags {} accel {} seq {} ts_us {}",
        size_of::(), align_of::(),
        offset_of!(ImuPacketC, flags), offset_of!(ImuPacketC, accel),
        offset_of!(ImuPacketC, seq), offset_of!(ImuPacketC, ts_us));
    println!("repr(Rust) size {:>2} align {}  offsets: flags {} accel {} seq {} ts_us {}",
        size_of::(), align_of::(),
        offset_of!(ImuPacketRust, flags), offset_of!(ImuPacketRust, accel),
        offset_of!(ImuPacketRust, seq), offset_of!(ImuPacketRust, ts_us));
    println!("Cmd: size {}  Dock as u8 = {:#04x}", size_of::(), Cmd::Dock as u8);
    println!("Millis: size {} (same as u32: {})", size_of::(), size_of::() == size_of::());
    println!("Option size {} (niche: unused tag values encode None)", size_of::>());
    let _ = (Cmd::Stop, Cmd::Move, Millis(5).0);
}


  
FFI: C를 부르고, C에게 불리기

  
C 함수는 unsafe extern "C" 블록에 선언하고 호출합니다(2024 에디션부터 블록 자체에 unsafe가 필요합니다. 선언이 틀리면 UB이기 때문입니다). 확실히 안전한 함수는 블록 안에서 safe fn으로 표시해 일반 함수처럼 부를 수 있습니다. 문자열은 CString/CStr로 NUL 종료를 맞추고, 콜백은 extern "C" fn으로 만들어 넘깁니다. 아래는 libc의 strlen과 qsort를 Rust에서 부르는 예입니다.


use std::ffi::{c_char, c_int, c_void, CStr, CString};

unsafe extern "C" {
    fn strlen(s: *const c_char) -> usize;
    fn qsort(base: *mut c_void, n: usize, size: usize,
             cmp: extern "C" fn(*const c_void, *const c_void) -> c_int);
    safe fn abs(x: c_int) -> c_int;           // declared safe: callable without `unsafe`
}

/// A Rust function with the C calling convention, passed to qsort as a callback.
extern "C" fn by_distance(a: *const c_void, b: *const c_void) -> c_int {
    // SAFETY: qsort only passes pointers to elements of the array we gave it (f32s).
    let (a, b) = unsafe { (*(a as *const f32), *(b as *const f32)) };
    a.total_cmp(&b) as c_int
}

fn main() {
    let name = CString::new("front_lidar").expect("no interior NUL");
    // SAFETY: `name` is a valid NUL-terminated string that outlives the call.
    let n = unsafe { strlen(name.as_ptr()) };
    println!("strlen = {n}, abs(-42) = {}", abs(-42));

    let mut ranges = [3.2f32, 0.4, 9.9, 1.5, 0.05];
    // SAFETY: pointer/len/size describe exactly our array; the comparator matches the element type.
    unsafe {
        qsort(ranges.as_mut_ptr().cast(), ranges.len(), size_of::(), by_distance);
    }
    println!("sorted by C qsort = {ranges:?}");

    let back: &CStr = name.as_c_str();
    println!("back to Rust: {}", back.to_str().unwrap());
}

  
반대로 Rust 함수를 C에서 부르게 하려면 이름 맹글링을 끄고(#[unsafe(no_mangle)], 2024 에디션 표기) C 호출 규약을 지정한 뒤, Cargo.toml에서 crate-type = ["staticlib"]나 ["cdylib"]로 빌드합니다. 헤더는 cbindgen이 생성하고, 반대 방향(C 헤더 → Rust 선언)은 bindgen이 생성합니다.


#[repr(C)]
pub struct Pose2D { pub x: f64, pub y: f64, pub theta: f64 }

/// Called from C. Returns 0 on success, -1 if `out` is null.
#[unsafe(no_mangle)]
pub extern "C" fn pose_compose(a: Pose2D, b: Pose2D, out: *mut Pose2D) -> i32 {
    let Some(out) = (unsafe { out.as_mut() }) else { return -1 };   // null -> None
    let (s, c) = a.theta.sin_cos();
    *out = Pose2D { x: a.x + c * b.x - s * b.y, y: a.y + s * b.x + c * b.y, theta: a.theta + b.theta };
    0
}


/* pose.h (generated by cbindgen) */
typedef struct { double x, y, theta; } Pose2D;
int32_t pose_compose(Pose2D a, Pose2D b, Pose2D *out);

int main(void) {
    Pose2D out;
    if (pose_compose((Pose2D){1, 0, 0}, (Pose2D){0, 1, 0}, &out) == 0)
        printf("%f %f\n", out.x, out.y);
}

  
임베디드: volatile 레지스터 접근을 safe API로

  
메모리 맵 I/O는 반드시 read_volatile/write_volatile로 접근해 컴파일러가 접근을 없애거나 합치지 못하게 합니다. 실무에서는 이것을 직접 쓰기보다 SVD 파일에서 생성한 PAC(peripheral access crate)와 그 위의 HAL을 씁니다. 원리는 아래처럼 "주소가 유효하다"는 증명을 생성자 한 곳에 모으는 것입니다.


#[repr(C)]
struct GpioRegs { moder: u32, otyper: u32, ospeedr: u32, pupdr: u32, idr: u32, odr: u32 }

pub struct Gpio { regs: *mut GpioRegs }

impl Gpio {
    /// # Safety
    /// `base` must be the address of a GPIO block, and only one `Gpio` may exist per block.
    pub const unsafe fn new(base: usize) -> Self { Gpio { regs: base as *mut GpioRegs } }

    pub fn set_high(&mut self, pin: u32) {
        // SAFETY: `regs` is valid per the constructor contract; &mut self gives exclusive access.
        unsafe {
            let odr = &raw mut (*self.regs).odr;
            odr.write_volatile(odr.read_volatile() | (1 << pin));
        }
    }
}
