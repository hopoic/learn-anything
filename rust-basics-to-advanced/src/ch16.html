Part IV · 고급 엔지니어의 Rust — 16장

크레이트·테스트·성능

이 장을 마치면: 모듈 트리와 가시성(pub, pub(crate))으로 API 경계를 설계할 수 있고, 단위·통합·문서 테스트를 구분해 쓸 수 있으며, 워크스페이스·feature·릴리스 프로필·크로스 컴파일을 설정하고, 측정(벤치마크·프로파일링)에 근거해 성능을 개선하는 흐름을 설명할 수 있습니다.

15장까지 언어를 배웠습니다. 고급 엔지니어의 일은 그 언어로 여러 사람이 오래 유지할 수 있는 코드베이스를 만드는 것입니다. Rust 생태계는 이 부분의 도구가 유난히 잘 표준화되어 있습니다.

모듈과 가시성: 기본은 비공개

크레이트는 컴파일 단위(라이브러리 하나 또는 실행 파일 하나)이고, 그 안을 모듈 트리로 나눕니다. 모든 항목은 기본적으로 자기 모듈 안에서만 보입니다. 밖으로 노출할 것만 pub을 붙이고, 크레이트 안에서만 공유할 것은 pub(crate)를 씁니다. 구조체 필드도 따로 공개해야 하므로, 15장의 Speed처럼 "검증 없이는 만들 수 없는 타입"을 쉽게 만들 수 있습니다.

robot/ # a Cargo workspace ├── Cargo.toml # [workspace] members = ["crates/*", "apps/*"] ├── crates/ │ ├── proto/ # wire format: no_std-compatible, no deps │ │ └── src/lib.rs # mod frame; mod crc; pub use frame::Frame; │ └── bus/ # message bus, depends on proto └── apps/ └── robotd/ # the binary: wires everything together └── src/main.rs // In a real crate each `mod` would be its own file (src/sensors.rs, src/sensors/imu.rs...). mod sensors { pub mod imu { #[derive(Debug)] pub struct Sample { pub ax: f32, pub ay: f32, pub(crate) raw: u16 } // `raw` hidden outside the crate pub fn read() -> Sample { Sample { ax: 0.1, ay: -0.2, raw: calibrate(512) } } fn calibrate(x: u16) -> u16 { x - super::OFFSET } // private helper } const OFFSET: u16 = 12; // private to `sensors` and its children pub use imu::Sample as ImuSample; // re-export: a flatter public API } mod control { use crate::sensors::ImuSample; // absolute path from the crate root pub fn tilt(s: &ImuSample) -> f32 { s.ay.atan2(s.ax).to_degrees() } } fn main() { let s = sensors::imu::read(); println!("{s:?} tilt = {:.1} deg, raw = {}", control::tilt(&s), s.raw); // sensors::imu::calibrate(1); // error[E0603]: function `calibrate` is private }

테스트는 언어에 내장되어 있다

#[test] 함수를 쓰고 cargo test를 실행하면 끝입니다. 테스트에는 세 종류가 있습니다.

종류위치볼 수 있는 것용도
단위 테스트같은 파일의 #[cfg(test)] mod tests비공개 항목까지내부 로직
통합 테스트tests/*.rs공개 API만사용자 관점 시나리오
문서 테스트/// 주석 안의 코드 블록공개 API만예제가 항상 컴파일·통과함을 보장
/// CRC-8 (polynomial 0x07), as used by many sensor protocols. /// /// ``` /// assert_eq!(proto::crc8(b"123456789"), 0xF4); // doc test: runs with `cargo test` /// ``` pub fn crc8(data: &[u8]) -> u8 { let mut crc = 0u8; for &b in data { crc ^= b; for _ in 0..8 { crc = if crc & 0x80 != 0 { (crc << 1) ^ 0x07 } else { crc << 1 }; } } crc } #[cfg(test)] // compiled only for `cargo test` mod tests { use super::*; #[test] fn empty_is_zero() { assert_eq!(crc8(&[]), 0); } #[test] fn detects_single_bit_flips() { let msg = *b"robot"; let good = crc8(&msg); for i in 0..msg.len() * 8 { let mut m = msg; m[i / 8] ^= 1 << (i % 8); assert_ne!(crc8(&m), good, "bit {i} not detected"); } } #[test] #[should_panic(expected = "index out of bounds")] fn panics_are_testable_too() { let v: Vec = vec![]; let _ = v[0]; } }

이 페이지의 실행 엔진은 main을 실행하므로, 같은 테스트를 main에서 직접 돌려 확인해 보겠습니다. 실무에서는 위처럼 #[test]로 두고 cargo test를 씁니다.

fn crc8(data: &[u8]) -> u8 { let mut crc = 0u8; for &b in data { crc ^= b; for _ in 0..8 { crc = if crc & 0x80 != 0 { (crc << 1) ^ 0x07 } else { crc << 1 }; } } crc } fn main() { assert_eq!(crc8(&[]), 0); assert_eq!(crc8(b"123456789"), 0xF4, "standard CRC-8 check value"); let msg = *b"robot"; let good = crc8(&msg); let mut detected = 0; for i in 0..msg.len() * 8 { let mut m = msg; m[i / 8] ^= 1 << (i % 8); if crc8(&m) != good { detected += 1; } } println!("crc8(\"robot\") = {good:#04x}; single-bit flips detected: {detected}/{}", msg.len() * 8); println!("all checks passed"); }
고급 테스트 도구
  • 속성 기반 테스트(proptest): "임의의 입력에 대해 encode 후 decode하면 원래 값"처럼 성질을 쓰면 수백 개의 입력을 생성해 반례를 찾고, 반례를 최소화해 줍니다.
  • 퍼징(cargo fuzz): 파서처럼 외부 입력을 받는 코드에 필수. libFuzzer가 커버리지를 따라 입력을 변형합니다.
  • 스냅샷 테스트(insta), 동시성 모델 검사(loom: 원자 연산과 락의 가능한 모든 실행 순서를 탐색), Miri(14장).

성능: 추측하지 말고 측정하라

Rust는 기본적으로 빠르지만, 빠른 코드를 쓰는 습관은 다른 언어와 같습니다. 먼저 release로 빌드하고(debug는 최적화가 없어 10배 이상 느릴 수 있습니다), 측정하고, 할당과 복사를 줄이고, 다시 측정합니다. 아래 예제는 release 모드로 실행되도록 표시되어 있습니다. 같은 합계를 세 가지 방식으로 구해 시간을 비교합니다(온라인 엔진은 다른 작업과 CPU를 나눠 쓰므로 수치는 참고만 하세요).

use std::hint::black_box; use std::time::Instant; fn time(label: &str, f: impl Fn() -> T) -> T { let t = Instant::now(); let mut out = f(); for _ in 0..9 { out = black_box(f()); } // repeat; black_box stops the optimizer from deleting work println!("{label:<28} {:>8.2} ms/iter", t.elapsed().as_secs_f64() * 100.0); out } fn main() { let data: Vec = (0..2_000_000u32).map(|i| i.wrapping_mul(2_654_435_761) >> 20).collect(); let data = black_box(data); let a = time("index loop", || { let mut s = 0u64; for i in 0..data.len() { s += data[i] as u64; } s }); let b = time("iterator sum", || data.iter().map(|&x| x as u64).sum::()); let c = time("allocating Vec (bad)", || { let v: Vec = data.iter().take(200_000).map(|x| x.to_string()).collect(); v.len() as u64 }); println!("same result: {}, (c = {c})", a == b); }
1cargo build --release, 그리고 실제 데이터로 재현 가능한 벤치마크(criterion, divan)를 만든다.
2프로파일러로 뜨거운 곳을 찾는다: perf record + cargo flamegraph, 할당은 heaptrack/dhat.
3알고리즘과 자료구조부터 바꾼다(7장의 컬렉션 선택). 그다음 할당 제거: with_capacity, 버퍼 재사용, &str/Cow.
4복사·간접 호출을 줄인다: 제네릭 vs dyn(8장), 데이터 배치(SoA), #[inline]은 측정 후에만.
5병렬화(rayon의 par_iter, 12장 scoped thread), SIMD(std::simd는 아직 nightly, 안정판에선 std::arch 내장 함수).
팀 리드의 눈으로

Rust 도입의 성패는 언어보다 CI 게이트에 달려 있는 경우가 많습니다. fmt --check, clippy -D warnings, test, unsafe가 있으면 miri, 의존성 audit/cargo deny를 첫날부터 걸어 두세요. 이 다섯 가지가 리뷰어가 사람에게만 집중하게 해 줍니다.

흔한 함정
  • debug 빌드로 성능을 재고 "Rust가 느리다"고 결론 내리기. 항상 --release.
  • 공개 API 타입에 의존성 크레이트의 타입이 노출되면, 그 크레이트의 메이저 업데이트가 내 크레이트의 브레이킹 체인지가 됩니다. 경계에서는 자기 타입으로 감싸세요.
  • feature는 더하기만 해야 합니다(additive). feature를 켰을 때 기존 API가 사라지면 의존성 그래프 어딘가에서 깨집니다.

이제 모든 도구가 갖춰졌습니다. 마지막 장에서 지금까지 배운 것을 하나의 프로그램으로 묶습니다.
