클로저와 반복자

이 장을 마치면: 클로저가 환경을 어떻게 캡처하는지(빌림·가변 빌림·이동)와 그에 따른 Fn/FnMut/FnOnce를 구분할 수 있고, 반복자 어댑터 체인이 게으르게(lazy) 원소 하나씩 당겨 처리된다는 것을 설명할 수 있으며, 직접 Iterator를 구현해 표준 어댑터를 공짜로 얻을 수 있습니다.

8장에서 트레잇을 배웠습니다. 클로저와 반복자는 트레잇이 실제로 얼마나 강력한지 보여 주는 예입니다. 둘 다 제네릭 + 단형화로 컴파일되므로, 고수준으로 써도 손으로 짠 루프와 같은 기계어가 나옵니다.

클로저는 환경을 캡처하는 익명 구조체다

|x| x + offset 같은 클로저는 컴파일러가 만드는 이름 없는 구조체입니다. 본문에서 쓰는 바깥 변수(offset)를 필드로 담고, 호출 연산을 구현합니다. 어떻게 담는지는 본문이 그 변수를 어떻게 쓰는지로 자동 결정됩니다.

본문이 하는 일캡처 방식구현하는 트레잇몇 번 호출?
읽기만&TFn몇 번이든, 동시에도
바꾼다&mut TFnMut몇 번이든, 한 번에 하나씩
소유권을 가져가 소비값(이동)FnOnce한 번만

세 트레잇은 포함 관계입니다. Fn이면 FnMut이고, FnMut이면 FnOnce입니다. 함수를 받는 쪽은 가장 약한 요구를 쓰는 것이 좋습니다. 한 번만 부를 거면 FnOnce를 받으세요. 그래야 호출자가 가장 많은 종류의 클로저를 넘길 수 있습니다. move 키워드는 본문이 빌리기만 해도 강제로 값을 이동해 담게 합니다. 클로저를 다른 스레드로 보내거나 함수 밖으로 반환할 때 필요합니다(12장).

fn apply_n(n: usize, mut f: F) { for _ in 0..n { f(); } } fn run_once String>(f: F) -> String { f() } // Returning closures: `impl Fn` (static) or Box (dynamic). fn make_scaler(k: f64) -> impl Fn(f64) -> f64 { move |x| x * k } fn make_filter(kind: &str) -> Box bool> { match kind { "positive" => Box::new(|x| x > 0.0), _ => Box::new(|x| x.is_finite()), } } fn main() { let offset = 0.5; let add = |x: f64| x + offset; // Fn: borrows `offset` println!("add(1) = {}", add(1.0)); let mut count = 0; apply_n(3, || count += 1); // FnMut: mutably borrows `count` println!("count = {count}"); let log = String::from("calibration done"); let consume = move || log + "!"; // FnOnce: moves `log` and consumes it println!("{}", run_once(consume)); // println!("{log}"); // error: `log` was moved into the closure let to_cm = make_scaler(100.0); let keep = make_filter("positive"); let data = [0.12, -0.4, 0.33]; let cm: Vec = data.iter().copied().filter(|x| keep(*x)).map(&to_cm).collect(); println!("cm = {cm:?}"); }

반복자는 게으르다: 원소 하나씩 끝까지 당긴다

Iterator 트레잇의 필수 메서드는 하나뿐입니다. fn next(&mut self) -> Option<Self::Item>. map, filter, take 같은 어댑터는 다른 반복자를 감싸는 작은 구조체일 뿐, 만들 때는 아무 일도 하지 않습니다. collect, sum, for 같은 소비자가 next()를 부를 때, 체인의 맨 끝에서 맨 앞까지 원소 하나를 당겨 와 끝까지 통과시킵니다. 중간 배열이 생기지 않고, take(2)가 만족되면 앞쪽 원소는 아예 계산하지 않습니다.

자주 쓰는 어댑터와 소유권 세 갈래

컬렉션에서 반복자를 얻는 방법은 세 가지이고, 소유권 규칙과 정확히 대응합니다. iter()는 &T를, iter_mut()는 &mut T를, into_iter()는 컬렉션을 소비하며 T를 내놓습니다. for x in &v는 v.iter(), for x in v는 v.into_iter()입니다.

#[derive(Debug)] struct Reading { sensor: &'static str, value: f64, ok: bool } fn main() { let rs = vec![ Reading { sensor: "imu", value: 0.98, ok: true }, Reading { sensor: "lidar", value: 12.4, ok: false }, Reading { sensor: "imu", value: 1.02, ok: true }, Reading { sensor: "cam", value: 30.0, ok: true }, ]; let healthy = rs.iter().filter(|r| r.ok).count(); let imu_mean = { let (sum, n) = rs.iter().filter(|r| r.sensor == "imu") .fold((0.0, 0), |(s, n), r| (s + r.value, n + 1)); sum / n as f64 }; let names: Vec<_> = rs.iter().map(|r| r.sensor).collect::>().into_iter().collect(); let first_bad = rs.iter().position(|r| !r.ok); let all_positive = rs.iter().all(|r| r.value > 0.0); println!("healthy={healthy} imu_mean={imu_mean:.2} names={names:?} first_bad={first_bad:?} all>0={all_positive}"); // zip + windows: deltas between consecutive samples let t = [0.0, 0.1, 0.25, 0.4]; let x = [0.0, 0.05, 0.2, 0.3]; let v: Vec = t.windows(2).zip(x.windows(2)) .map(|(tw, xw)| (xw[1] - xw[0]) / (tw[1] - tw[0])).collect(); println!("velocities = {v:.2?}"); // chunks + flat_map: split a byte stream into 3-byte frames and flatten fields let bytes = [1u8, 2, 3, 4, 5, 6, 7]; let sums: Vec = bytes.chunks(3).map(|c| c.iter().map(|&b| b as u32).sum()).collect(); println!("chunk sums = {sums:?}"); // into_iter consumes: partition into owned vectors let (good, bad): (Vec, Vec) = rs.into_iter().partition(|r| r.ok); println!("good={} bad={:?}", good.len(), bad); }

직접 만든 반복자도 일급 시민

next() 하나만 구현하면 map, filter, zip, sum 등 70개가 넘는 메서드를 공짜로 얻습니다. 하드웨어 레지스터를 순회하거나, 링 버퍼를 읽거나, 프로토콜 프레임을 하나씩 잘라내는 코드를 반복자로 만들면 나머지 표준 도구와 자연스럽게 맞물립니다.

/// Yields fixed-point samples from a simple linear-feedback shift register (a fake noise source). struct Lfsr { state: u16 } impl Iterator for Lfsr { type Item = u16; fn next(&mut self) -> Option { let bit = (self.state ^ (self.state >> 2) ^ (self.state >> 3) ^ (self.state >> 5)) & 1; self.state = (self.state >> 1) | (bit << 15); Some(self.state) // infinite: never returns None } } fn main() { let noise = Lfsr { state: 0xACE1 }; let samples: Vec = noise.take(5).collect(); println!("{samples:04X?}"); let mean = Lfsr { state: 0xACE1 }.take(1000).map(|x| x as f64).sum::() / 1000.0; println!("mean of 1000 samples = {mean:.0} (ideal ~32768)"); let above = Lfsr { state: 1 }.take(64).filter(|&x| x > 0x8000).count(); println!("{above} of 64 samples above midscale"); }
성능 엔지니어의 눈으로

반복자 체인은 컴파일 후 손으로 쓴 for 루프와 사실상 같은 기계어가 됩니다. 단형화로 모든 클로저가 인라인되고, iter()는 범위를 이미 알고 있어 인덱스 범위 검사도 생략됩니다. 오히려 for i in 0..v.len() { v[i] }가 매 접근마다 범위 검사를 해야 해서 느릴 수 있습니다. 확신이 서지 않으면 Compiler Explorer에서 두 버전의 어셈블리를 비교해 보세요.

흔한 함정
  • 어댑터만 만들고 소비하지 않으면 아무 일도 일어나지 않습니다. 컴파일러가 unused_must_use로 "iterators are lazy"라고 경고합니다.
  • collect()는 결과 타입을 알아야 합니다. let v: Vec<_> = ...나 터보피시 collect::<Vec<_>>()로 알려 주세요. Result<Vec<T>, E>로 collect하면 첫 오류에서 멈추는 것까지 됩니다.
