동적 계획법

이 장을 마치면: 문제가 DP로 풀리는지 판별하고, 상태·전이·기저·계산 순서를 정의해 점화식을 세우며, 표를 채운 뒤 역추적으로 실제 답을 복원하고, 1차원 배열로 메모리를 줄일 수 있습니다.

같은 계산을 두 번 하지 않는다

피보나치 수를 정의대로 재귀하면 fib(n−2)를 두 번, fib(n−3)을 세 번 계산하며 호출 수가 지수적으로 늘어납니다. 한 번 계산한 값을 저장해 두면 각 값을 한 번씩만 계산하므로 O(n)이 됩니다. 이것이 동적 계획법(DP)의 전부입니다. 다만 아무 문제에나 통하지 않고 두 조건이 필요합니다.

  • 겹치는 부분 문제: 같은 작은 문제가 여러 번 등장한다. (안 겹치면 그냥 분할 정복입니다. 병합 정렬처럼.)
  • 최적 부분 구조: 큰 문제의 최적해가 작은 문제들의 최적해로 조립된다.

구현 방식은 두 가지입니다. 하향식(메모이제이션)은 재귀를 그대로 쓰고 결과를 캐시합니다. 점화식을 그대로 옮기면 되어 실수가 적고, 실제로 필요한 상태만 계산합니다. 상향식(타뷸레이션)은 작은 상태부터 표를 채웁니다. 재귀 깊이 제한이 없고, 루프라서 빠르고, 메모리 최적화가 쉽습니다.

DP 설계 레시피 다섯 단계

  1. 상태: 부분 문제를 무엇으로 식별하나? "dp[i][j] = a의 앞 i글자와 b의 앞 j글자의 LCS 길이"처럼 한 문장으로 쓸 수 있어야 합니다.
  2. 전이: 상태 하나를 더 작은 상태들로 어떻게 표현하나? 마지막 선택(마지막 글자를 쓰나 안 쓰나, 마지막 물건을 넣나 안 넣나)을 기준으로 경우를 나누면 대개 나옵니다.
  3. 기저: 더 쪼갤 수 없는 상태의 값. 빈 문자열, 용량 0.
  4. 순서: 표를 채울 때 오른쪽 항이 항상 먼저 계산되어 있게.
  5. 복원: 값만이 아니라 답 자체(경로, 선택한 물건)가 필요하면, 표를 끝에서부터 거꾸로 따라가거나 선택을 따로 기록합니다.

공간 최적화와 0/1 배낭의 함정

배낭 문제의 2차원 점화식 best[k][c] = max(best[k−1][c], best[k−1][c−w_k] + v_k)는 바로 위 행만 봅니다. 그래서 1차원 배열 하나로 줄일 수 있는데, 용량을 큰 쪽에서 작은 쪽으로 돌아야 합니다. 작은 쪽부터 돌면 best[c − w_k]가 이미 이번 물건을 넣은 값으로 바뀌어 있어 같은 물건을 여러 번 넣게 됩니다. 그건 물건을 무제한 쓸 수 있는 "무한 배낭"의 정답입니다. 루프 방향 하나로 문제가 바뀝니다.

LIS의 O(n log n) 풀이는 DP 표를 tails 배열로 압축하고 7장의 lower_bound로 갱신 위치를 찾습니다. DP와 이분 탐색의 조합은 자주 나오는 패턴입니다.

고급 자료구조

이 장을 마치면: 질의 유형을 보고 펜윅 트리, 세그먼트 트리, 트라이 중 맞는 것을 고르고 구현할 수 있으며, 해시 맵과 연결 리스트를 조합해 O(1) LRU 캐시를 만들 수 있습니다.

질의가 자료구조를 정한다

지금까지의 자료구조로도 대부분의 문제를 풀 수 있지만, "값이 계속 바뀌는데 구간 합이나 최솟값을 자주 묻는다", "접두사로 찾는다", "최근에 쓴 것만 남긴다" 같은 요구가 오면 O(n) 스캔이 병목이 됩니다. 이 장의 구조들은 그 특정 질의를 O(log n)이나 O(키 길이)로 줄이기 위해 만들어졌습니다.

펜윅 트리: 최하위 비트 하나로 만든 트리

펜윅 트리는 배열 t의 i번째 칸이 "i에서 시작해 거꾸로 i & −i개 원소의 합"을 저장합니다. i & −i는 i의 최하위 1비트입니다(2의 보수 덕분). 접두사 합은 i에서 최하위 비트를 하나씩 지우며 log n개의 칸을 더하고, 갱신은 최하위 비트를 더해 가며 log n개의 칸을 고칩니다. 코드가 열 줄도 안 되고 상수가 아주 작아서, 구간 합만 필요하면 세그먼트 트리보다 먼저 고려합니다.

세그먼트 트리: 구간을 반씩 나눠 미리 계산

세그먼트 트리는 배열 구간을 반씩 나눈 이진 트리이고, 각 노드가 자기 구간의 결과(최솟값, 합…)를 저장합니다. 결합 법칙만 성립하면 어떤 연산이든 됩니다. 아래 구현은 크기 2n 배열에 리프를 뒤쪽 n칸에 두는 반복형으로, 재귀형보다 짧고 빠릅니다. 구간 전체에 값을 더하는 갱신이 필요하면 "아직 자식에게 내려보내지 않은 갱신"을 노드에 적어 두는 지연 전파(lazy propagation)로 확장합니다.

트라이: 공통 접두사를 공유하는 트리

트라이는 문자열을 글자 단위로 쪼개 경로로 저장합니다. 같은 접두사를 가진 키들은 경로를 공유하므로, "/amr2로 시작하는 모든 토픽"을 키 개수와 무관하게 O(접두사 길이)에 찾아갑니다. 아래 구현은 노드를 vector에 두고 인덱스로 연결합니다. 3장에서 말한 아레나 방식이라 Rust로 옮기기도 쉽습니다. 단, 노드를 추가하며 vector가 재할당되면 기존 노드 참조가 무효화되므로, 코드에서 Node&를 붙잡지 않고 매번 인덱스로 접근하는 점을 눈여겨보세요.

A*: 다익스트라에 방향 감각을 더하다

다익스트라는 출발점에서 가까운 순서로, 즉 동심원 모양으로 퍼집니다. 목표가 동쪽에 있어도 서쪽을 똑같이 탐색합니다. A*는 힙의 키를 g(n)(출발점부터 실제 비용) 대신 f(n) = g(n) + h(n)으로 바꿉니다. h(n)은 n에서 목표까지 남은 비용의 추정치입니다.

  • 허용적(admissible): h가 실제 남은 비용을 절대 넘지 않으면 A*는 최적 경로를 찾습니다.
  • 일관적(consistent): 이웃 n'에 대해 h(n) ≤ c(n, n') + h(n')이면, 한 번 닫힌 노드는 다시 열 필요가 없습니다. 아래 코드의 닫힌 목록이 이 성질에 기댑니다.
  • h = 0이면 다익스트라와 같고, h가 정확할수록 탐색이 목표를 향해 좁아집니다. h에 가중치 w > 1을 곱하면(Weighted A*) 훨씬 적게 탐색하는 대신 최적 비용의 최대 w배까지 나쁜 경로를 받아들입니다.

8방향 격자에서 장애물이 없을 때의 정확한 거리는 옥타일 거리 (dx + dy) + (√2 − 2)·min(dx, dy)입니다. 대각선으로 min(dx, dy)칸, 남은 거리는 직선으로 가는 비용이라 허용적이고 일관적입니다. 4방향 격자라면 맨해튼 거리, 자유 공간이라면 유클리드 거리를 씁니다.

Nav2의 NavFn은 이 구조에 코스트맵의 연속 비용, 경로 평활화, 목표 허용 오차를 더한 것이고, Smac Hybrid-A*는 상태에 방향(θ)을 넣고 차량의 최소 회전 반경을 지키는 모션 프리미티브로 이웃을 만듭니다. 원리는 이 장의 120줄과 같습니다.

확장 과제

하나씩 구현하고, 매번 같은 지도 세트에서 비용·확장 노드 수·실행 시간을 표로 비교하세요.

  1. 코스트맵: 칸마다 0–254 비용을 두고, 8장의 브러시파이어 BFS로 장애물 근처 비용을 높이는 팽창 계층을 만든다. 간선 비용 = 거리 × (1 + 칸 비용/α).
  2. 타이 브레이킹: f가 같으면 h가 작은(목표에 가까운) 노드를 먼저 꺼내게 힙 키를 (f, h)로 바꾸고, 열린 공간에서 확장 수가 얼마나 줄어드는지 측정한다.
  3. 자체 힙으로 교체: 6장의 MinHeap에 decrease-key(위치 인덱스 배열 유지)를 추가해 지연 삭제와 성능을 비교한다.
  4. 대형 지도: 2000×2000 지도를 생성해 Python, C++, Rust 구현의 실행 시간과 메모리를 측정하고, 1장의 측정 원칙대로 보고한다.
  5. Jump Point Search: 균일 비용 격자에서 대칭 경로를 건너뛰어 확장 수를 크게 줄이는 JPS를 구현한다.
  6. 동적 재계획: 로봇이 이동 중 새 장애물을 발견하면 처음부터 다시 계산하는 대신 이전 결과를 재사용하는 D* Lite를 조사하고 구현한다.
  7. ROS 2 통합: nav2_core::GlobalPlanner 인터페이스로 플러그인을 만들어 Nav2에 붙이고, NavFn과 같은 시나리오에서 비교한다.
