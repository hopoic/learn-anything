엔지니어를 위한 수학 교본

수식=그림+코드

수학을 포기했던 엔지니어를 위한 책입니다. 공식을 외우게 하지 않습니다. 모든 수식을 그림 한 장과 코드 몇 줄로 바꿔서 보여 드립니다. 반복문을 읽을 수 있다면 Σ를 읽을 수 있고, 센서 값을 누적해 본 적이 있다면 이미 적분을 해 본 것입니다. 수식 기호 읽기에서 시작해 지수와 로그, 삼각함수, 미적분, 벡터와 행렬, 복소수, 확률과 통계를 차례로 다시 세우고, 마지막에는 이 모든 것을 합쳐 로봇의 위치를 추정하는 칼만 필터를 직접 만듭니다.

수식은 코드다

이 장을 마치면: 엔지니어링 문서에 자주 나오는 기호(첨자, 함수 표기, Σ, Π, |x|, Δ, 그리스 문자)를 소리 내어 읽을 수 있고, Σ가 들어간 수식을 for 루프로 옮길 수 있으며, 처음 보는 수식을 만났을 때 따라 할 수 있는 네 단계 읽기 절차를 갖게 됩니다.

수학을 못하는 게 아니라 언어를 모르는 것이다

데이터시트나 논문을 읽다가 수식이 나오면 눈이 저절로 다음 문단으로 넘어가는 경험, 많은 엔지니어가 갖고 있습니다. 그런데 그 수식이 하는 일을 코드로 보여 주면 대부분 "아, 이거였어?"라고 합니다. 이동평균, 센서 보정, 제어 루프처럼 이미 매일 짜고 있는 코드인 경우가 많기 때문입니다.

수학 표기법은 칠판에 손으로 빠르게 쓰기 위해 압축된 프로그래밍 언어라고 생각하면 편합니다. 변수 이름은 한 글자이고, 곱셈 기호는 생략하고, 반복문은 Σ 하나로 줄입니다. 그래서 어려워 보이는 것이지, 하는 일 자체가 어려운 경우는 생각보다 적습니다. 이 책은 모든 수식을 읽는 법 → 그림 → 코드 순서로 풀어 드립니다.

임베디드 엔지니어의 눈으로

펌웨어에서 ADC 값을 8번 읽어 평균 내는 루프를 짜 본 적이 있다면 이미 Σ를 써 본 것이고, 타이머 인터럽트마다 pos += speed * dt를 해 봤다면 이미 적분을 해 본 것입니다. 이 책이 하는 일은 그 코드에 수학 이름표를 붙여 주는 것입니다.

Σ는 for 루프다

가장 중요한 번역 하나를 익히겠습니다. N개 측정값의 평균은 이렇게 씁니다.

x = 1N NΣi=1 xi
mean_loop.py
total = 0
for i in range(N):      # i = 1..N in the formula
    total += x[i]
x_bar = total / N

소리 내어 읽기: "x 바는, i를 1부터 N까지 바꿔 가며 x i를 모두 더한 것에 N분의 1을 곱한 것이다."

Σ 아래의 i=1은 루프 변수와 시작값, 위의 N은 끝값, 오른쪽의 xi는 루프 몸통에서 더하는 값입니다. 수학은 보통 1부터 세고 C와 Python은 0부터 셉니다. 번역할 때 인덱스 범위만 조심하면 됩니다.

조금 더 복잡한 것도 같은 방식입니다. 디지털 필터(FIR)의 정의는 이렇습니다.

yn = M−1Σk=0 hk · xn−k "n번째 출력은, 계수 h k와 k칸 전의 입력을 곱해서 M개 더한 것"

이건 "최근 M개 입력에 각각 가중치를 곱해 더한다"는 뜻입니다. 가중치가 모두 1/M이면 이동평균이 됩니다. 코드는 아래와 같고, 직접 실행해 확인할 수 있습니다. 이 책의 Python 예제는 모두 빌드할 때 실제로 실행해 결과를 확인한 것입니다.

sigma_is_a_loop.py · 실행 검증됨
import numpy as np

x = [2.0, 4.0, 4.0, 5.0, 7.0, 9.0]
N = len(x)

# x_bar = (1/N) * sum_{i=1..N} x_i
total = 0.0
for i in range(N):
    total += x[i]
print("mean (loop) :", total / N, "| numpy:", np.mean(x))

# y_n = sum_{k=0..M-1} h_k * x_{n-k}   (moving average when h_k = 1/M)
h = [1 / 3, 1 / 3, 1 / 3]
M = len(h)
y = []
for n in range(M - 1, N):
    acc = 0.0
    for k in range(M):
        acc += h[k] * x[n - k]
    y.append(round(acc, 3))
print("3-tap moving average:", y)

# prod_{i=1..3} (1 - p_i): probability that none of three parts fails
p = [0.01, 0.02, 0.05]
prod = 1.0
for pi in p:
    prod *= (1 - pi)
print("prod (1 - p_i) =", round(prod, 4))

처음 보는 수식을 읽는 네 단계

앞으로 어떤 수식을 만나도 이 순서로 읽으면 됩니다. 핵심은 수식을 한 번에 이해하려 하지 않고, 코드 리뷰하듯 안쪽부터 한 겹씩 벗기는 것입니다.

1단계소리 내어 읽는다. 기호 사전을 보며 한 기호도 빼지 않고 말로 바꿉니다. 읽을 수 없는 기호가 있으면 그것부터 찾습니다.
2단계정체를 가린다. 무엇이 입력(변하는 값)이고, 무엇이 상수이고, 무엇이 결과인지, 각각의 단위는 무엇인지 적습니다.
3단계작은 숫자를 넣어 본다. N = 2, x = 1처럼 손으로 계산할 수 있는 값을 넣어 결과가 상식에 맞는지 봅니다.
4단계코드로 옮겨 그려 본다. 입력을 바꿔 가며 출력이 어떻게 변하는지 그래프로 봅니다. 이 책의 실습 벤치가 이 단계입니다.

연습 삼아 전기 신호의 "실효값" RMS(Root Mean Square)를 읽어 봅시다.

xrms = √1N NΣi=1 xi2

안쪽부터 읽으면 ① 각 값을 제곱(Square)하고 ② 그것들의 평균(Mean)을 내고 ③ 루트(Root)를 씌웁니다. 이름 "Root Mean Square"는 이 순서를 바깥부터 읽은 것입니다. 수식을 코드로 옮기면 sqrt(mean(x**2)), 이름 순서 그대로입니다. 왜 그냥 평균을 내지 않고 제곱했다가 루트를 씌울까요? 교류처럼 +와 −를 오가는 신호는 그냥 평균 내면 0이 되어 버리기 때문입니다. 제곱하면 부호가 사라져 "얼마나 크게 흔들리는가"를 잴 수 있습니다.

흔한 함정
  • x^2는 제곱이 아니다: C와 Python에서 ^는 비트 XOR입니다. 수식의 x2를 그대로 옮기면 컴파일은 되지만 값이 엉뚱해집니다. x*x나 Python의 x**2를 쓰세요.
  • 생략된 곱셈과 우선순위: 2πft는 2*pi*f*t이고, 1/2x는 보통 1/(2x)로 읽습니다. 애매하면 괄호를 더 칩니다.
  • log의 밑: C의 log()와 Python의 math.log()는 자연로그(밑 e)입니다. 수식의 log가 상용로그(밑 10)라면 log10()을 써야 합니다(3장).
  • 1부터 vs 0부터: Σ 범위를 그대로 옮기면 배열 범위를 하나 넘어가기 쉽습니다.
핵심 정리
  • 수식은 압축된 코드다. 첨자는 배열 인덱스, Σ는 더하는 루프, Π는 곱하는 루프.
  • 그리스 문자는 공학에서 거의 정해진 뜻이 있다. 문자를 보면 양의 종류를 짐작한다.
  • 처음 보는 수식은 읽기 → 정체 가리기 → 작은 숫자 → 코드 순서로 안쪽부터 벗긴다.

이제 수식을 읽을 수 있게 되었으니, 수식이 다루는 가장 기본 단위인 "함수"로 넘어갑니다. 다음 장에서는 함수를 C 함수처럼 입력과 출력을 가진 상자로 보고, 그래프를 읽는 법과 센서 보정에 쓰는 직선의 수학을 익힙니다.

확인 문제

Part I · 수학의 언어 — 2장

함수와 그래프

이 장을 마치면: 함수를 입력과 출력을 가진 상자로 보고 그래프에서 값을 읽을 수 있고, 직선 y = ax + b의 기울기와 절편을 단위와 함께 해석해 센서 2점 보정과 선형 보간을 할 수 있으며, 2차·지수·주기 함수의 모양을 구분하고 그래프를 옮기고 늘리는 규칙을 쓸 수 있습니다.

함수는 입력을 받아 출력을 돌려주는 상자다

1장에서 수식이 코드라고 했습니다. 그 코드의 기본 단위가 함수입니다. 수학의 함수는 C 함수와 거의 같습니다. 값을 하나 넣으면 값이 하나 나옵니다. 다만 수학의 함수는 전역 변수를 건드리지 않는 순수 함수입니다. 같은 입력을 넣으면 언제나 같은 출력이 나옵니다.

그래프는 이 상자에 가능한 입력을 전부 넣어 보고, (입력, 출력) 쌍을 점으로 찍어 이은 그림입니다. 가로축(x축)이 입력, 세로축(y축)이 출력입니다. 그래프를 읽는다는 것은 "가로로 여기쯤이면 세로로 얼마인가"를 읽는 것이고, 더 중요하게는 "입력이 늘 때 출력이 어떻게 변하는가"라는 모양을 읽는 것입니다.

임베디드 엔지니어의 눈으로

써미스터 온도표처럼 함수를 계산하는 대신 표로 저장해 두는 것이 룩업 테이블(LUT)입니다. 표는 함수의 그래프에서 점 몇 개를 뽑아 둔 것이고, 점 사이 값은 아래에서 배울 선형 보간으로 채웁니다.

직선: 기울기는 "입력이 1 늘 때 출력이 얼마나"

가장 중요한 함수는 직선입니다. 공학에서 "선형(linear)"이라는 말이 나오면 대개 이 모양이 숨어 있습니다.

y = a · x + b a: 기울기(slope) · b: 절편(intercept), 즉 x = 0일 때의 y

읽는 법: "x가 1 늘 때마다 y는 a씩 늘고, 출발점은 b다."

기울기는 두 점 사이에서 세로 변화량 ÷ 가로 변화량, 즉 Δy/Δx입니다. 기울기에는 반드시 단위가 있다는 점이 중요합니다. 0°C에서 500 mV를 내고 1°C 오를 때마다 10 mV씩 오르는 온도 센서라면 V = 10 [mV/°C] · T + 500 [mV]입니다. 기울기의 단위 mV/°C를 보면 무엇을 무엇으로 나눈 값인지 바로 알 수 있습니다.

이 식을 거꾸로 풀면 전압에서 온도를 구할 수 있습니다. 양변에서 500을 빼고 10으로 나누면 T = (V − 500) / 10. 펌웨어가 하는 "변환"이 바로 이 역함수 계산입니다.

두 점이면 직선이 정해진다: 2점 보정과 선형 보간

실제 센서는 데이터시트 값과 조금씩 다릅니다. 그래서 알려진 두 조건에서 원시값(raw)을 읽어 직선을 직접 만듭니다. 예를 들어 12비트 ADC가 25.0°C에서 1240, 75.0°C에서 1860을 읽었다면 두 점 (1240, 25.0)과 (1860, 75.0)이 생깁니다.

a = y2 − y1x2 − x1 = 75.0 − 25.01860 − 1240 ≈ 0.0806 °C/count,   b = y1 − a x1 = −75.0 °C

이제 raw = 1500이면 T = 0.0806 × 1500 − 75.0 ≈ 46.0°C입니다. 같은 계산을 표의 이웃한 두 점 사이에서 하면 선형 보간(lerp, linear interpolation)이 됩니다. "두 점 사이를 직선으로 이었다고 치고 그 위의 값을 읽는다"는 뜻입니다.

y = y1 + (y2 − y1) · x − x1x2 − x1 오른쪽 분수는 "x가 두 점 사이 몇 % 지점에 있는가" (0이면 왼쪽 점, 1이면 오른쪽 점)
two_point_calibration.py · 실행 검증됨
import numpy as np

# Two known points: (raw ADC count, temperature in degC)
x1, y1 = 1240, 25.0
x2, y2 = 1860, 75.0

a = (y2 - y1) / (x2 - x1)        # slope  [degC per count]
b = y1 - a * x1                   # intercept [degC]
print(f"T = {a:.5f} * raw {b:+.2f}")
print(f"raw 1500 -> {a * 1500 + b:.2f} degC")

def lerp(x, xa, ya, xb, yb):
    t = (x - xa) / (xb - xa)      # 0 at the left point, 1 at the right point
    return ya + (yb - ya) * t

# A thermistor lookup table: interpolate between neighbouring entries
raw_tab = [800, 1200, 1600, 2000, 2400]
deg_tab = [-10.0, 12.0, 31.0, 47.0, 61.0]
raw = 1750
i = np.searchsorted(raw_tab, raw) - 1
print("table lerp :", lerp(raw, raw_tab[i], deg_tab[i], raw_tab[i + 1], deg_tab[i + 1]))

그래프를 옮기고 늘리는 네 가지 규칙

어떤 함수 f(x)든 아래 네 가지 조작으로 위치와 크기를 바꿀 수 있습니다. 4장에서 사인파의 위상을 다룰 때 바로 쓰게 됩니다.

바꾼 식그래프에 일어나는 일예
f(x) + c위로 c만큼 이동센서 오프셋
f(x − c)오른쪽으로 c만큼 이동 (빼는데 오른쪽!)신호 지연
k · f(x)세로로 k배 늘림증폭기 이득
f(kx)가로로 1/k배 압축주파수를 k배로

f(x − c)가 오른쪽으로 가는 이유는 이렇게 생각하면 쉽습니다. 원래 x = 0에서 일어나던 일이 이제는 x − c = 0, 즉 x = c가 되어야 일어납니다. 같은 사건이 c만큼 늦게 일어나니 그래프가 오른쪽으로 밀립니다.

흔한 함정
  • 단위 없는 기울기: 기울기 0.0806이라고만 적으면 무엇의 0.0806인지 알 수 없습니다. 항상 "°C/count"처럼 단위를 붙이세요.
  • 보정 범위 밖으로 외삽: 25–75°C에서 만든 직선을 −20°C에 그대로 쓰면, 센서가 그 범위에서 직선이 아닐 경우 오차가 커집니다. 보정 점은 실제 사용 범위의 양끝 근처에 잡습니다.
  • 정수 나눗셈: C에서 (y2 - y1) / (x2 - x1)를 정수로 계산하면 50/620 = 0이 됩니다. 고정소수점이라면 곱셈을 먼저 하고 나중에 나눕니다.
핵심 정리
  • 함수 = 입력을 출력으로 바꾸는 순수한 규칙, 그래프 = 그 규칙의 모양.
  • 직선의 기울기 = Δy/Δx, 단위를 붙여 읽는다. 두 점이면 직선이 정해진다.
  • f(x − c)는 오른쪽 이동, k·f는 세로로 늘림, f(kx)는 가로로 압축.

직선은 "더해서" 늘어나는 함수입니다. 그런데 "곱해서" 늘어나는 현상, 예를 들어 비트 수가 하나 늘면 표현 범위가 두 배가 되는 일은 직선으로 다룰 수 없습니다. 다음 장에서 이런 현상을 다루는 지수와, 그것을 거꾸로 묻는 로그를 익힙니다. 데시벨도 거기서 나옵니다.

지수와 로그

이 장을 마치면: 거듭제곱과 지수 법칙을 써서 비트 수·메모리 크기·과학적 표기를 다룰 수 있고, 로그를 "몇 번 곱했나"로 읽어 필요한 비트 수와 반감기를 계산하며, 데시벨(dB)을 자유롭게 변환하고 로그 눈금 그래프를 해석할 수 있습니다.

지수는 "몇 번 곱했나"다

2장의 직선은 x가 1 늘 때마다 같은 양을 더합니다. 지수는 x가 1 늘 때마다 같은 배수를 곱합니다.

2n = 2 × 2 × … × 2 (n번) 2를 밑(base), n을 지수(exponent)라고 부른다

임베디드 엔지니어에게는 이미 익숙한 이야기입니다. 1 << n은 2n이고, n비트로 표현할 수 있는 값의 개수도 2n입니다. 12비트 ADC는 212 = 4096단계, 비트 하나를 더하면 단계 수가 두 배가 됩니다. 비트 수는 더해서 늘지만 표현 범위는 곱해서 늘어납니다. 이것이 지수의 본질입니다.

지수의 계산 규칙은 "몇 번 곱했나"를 세어 보면 모두 당연해집니다.

규칙왜 그런가예
am · an = am+nm번 곱하고 또 n번 곱함210 · 210 = 220 (1 Ki × 1 Ki = 1 Mi)
(am)n = amnm번 곱한 묶음을 n번(103)2 = 106
a0 = 1한 번도 안 곱함. 곱셈의 시작값은 1prod = 1.0으로 시작하는 이유
a−n = 1/an음수 번 곱함 = 그만큼 나눔10−6 = 0.000001 (마이크로)
a1/2 = √a두 번 곱하면 a가 되는 수40.5 = 2

과학적 표기 3.3e−6은 3.3 × 10−6, 즉 3.3 μ입니다. 210 = 1024 ≈ 103이라는 사실도 기억해 두면 편합니다. 220 ≈ 백만, 230 ≈ 십억, 232 ≈ 43억(32비트 카운터의 한계)을 암산할 수 있습니다.

로그는 지수를 거꾸로 묻는다

지수가 "2를 10번 곱하면?"(답: 1024)이라면, 로그는 그 질문을 뒤집습니다. "2를 몇 번 곱하면 1024가 되나?"(답: 10)

log2 1024 = 10  ⇔  210 = 1024 loga x: "a를 몇 번 곱해야 x가 되나"

로그의 가장 유용한 성질은 곱셈을 덧셈으로 바꾼다는 것입니다. 지수의 첫 번째 규칙을 뒤집은 것입니다.

log(a · b) = log a + log b,   log(an) = n · log a

그래서 로그는 "몇 자리 수인가", "몇 비트가 필요한가", "몇 배인가"를 다룰 때 등장합니다.

  • 필요한 비트 수: 5000가지 값을 구분하려면 log2 5000 ≈ 12.3이므로 올림해서 13비트.
  • 자릿수: log10 1,000,000 = 6. 상용로그는 "10을 몇 번 곱했나", 즉 대략 자릿수입니다.
  • 이진 탐색 횟수: 100만 개 정렬 배열에서 찾기는 log2 106 ≈ 20번 비교면 충분합니다.

밑이 2인 로그(log2), 10인 로그(log10) 말고 밑이 e ≈ 2.718인 자연로그 ln도 자주 나옵니다. e가 왜 특별한지는 5장과 7장에서 미분과 함께 보게 됩니다. 지금은 "자연 현상의 성장·감쇠를 다룰 때 계산이 가장 깔끔해지는 밑"이라고만 알아 두세요.

데시벨: 엔지니어가 매일 쓰는 로그

앰프 이득, 필터 감쇠, 신호 대 잡음비(SNR)는 모두 "몇 배인가"라는 비율입니다. 비율은 수백만 배에서 백만분의 일까지 범위가 넓고, 여러 단을 거치면 곱해집니다. 로그를 취하면 범위가 다루기 쉬워지고 곱셈이 덧셈이 됩니다. 이것이 데시벨입니다.

지수적 성장과 감쇠, 그리고 로그 그래프 위의 직선

"일정한 시간마다 두 배"가 되는 현상은 2t/T로 쓸 수 있고, T를 배증 시간이라고 합니다. 반대로 "일정한 시간마다 절반"이 되는 현상은 2−t/T, T는 반감기입니다. 커패시터 방전, 뜨거운 모터의 냉각, 신호가 매질을 지나며 약해지는 현상이 모두 이런 모양입니다.

지수 곡선을 세로축이 로그 눈금인 그래프에 그리면 직선이 됩니다. log(2t/T) = (t/T) · log 2이므로 t에 대한 1차식이기 때문입니다. 실험 데이터를 로그 그래프에 그려 직선이 나오면 "이건 지수 현상이구나" 하고 알아챌 수 있고, 그 기울기에서 반감기를 읽을 수 있습니다.

삼각함수와 회전

이 장을 마치면: 도(°)와 라디안을 오가며 바퀴의 이동 거리를 계산할 수 있고, sin과 cos을 원 위를 도는 점의 좌표로 이해해 직각삼각형 문제를 풀며, 사인파 A sin(2πft + φ)의 세 숫자를 읽고, atan2와 각도 정규화로 로봇의 방향 오차를 올바르게 계산할 수 있습니다.

라디안: 반지름으로 잰 각도

학교에서는 각도를 도(°)로 배웠지만, 공학 수식과 프로그래밍 라이브러리는 거의 모두 라디안(rad)을 씁니다. 라디안은 "호의 길이가 반지름의 몇 배인가"로 잰 각도입니다. 반지름 1인 원에서 호 길이 1만큼 돈 각도가 1 rad입니다.

s = r · θ   (θ는 라디안) 원 한 바퀴의 둘레 2πr ⇒ 한 바퀴 = 2π rad = 360°, 1 rad ≈ 57.3°

이 단순한 식 하나가 라디안을 쓰는 이유입니다. 바퀴 반지름이 0.05 m이고 엔코더가 바퀴가 3π rad(1.5바퀴) 돌았다고 알려 주면, 로봇이 간 거리는 곱셈 한 번으로 0.05 × 3π ≈ 0.471 m입니다. 도를 쓰면 매번 π/180을 곱해야 합니다.

sin과 cos은 원 위를 도는 점의 좌표다

반지름 1인 원(단위원) 위에 점이 하나 있다고 합시다. 오른쪽 수평 방향에서 시작해 반시계 방향으로 각도 θ만큼 돌아간 위치에 있습니다. 이 점의 가로 좌표가 cos θ, 세로 좌표가 sin θ입니다. 삼각함수의 정의는 이게 전부입니다.

이 그림에서 학교 때 배운 공식이 모두 나옵니다. 빗변 r, 각도 θ인 직각삼각형의 밑변은 r cos θ, 높이는 r sin θ입니다. 점은 원 위에 있으니 원점까지 거리가 1이고, 피타고라스 정리로 sin²θ + cos²θ = 1입니다. 로봇이 방향 θ로 속도 v만큼 달리면 x 방향으로 v cos θ, y 방향으로 v sin θ만큼 움직인다는 것도 같은 그림입니다.

재생을 눌러 점을 돌려 보세요. 점의 세로 좌표를 시간에 따라 펼치면 사인파가 되고, 가로 좌표를 펼치면 코사인파가 됩니다. 둘은 모양이 같고 90°(π/2)만큼 어긋나 있을 뿐입니다. 사인파는 원운동의 그림자입니다. 발전기의 회전자가 돌면 교류가, 모터가 돌면 진동이 사인파 모양으로 나오는 이유입니다.

사인파의 세 숫자: 진폭, 주파수, 위상

점이 1초에 f바퀴 돈다면, t초 동안 돈 각도는 2πft 라디안입니다. 여기에 원의 크기와 출발 각도를 붙이면 모든 사인파를 표현할 수 있습니다.

y(t) = A · sin(2πf t + φ) A: 진폭(원의 반지름) · f: 주파수 [Hz] (1초에 몇 바퀴) · φ: 위상 [rad] (출발 각도)

주기 T = 1/f는 한 바퀴 도는 데 걸리는 시간이고, 2πf를 묶어 각주파수 ω[rad/s]라고 부르기도 합니다. 위상 φ는 2장의 "그래프 옮기기"입니다. sin(2πf(t − t0))로 쓰면 신호가 t0만큼 늦게 도착한 것이고, 이때 위상은 φ = −2πf t0입니다. 시간 지연이 곧 위상 지연입니다.

각도를 되찾기: atan2와 각도 정규화

반대 문제도 자주 나옵니다. 목표 지점까지 가로로 Δx, 세로로 Δy 떨어져 있을 때 방향 각도는? tan θ = Δy/Δx이니 θ = atan(Δy/Δx)라고 하고 싶지만, 이 식에는 두 가지 문제가 있습니다.

  • (1, 1)과 (−1, −1)은 Δy/Δx가 둘 다 1이라 같은 각도(45°)가 나옵니다. 실제로는 정반대 방향(45°와 −135°)입니다.
  • Δx = 0이면 0으로 나누게 됩니다.

그래서 atan2(Δy, Δx)를 씁니다. 두 값을 따로 받아 부호를 보고 사분면을 판단하므로 −π부터 +π까지 올바른 각도를 돌려줍니다. 인자 순서가 y, x인 것에 주의하세요.

또 하나, 각도의 차이를 구할 때는 반드시 정규화해야 합니다. 로봇이 350°를 보고 있고 목표가 10°라면 오차는 10 − 350 = −340°가 아니라 +20°입니다. 왼쪽으로 20°만 돌면 됩니다. 차이를 −180°~+180° 범위로 감싸 주는 함수가 필요합니다.

angles.py · 실행 검증됨
import math

# Wheel odometry: arc length s = r * theta (theta in radians)
r = 0.05                       # wheel radius [m]
theta = 3 * math.pi            # 1.5 turns
print(f"distance = {r * theta:.3f} m")

# atan loses the quadrant, atan2 keeps it
for dx, dy in [(1, 1), (-1, -1), (0, 2)]:
    a1 = math.degrees(math.atan(dy / dx)) if dx != 0 else float("nan")
    a2 = math.degrees(math.atan2(dy, dx))
    print(f"({dx:+d},{dy:+d})  atan: {a1:7.1f} deg   atan2: {a2:7.1f} deg")

def wrap_pi(a):
    """Wrap an angle in radians to (-pi, pi]."""
    return math.atan2(math.sin(a), math.cos(a))

heading, target = math.radians(350), math.radians(10)
print(f"naive error : {math.degrees(target - heading):.0f} deg")
print(f"wrapped     : {math.degrees(wrap_pi(target - heading)):.0f} deg")

  • 사인파 = 진폭 · 주파수 · 위상. 방향 계산은 atan2, 각도 차이는 항상 정규화.

미분: 순간의 기울기

이 장을 마치면: 미분을 "아주 짧은 구간에서 잰 기울기"로 설명할 수 있고, 위치·속도·가속도의 관계를 미분으로 읽으며, 기본 미분 규칙 몇 개로 최댓값 문제를 풀고, 센서 데이터를 수치 미분할 때 잡음이 커지는 이유와 대처법을 알게 됩니다.

평균 속도에서 순간 속도로

2장에서 직선의 기울기는 Δy/Δx라고 했습니다. 직선은 어디서 재도 기울기가 같습니다. 그런데 곡선은 위치마다 기울기가 다릅니다. 차가 출발해서 가속할 때, "지금 이 순간의 속도"는 얼마일까요?

위치를 x(t)라고 하면 1초 동안의 평균 속도는 (x(t+1) − x(t)) / 1입니다. 그래프에서는 곡선 위 두 점을 잇는 직선(할선)의 기울기입니다. 이제 간격을 0.1초, 0.01초, 0.001초로 줄여 가면, 두 점이 거의 붙으면서 할선이 곡선에 살짝 닿는 직선(접선)에 다가갑니다. 간격을 한없이 줄였을 때 기울기가 다가가는 값, 그것이 미분입니다.

f ′(x) =  limh→0 f(x + h) − f(x)h 다른 표기: dfdx, dydx. 여기서 d는 "아주아주 작은 Δ"라는 뜻

소리 내어 읽기: "f 프라임 x는, h를 0으로 보낼 때 'f(x+h) 빼기 f(x), 나누기 h'가 다가가는 값이다." lim(극한, limit)은 "그 값에 다가간다"는 뜻입니다. h를 정말 0으로 만들면 0/0이 되니까, 0에 "다가가게만" 하는 것입니다.

컴퓨터에서는 lim을 계산할 수 없으니 h를 충분히 작은 값으로 두고 그냥 나눕니다. 그것이 수치 미분이고, 펌웨어가 늘 하는 (x[k] - x[k-1]) / dt입니다.

여기에 규칙 두 개만 더하면 됩니다. 첫째, 선형성: 더한 것의 미분은 미분한 것의 합이고, 상수배는 그대로 밖으로 나옵니다. (3x2 + sin x)′ = 6x + cos x. 둘째, 연쇄 법칙: 안쪽에 함수가 들어 있으면 안쪽의 미분을 곱합니다. 공학에서 가장 흔한 예는 사인파입니다.

ddt sin(ωt) = ω · cos(ωt) 안쪽 ωt가 ω배 빨리 변하니까, 바깥도 ω배 빨리 변한다

이 식은 실용적인 사실 하나를 알려 줍니다. 진폭이 같아도 주파수가 높은 신호일수록 미분값(변화 속도)이 주파수에 비례해 커집니다. 그래서 미분은 고주파를 키우는 연산, 즉 잡음을 키우는 연산입니다. 이 장의 마지막 절에서 다시 만납니다.

위치 → 속도 → 가속도, 그리고 최댓값 찾기

미분은 "변화율"이므로 물리량 사이의 사다리를 만듭니다. 위치 x(t)를 미분하면 속도 v = dx/dt, 속도를 미분하면 가속도 a = dv/dt입니다. 두 번 미분한 것을 2계 미분이라 하고 f ″로 씁니다. 2계 미분은 기울기가 변하는 정도, 즉 곡선이 얼마나 휘었는가입니다.

미분의 가장 강력한 쓰임은 최댓값과 최솟값 찾기입니다. 매끄러운 곡선이 꼭대기나 바닥에 닿는 순간에는 접선이 수평이므로 기울기가 0입니다. 그래서 "f ′(x) = 0인 x를 찾아라"가 최적화 문제의 출발점이 됩니다.

전자과에서 배운 최대 전력 전달이 좋은 예입니다. 내부 저항 Rs인 전원에 부하 R을 달면 부하가 받는 전력은 P(R) = V2R / (R + Rs)2입니다. R이 너무 작으면 전압이 안 걸리고, 너무 크면 전류가 안 흐릅니다. 그 사이 어딘가에 꼭대기가 있고, dP/dR = 0을 풀면 R = Rs가 나옵니다. 아래 코드는 이것을 손으로 미분하지 않고 수치로 확인합니다.

max_power.py · 실행 검증됨
import numpy as np

V, Rs = 12.0, 4.0                       # source voltage [V], internal resistance [ohm]

def P(R):
    return V**2 * R / (R + Rs) ** 2     # power delivered to the load [W]

R = np.linspace(0.5, 20, 3901)          # sweep the load resistance
dP = np.gradient(P(R), R)               # numerical derivative dP/dR
i = np.where(np.diff(np.sign(dP)) != 0)[0][0]   # where the slope changes sign
print(f"slope crosses zero at R = {R[i]:.2f} ohm (theory: R = Rs = {Rs} ohm)")
print(f"max power = {P(R[i]):.2f} W, at R = 2 ohm: {P(2.0):.2f} W, at R = 8 ohm: {P(8.0):.2f} W")

실전 수치 미분: 잡음이 커지는 이유

엔코더나 위치 센서로 속도를 구할 때 가장 간단한 방법은 연속한 두 샘플의 차를 시간 간격으로 나누는 것입니다.

velocity.c 
/* Called every dt seconds from a timer interrupt */
float velocity_update(float pos_now, float dt)
{
    static float pos_prev = 0.0f;
    float v = (pos_now - pos_prev) / dt;   /* backward difference */
    pos_prev = pos_now;
    return v;
}

그런데 위치 값에 아주 작은 잡음 ε이 섞여 있다면, 차를 dt로 나누는 순간 잡음은 대략 ε/dt 크기가 됩니다. dt를 줄여 "더 정확한 미분"을 하려 할수록 잡음은 커집니다. 벤치 5-A에서는 h를 줄일수록 좋아졌지만, 그건 잡음 없는 수학 곡선이었기 때문입니다. 아래 실험은 잡음이 0.001밖에 안 되는 위치 신호를 여러 간격으로 미분해 오차를 잽니다.

noisy_derivative.py · 실행 검증됨
import numpy as np

rng = np.random.default_rng(1)
sigma = 0.001                                    # position noise (tiny!)
print("   dt     forward-diff error   central-diff error")
for dt in (0.2, 0.05, 0.01, 0.001):
    t = np.arange(0, 10, dt)
    x = np.sin(t) + rng.normal(0, sigma, t.size)  # measured position
    v_true = np.cos(t)
    v_fwd = (x[1:] - x[:-1]) / dt                 # (x[k+1] - x[k]) / dt
    v_cen = (x[2:] - x[:-2]) / (2 * dt)           # (x[k+1] - x[k-1]) / 2dt
    e_fwd = np.sqrt(np.mean((v_fwd - v_true[:-1]) ** 2))
    e_cen = np.sqrt(np.mean((v_cen - v_true[1:-1]) ** 2))
    print(f"{dt:6.3f}   {e_fwd:12.4f}         {e_cen:12.4f}")

  • 중앙 차분: (xk+1 − xk−1)/2dt. 간격이 같아도 근사 오차가 훨씬 작습니다. 대신 한 샘플 늦게 나옵니다.
  • 미분 전후에 저역통과 필터: 고주파 잡음을 먼저 깎아 냅니다(7장의 1차 필터).
  • 미분하지 말고 추정하기: 위치와 속도를 함께 추정하는 필터를 씁니다(13장의 칼만 필터).
임베디드 엔지니어의 눈으로

PID 제어기의 D항이 바로 오차의 미분입니다. D 이득을 올리면 모터가 "지글거리는" 이유가 이 절에 있습니다. 그래서 대부분의 실전 PID 구현은 D항에 저역통과 필터를 달고, 목표값이 계단처럼 바뀔 때 생기는 미분 폭발(derivative kick)을 피하려 오차 대신 측정값을 미분합니다.

흔한 함정
  • "샘플링을 빠르게 하면 속도가 더 정확해진다": 잡음이 있으면 반대입니다. 엔코더 분해능이 낮으면 짧은 dt에서 차가 0 아니면 1카운트라 속도가 계단처럼 튑니다.
  • 불규칙한 dt: 인터럽트 지터로 실제 간격이 흔들리면, 고정 상수 dt로 나눈 미분값도 흔들립니다. 타임스탬프로 실제 간격을 재서 나누세요.
핵심 정리
  • 미분 = 간격을 한없이 줄였을 때의 기울기 = 순간 변화율. 코드로는 차분 ÷ 간격.
  • xn → nxn−1, sin → cos, ex → ex, 안쪽이 있으면 안쪽의 미분을 곱한다.
  • 꼭대기와 바닥에서는 기울기가 0. 미분은 고주파와 잡음을 키운다.

미분은 "얼마나 빨리 변하나"였습니다. 다음 장에서는 반대 질문, "지금까지 얼마나 쌓였나"를 다룹니다. 속도에서 이동 거리를, 전류에서 배터리 사용량을 구하는 적분입니다. 그리고 미분과 적분이 서로를 되돌리는 연산이라는 것을 보게 됩니다.

적분: 차곡차곡 쌓기

이 장을 마치면: 적분을 "얇은 조각을 모두 더한 것"으로 설명할 수 있고, 속도에서 거리를, 전류에서 배터리 사용량(mAh)을 수치 적분으로 구하며, 미분과 적분이 서로 되돌리는 연산이라는 것과 적분할 때 오차가 시간에 따라 쌓이는(드리프트) 이유를 설명할 수 있습니다.

넓이 = 쌓인 양

시속 60 km로 2시간 달리면 120 km를 갑니다. 속도 × 시간입니다. 이것을 그래프로 그리면, 가로축이 시간이고 세로축이 속도인 그래프에서 높이 60, 폭 2인 직사각형의 넓이가 120입니다. "그래프 아래 넓이 = 쌓인 양"이라는 것이 적분의 핵심 그림입니다.

속도가 계속 변한다면? 시간을 아주 얇은 조각으로 자릅니다. 각 조각 안에서는 속도가 거의 일정하니 직사각형으로 칠 수 있고, 조각마다 속도 × 짧은 시간을 구해 전부 더하면 됩니다. 조각을 한없이 얇게 하면 정확한 넓이가 되고, 그것이 적분입니다.

b∫a f(x) dx  ≈  N−1Σi=0 f(xi) · Δx ∫는 길게 늘인 S(Sum), dx는 "아주 얇은 폭". 왼쪽은 오른쪽에서 Δx → 0으로 보낸 것

소리 내어 읽기: "a부터 b까지 f(x)dx를 적분한다" = "a에서 b까지 구간을 얇게 잘라, 각 조각의 높이 f(x) 곱하기 폭 dx를 전부 더한다." 1장에서 Σ가 for 루프였으니, 적분은 아주 촘촘한 for 루프입니다.

적분은 누산기다

펌웨어에서 적분은 한 줄입니다. 일정한 주기 dt마다 현재 값에 dt를 곱해 누산기에 더합니다.

coulomb_counter.c 
/* Coulomb counting: integrate battery current to get the charge used */
static float used_mAh = 0.0f;

void battery_tick(float current_mA, float dt_s)   /* called every dt_s seconds */
{
    used_mAh += current_mA * dt_s / 3600.0f;      /* mA * s -> mAh */
}

배터리 잔량계(fuel gauge)가 하는 일이 정확히 이것입니다. 전하량 Q = ∫ I dt, 즉 전류 그래프 아래 넓이가 사용한 전하입니다. 2 A를 30분 동안 흘리면 넓이는 2 A × 0.5 h = 1 Ah = 1000 mAh입니다. 아래 예제는 로봇이 대기, 주행, 기동 순간의 큰 전류를 오가는 프로파일을 적분하면서, 샘플링 주기가 결과를 얼마나 바꾸는지 봅니다.

coulomb_counting.py · 실행 검증됨
import numpy as np

def current(t):
    """Robot battery current [A] over a 10-minute mission."""
    I = np.full_like(t, 0.3)                     # idle
    I[(t >= 60) & (t < 300)] = 2.0               # driving
    I[(t >= 60) & (t < 63)] = 6.0                # 3-second start-up surge
    ramp = (t >= 300) & (t < 330)                # gentle stop: 2.0 A -> 0.3 A
    I[ramp] = 2.0 - (t[ramp] - 300) / 30 * 1.7
    I[(t >= 400) & (t < 500)] = 1.2              # slow patrol
    return I

# Reference: integrate a very finely sampled profile (trapezoid rule)
tf = np.arange(0, 600.001, 0.001)
ref = np.trapezoid(current(tf), tf) / 3.6        # A*s / 3.6 = mAh
print(f"reference          : {ref:6.1f} mAh")

# Firmware accumulator: used += I * dt at a fixed sampling period
for dt in (0.1, 1.0, 5.0):
    t = np.arange(0, 600, dt)
    used = np.sum(current(t) * dt) / 3.6
    print(f"sampled every {dt:3.1f} s: {used:6.1f} mAh  (error {100 * (used - ref) / ref:+.1f} %)")

sampled every 5.0 s:  202.2 mAh  (error +1.7 %)

0.1초 주기는 기준값과 거의 같지만, 5초 주기로 재면 3초짜리 기동 전류를 한 번 찍고 그 값이 5초 내내 흘렀다고 셉니다. 조각의 폭이 현상보다 넓으면 넓이를 잘못 셉니다. 짧은 스파이크가 있는 신호일수록 촘촘히 재거나, 하드웨어 적분기가 있는 전용 잔량계 칩을 씁니다.

미분과 적분은 서로 되돌린다

위치를 미분하면 속도이고, 속도를 적분하면 위치(이동 거리)입니다. 두 연산은 서로를 되돌립니다. 이것이 미적분학의 기본 정리이고, 그림으로 보면 당연합니다. 넓이가 쌓여 가는 속도는 지금 이 순간 막대의 높이와 같으니까요. 높이가 큰 곳을 지날 때는 넓이가 빨리 쌓이고, 높이가 0인 곳에서는 넓이가 멈춥니다.

그래서 5장의 미분 표를 거꾸로 읽으면 적분 표가 됩니다. cos x를 적분하면 sin x, xn을 적분하면 xn+1/(n+1)입니다. 단 하나 주의할 점이 있습니다. 미분하면 상수는 사라지므로, 적분으로 되돌릴 때 원래 상수가 얼마였는지는 알 수 없습니다. 이것이 "적분 상수 C"이고, 공학적으로는 초깃값입니다. 속도를 아무리 정확히 적분해도 출발 위치를 모르면 현재 위치를 알 수 없습니다.

적분의 함정: 드리프트

적분은 잡음에는 강합니다. 위아래로 흔들리는 잡음은 더하다 보면 서로 상쇄되기 때문입니다(미분과 정반대). 대신 적분에는 치명적인 약점이 있습니다. 작은 치우침(바이어스)이 끝없이 쌓입니다. 자이로가 정지 상태에서도 0.01 °/s를 읽는다면, 이 값을 적분한 각도는 1시간 뒤 36°가 틀어져 있습니다. 가속도계로 위치를 구하려면 두 번 적분해야 하는데, 이 경우 바이어스 오차는 시간의 제곱으로 커집니다.

integration_drift.py · 실행 검증됨
import numpy as np

dt = 0.01
t = np.arange(0, 60 + dt, dt)          # one minute
rng = np.random.default_rng(7)

# Gyro at rest: true rate 0, measured = bias + noise
bias = 0.01                                        # [deg/s]
for T in (60, 600):
    tt = np.arange(0, T, dt)
    n = rng.normal(0, 0.5, tt.size)
    noise_part = np.sum(n) * dt                    # integrated noise only
    print(f"gyro after {T:3d} s: noise part {noise_part:+6.2f} deg, bias part {bias * T:+5.2f} deg")

# Accelerometer at rest with a tiny bias: integrate twice for position
acc = 0.01 + rng.normal(0, 0.05, t.size)           # [m/s^2]
vel = np.cumsum(acc) * dt
pos = np.cumsum(vel) * dt
for T in (1, 10, 60):
    k = int(T / dt)
    print(f"accel: position error after {T:2d} s = {pos[k]:8.3f} m  (0.5*b*t^2 = {0.5 * 0.01 * T**2:.3f})")

자이로의 잡음(0.5 °/s)은 바이어스(0.01 °/s)보다 50배나 크지만, 적분하면 +와 −가 상쇄되어 시간의 제곱근(√t)으로만 자랍니다. 바이어스는 상쇄될 상대가 없어 시간에 정비례(t)로 자랍니다. 그래서 시간이 길어질수록 결국 바이어스가 이깁니다. 가속도계 쪽은 0.01 m/s²라는 미미한 바이어스가 1분 만에 18 m 오차가 됩니다. 관성 센서만으로 위치를 오래 추정할 수 없는 이유이고, 13장에서 다른 센서와 섞는 이유입니다.

임베디드 엔지니어의 눈으로

PID의 I항이 오차의 적분입니다. 작은 정상상태 오차도 계속 쌓아 결국 없애 주지만, 모터가 포화되어 있는 동안에도 계속 쌓이면 나중에 크게 오버슈트합니다. 이것이 적분기 와인드업(windup)이고, 그래서 I항 누산기에는 상한을 둡니다. 고정소수점 누산기라면 오버플로도 같은 이유로 조심해야 합니다.

흔한 함정
  • 단위 환산 누락: mA × s를 그냥 더하면 mA·s(밀리쿨롬)입니다. mAh로 보려면 3600으로 나눕니다.
  • 초깃값 잊기: 적분은 변화량만 줍니다. 누산기 초기화(부팅 시 잔량, 출발 위치)가 틀리면 결과 전체가 그만큼 틀립니다.
  • 바이어스 보정 없이 적분: 정지 상태에서 센서 평균을 재서 바이어스를 빼고 적분하세요. 그래도 남는 드리프트는 다른 센서로 잡아야 합니다.
핵심 정리
  • 적분 = 그래프 아래 넓이 = 얇은 조각의 합 = 누산기 acc += x * dt.
  • 미분과 적분은 서로 되돌린다. 적분으로 되돌릴 때는 초깃값이 필요하다.
  • 적분은 잡음은 상쇄하지만 바이어스는 쌓는다. 두 번 적분하면 시간의 제곱으로 쌓인다.

지금까지는 변화율이 이미 주어져 있었습니다. 그런데 현실의 많은 시스템은 "변화율이 현재 상태에 달려 있다"는 규칙으로 움직입니다. 커패시터는 충전될수록 천천히 충전되고, 뜨거운 모터는 식을수록 천천히 식습니다. 다음 장에서 이런 규칙을 미분방정식으로 쓰고, 그것을 펌웨어의 루프 한 줄로 풀어 봅니다.

미분방정식과 시뮬레이션

이 장을 마치면: "변화율이 현재 상태에 달려 있다"는 미분방정식을 읽을 수 있고, 1차 시스템의 시정수 τ와 63%·5τ 규칙을 쓰며, 오일러 방법으로 미분방정식을 루프 코드로 바꾸고 시간 간격이 너무 크면 왜 발산하는지 설명하며, 2차 시스템의 감쇠비가 오버슈트를 정한다는 것을 압니다.

변화율이 상태에 달려 있을 때

저항 R을 거쳐 커패시터 C를 전압 Vin으로 충전한다고 합시다. 처음에는 전압 차가 커서 전류가 많이 흐르고 빠르게 충전됩니다. 커패시터 전압 V가 Vin에 가까워지면 차이가 작아져 전류가 줄고, 충전이 느려집니다. 이 이야기를 식으로 쓰면 이렇습니다.

dVdt = Vin − Vτ,   τ = RC "전압이 변하는 속도는 목표와의 차이에 비례한다"

이렇게 미지의 함수와 그 미분이 함께 들어 있는 식을 미분방정식이라고 합니다. 보통 방정식의 답은 숫자(x = 3)이지만, 미분방정식의 답은 함수(V(t) = …)입니다. "다음 순간이 어떻게 될지를 지금 상태로 정하는 규칙"이라고 생각하면 됩니다. 프로그래머에게 익숙한 말로는 상태 갱신 규칙입니다.

같은 모양의 식이 곳곳에 있습니다. 뜨거운 모터가 주변 온도로 식는 속도(뉴턴의 냉각 법칙), 탱크에서 물이 빠지는 속도, 그리고 디지털 저역통과 필터가 입력을 따라가는 속도가 모두 "목표와의 차이에 비례해 다가간다"입니다.

e와 시정수 τ

위 미분방정식의 답(처음에 V = 0)은 다음과 같습니다.

V(t) = Vin · (1 − e−t/τ) e ≈ 2.71828, 자연로그의 밑

왜 하필 e일까요? 5장 표에서 ex는 미분해도 자기 자신인 유일한 함수라고 했습니다. "변화율이 현재 값에 비례한다"는 규칙을 만족하는 함수가 바로 지수 함수이고, 그 비례 상수가 1이 되게 하는 밑이 e입니다. 그래서 자연의 성장과 감쇠를 쓰면 저절로 e가 나옵니다.

τ(타우)는 시정수(time constant)로, 단위는 초입니다. 10 kΩ과 10 μF이면 τ = 104 × 10−5 = 0.1 s입니다. 아래 표만 기억하면 대부분의 1차 시스템 문제를 암산할 수 있습니다.

오일러 방법: 미분방정식은 루프가 된다

대부분의 미분방정식은 위처럼 깔끔한 답이 없습니다. 그래도 걱정할 필요가 없습니다. 컴퓨터로 한 걸음씩 밟아 가면 됩니다. 아주 짧은 시간 dt 동안은 변화율이 거의 일정하니, "지금 값 + 변화율 × dt"로 다음 값을 구합니다. 이것이 오일러(Euler) 방법입니다.

Vk+1 = Vk + dt · Vin − Vkτ 미분방정식의 dV/dt를 (Vk+1 − Vk)/dt로 바꾸고 정리한 것

이 식을 α = dt/τ로 놓고 코드로 쓰면 놀랍게도 익숙한 모양이 나옵니다.

lowpass.c 
/* One step of the RC equation = the classic exponential moving average */
float lowpass_step(float y, float x, float alpha)   /* alpha = dt / tau */
{
    return y + alpha * (x - y);    /* move a fraction alpha toward the input */
}

센서 값을 부드럽게 할 때 쓰는 y += alpha * (x - y), 즉 지수 이동평균(EMA) 필터는 RC 저역통과 회로의 미분방정식을 오일러 방법으로 푼 것과 정확히 같은 식입니다. α를 고르는 것은 시정수를 고르는 것이고, τ = dt/α입니다. 100 Hz로 갱신하면서 α = 0.1이면 τ = 0.1 s입니다.

간격을 키워 보세요. α가 1보다 작으면 계산값이 모자란 쪽에서 다가가고, 1을 넘으면 목표를 지나쳤다 돌아오기를 반복하며, 2를 넘으면 진동이 점점 커져 발산합니다. 이유는 간단합니다. 목표와의 오차가 한 걸음마다 (1 − α)배가 되는데, α > 2이면 |1 − α| > 1이라 오차가 매번 커집니다. 실제 회로는 절대 발산하지 않으니, 이건 순전히 계산 방법이 만든 가짜 현상입니다. 시뮬레이션이나 제어 루프의 주기를 정할 때 간격은 시스템의 가장 빠른 시정수보다 충분히 짧게(보통 1/10 이하) 잡아야 하는 이유입니다.

euler_rc.py · 실행 검증됨
import numpy as np

tau, Vin, T_end = 1.0, 1.0, 5.0
for ratio in (0.1, 0.5, 1.5, 2.5):
    dt = ratio * tau
    n = int(round(T_end / dt))
    V, err = 0.0, 0.0
    for k in range(n):
        V = V + dt * (Vin - V) / tau                  # Euler step
        exact = Vin * (1 - np.exp(-(k + 1) * dt / tau))
        err = max(err, abs(V - exact))
    print(f"dt/tau = {ratio:3.1f}: error factor per step {1 - ratio:+.1f}, "
          f"max error over {n:2d} steps = {err:.3g}")

# The 63 % / 5 tau rule
for m in (1, 2, 3, 5):
    print(f"t = {m} tau -> {100 * (1 - np.exp(-m)):.1f} % of the way")

2차 시스템 맛보기: 스프링, 댐퍼, 그리고 오버슈트

로봇 팔이나 서스펜션처럼 질량이 있는 시스템은 상태가 둘입니다. 위치와 속도. 스프링은 위치에 비례해 되돌리는 힘을, 댐퍼는 속도에 비례해 저항하는 힘을 냅니다. 뉴턴의 법칙 F = ma로 쓰면 가속도(2계 미분)가 들어간 2차 미분방정식이 됩니다.

m · x ″ = −k · x − c · x ′ 질량 × 가속도 = 스프링 힘 + 댐퍼 힘

풀 때는 상태를 둘로 나눠 오일러 방법을 그대로 씁니다. 매 걸음 가속도를 구해 속도를 갱신하고, 그 속도로 위치를 갱신합니다. 이 시스템의 성격은 감쇠비 ζ(제타) 하나로 요약됩니다. ζ가 작으면 출렁이며(부족 감쇠), 1이면 출렁임 없이 가장 빨리 도착하고(임계 감쇠), 1보다 크면 굼뜨게 다가갑니다(과감쇠). 제어 루프를 튜닝한다는 것은 결국 닫힌 루프의 ζ와 응답 속도를 고르는 일입니다.

spring_damper.py · 실행 검증됨
import numpy as np

wn = 2 * np.pi * 1.0          # natural frequency: 1 Hz
dt = 1e-4
t = np.arange(0, 6, dt)
print(" zeta   overshoot   theory   rise(10-90%)   settle(2%)")
for zeta in (0.1, 0.4, 0.7, 1.0, 2.0):
    x, v = 0.0, 0.0           # step response toward x = 1
    xs = np.empty(t.size)
    for i in range(t.size):
        a = wn**2 * (1.0 - x) - 2 * zeta * wn * v   # acceleration from the ODE
        v += a * dt                                  # update velocity first
        x += v * dt                                  # then position (semi-implicit Euler)
        xs[i] = x
    over = max(0.0, xs.max() - 1.0) * 100
    theory = 100 * np.exp(-zeta * np.pi / np.sqrt(1 - zeta**2)) if zeta < 1 else 0.0
    outside = np.where(np.abs(xs - 1.0) > 0.02)[0]
    settle = t[outside[-1]] if outside.size else 0.0
    settle_s = f"{settle:5.2f} s" if settle < t[-1] - 0.01 else "  > 6 s"
    rise = t[np.argmax(xs >= 0.9)] - t[np.argmax(xs >= 0.1)]
    print(f" {zeta:3.1f}   {over:6.1f} %   {theory:6.1f} %     {rise:5.2f} s      {settle_s}")

흔한 함정
  • 너무 긴 루프 주기: dt가 시스템 시정수에 비해 길면 시뮬레이션도, 이산 제어기도 진동하거나 발산합니다. 실제 하드웨어 문제가 아닌데 코드가 불안정해 보인다면 먼저 dt를 의심하세요.
  • EMA 계수를 주기와 따로 바꾸기: 루프 주기를 바꾸면서 α를 그대로 두면 시정수가 바뀝니다. α = dt/τ로 계산해 두세요.
핵심 정리
  • 미분방정식 = 지금 상태로 변화율을 정하는 규칙 = 상태 갱신 규칙.
  • 1차 시스템: 1τ에 63%, 5τ에 99%. EMA 필터 y += α(x − y)는 RC 회로와 같은 식, τ = dt/α.
  • 오일러 방법: 다음 값 = 지금 값 + 변화율 × dt. dt가 너무 크면 가짜 진동과 발산이 생긴다.

벡터: 방향이 있는 수

이 장을 마치면: 벡터를 숫자 묶음이자 화살표로 보고 덧셈·뺄셈·스칼라배·크기·정규화를 계산할 수 있고, 내적으로 두 방향 사이의 각도와 한 벡터를 다른 방향으로 투영한 길이를 구하며, 2D 외적의 부호로 왼쪽·오른쪽을 판단할 수 있습니다.

숫자 묶음이자 화살표

온도나 전압은 숫자 하나로 충분합니다. 이런 양을 스칼라라고 합니다. 그런데 로봇의 위치, 속도, 바람, 힘은 "얼마나"와 "어느 쪽으로"를 함께 말해야 합니다. 이런 양을 벡터라고 합니다.

벡터는 두 가지 얼굴을 갖습니다. 하나는 숫자 묶음입니다. 평면 위라면 (3, 4)처럼 두 숫자, 공간이라면 (x, y, z) 세 숫자. 코드로는 struct { float x, y; }나 길이 2짜리 배열입니다. 다른 하나는 화살표입니다. 원점에서 가로로 3, 세로로 4만큼 간 곳을 가리키는 화살표. 계산은 숫자로 하고, 이해는 화살표로 합니다.

화살표의 길이, 즉 벡터의 크기(norm)는 4장의 피타고라스 정리로 구합니다.

|v| = √vx2 + vy2   예: |(3, 4)| = √9 + 16 = 5 3차원이면 z2을 더하면 된다. 굵은 글씨 v는 "이건 벡터"라는 표시

더하기, 빼기, 늘리기

벡터 계산은 성분끼리 하면 됩니다. 그림으로 보면 각각 뜻이 있습니다.

  • 덧셈 (ax + bx, ay + by): 화살표를 이어 붙인 결과. 이동을 연달아 하면 위치 벡터가 더해지고, 힘 여러 개가 작용하면 힘 벡터가 더해집니다.
  • 뺄셈 B − A: A에서 B로 가는 화살표. 로봇에서 목표까지의 방향과 거리가 이 한 번의 뺄셈으로 나옵니다.
  • 스칼라배 k · v: 방향은 그대로, 길이만 k배. k가 음수면 반대 방향.
  • 정규화 v / |v|: 길이를 1로 만든 단위 벡터. "얼마나"를 지우고 "어느 쪽"만 남깁니다. 로봇의 방향 ψ는 단위 벡터 (cos ψ, sin ψ)로 나타낼 수 있습니다(4장).

내적: 두 방향이 얼마나 같은가

벡터 둘을 곱하는 방법 중 공학에서 가장 많이 쓰는 것이 내적(dot product)입니다. 계산은 성분끼리 곱해 더하는 것뿐인데, 그 결과에 기하학적인 뜻이 숨어 있습니다.

a · b = axbx + ayby = |a| |b| cos θ θ: 두 화살표 사이의 각도. 왼쪽은 계산법, 오른쪽은 뜻

cos θ는 두 방향이 같으면 1, 수직이면 0, 반대면 −1입니다. 그래서 내적의 부호만 봐도 많은 것을 알 수 있습니다. 양수면 대체로 같은 쪽, 0이면 직각, 음수면 대체로 반대쪽입니다. 또 b가 단위 벡터라면 a · b는 "a가 b 방향으로 얼마나 뻗어 있는가", 즉 투영(그림자)의 길이입니다.

두 방향을 직각으로 맞추면 내적이 정확히 0이 되고 그림자가 사라집니다. 성분으로 계산한 값과 |a||b|cos θ로 계산한 값이 언제나 같다는 것도 확인해 보세요. 1장의 FIR 필터 Σhkxn−k도 사실 계수 벡터와 입력 벡터의 내적입니다. 필터는 "입력이 계수 모양과 얼마나 닮았나"를 재는 셈이고, 12장의 상관(correlation)도 같은 생각입니다.

실전: 목표가 앞에 있나, 왼쪽에 있나

로봇이 위치 P에서 방향 ψ를 보고 있고, 목표가 G에 있습니다. 방향 단위 벡터를 h = (cos ψ, sin ψ), 목표를 향한 벡터를 g = G − P라고 하면 질문 두 개가 계산 두 번으로 풀립니다.

  • 앞인가 뒤인가? h · g > 0이면 앞쪽(±90° 이내).
  • 왼쪽인가 오른쪽인가? 2D 외적 hxgy − hygx가 양수면 왼쪽(반시계 방향), 음수면 오른쪽. 크기는 |h||g| sin θ입니다.

둘을 합치면 각도도 바로 나옵니다. θ = atan2(외적, 내적). 4장의 atan2에 sin 성분과 cos 성분을 넣은 것입니다. 이렇게 구한 각도는 자동으로 −180°~+180° 범위라 따로 정규화할 필요도 없습니다.

vectors.py · 실행 검증됨
import numpy as np

P = np.array([1.0, 1.0])                 # robot position [m]
psi = np.radians(30)                     # robot heading
h = np.array([np.cos(psi), np.sin(psi)]) # unit heading vector

for G in ([4.0, 2.0], [0.0, 3.0], [-2.0, 0.0]):
    g = np.array(G) - P                  # vector from robot to goal
    dist = np.linalg.norm(g)
    dot = h @ g                          # h . g
    cross = h[0] * g[1] - h[1] * g[0]    # 2D cross product (z component)
    ang = np.degrees(np.arctan2(cross, dot))
    side = "left" if cross > 0 else "right"
    where = "ahead" if dot > 0 else "behind"
    print(f"goal {G}: dist {dist:4.2f} m, {where:6s}, {side:5s}, turn {ang:+6.1f} deg")

# acos needs clamping: rounding can push the cosine slightly above 1
u = np.array([0.9, 0.6]); v = u * 0.1          # same direction, angle is 0
c = (u @ v) / (np.linalg.norm(u) * np.linalg.norm(v))
print(f"cos = {c:.17g}")
with np.errstate(invalid="ignore"):
    print("acos(cos)          =", np.degrees(np.arccos(c)))
print("acos(clip(cos))    =", np.degrees(np.arccos(np.clip(c, -1.0, 1.0))))

벡터 연산은 SIMD와 궁합이 좋습니다. 성분끼리 독립적으로 곱하고 더하므로 NEON 같은 명령으로 여러 성분을 한 번에 처리할 수 있고, 내적은 곱셈-누산(MAC)의 연속입니다. GPU와 DSP가 잘하는 일이 바로 이것입니다.

흔한 함정
  • 0 벡터 정규화: 로봇이 이미 목표 위에 있으면 |g| = 0이라 0으로 나눕니다. 길이가 아주 작으면 정규화하지 않도록 분기하세요.
  • acos의 NaN: 내적 ÷ 크기의 곱이 반올림 오차로 1.0000001이 되면 acos가 NaN을 냅니다. −1~1로 잘라(clamp) 쓰거나, 처음부터 atan2(외적, 내적)를 쓰세요.
  • 좌표계 손잡이: 화면 좌표처럼 y가 아래로 커지는 좌표계에서는 외적의 왼쪽/오른쪽 판정이 뒤집힙니다. ROS의 REP 103처럼 좌표계 규약을 먼저 확인하세요.
핵심 정리
  • 벡터 = 숫자 묶음 = 화살표. 크기는 피타고라스, B − A는 A에서 B로 가는 화살표.
  • 내적 = 성분 곱의 합 = |a||b|cos θ. 부호로 앞/뒤, 단위 벡터와의 내적은 투영 길이.
  • 2D 외적의 부호로 왼쪽/오른쪽, 각도는 atan2(외적, 내적).

내적은 벡터 둘에서 숫자 하나를 만들었습니다. 그렇다면 내적을 여러 개 한꺼번에 해서 벡터에서 새 벡터를 만들면? 그것이 다음 장의 행렬입니다. 행렬은 공간 전체를 돌리고 늘리는 변환 기계이고, 로봇 좌표계 변환의 언어입니다.

행렬: 변환 기계

이 장을 마치면: 행렬 × 벡터를 "내적 여러 개"이자 "공간 변환"으로 읽을 수 있고, 회전 행렬과 동차 좌표로 로봇 좌표계와 월드 좌표계 사이를 변환하며, 변환을 곱으로 이어 붙일 때 순서가 중요하다는 것과 연립방정식을 행렬로 풀고 행렬식이 0일 때 무슨 일이 일어나는지 설명할 수 있습니다.

행렬은 표, 행렬 × 벡터는 내적 여러 개

행렬은 숫자를 직사각형으로 늘어놓은 표입니다. 2행 2열이면 2×2 행렬. 행렬에 벡터를 곱하는 규칙은 하나입니다. 각 행과 벡터의 내적(8장)을 구해 위에서부터 차례로 적습니다.

abcd xy = a x + b yc x + d y 1행 (a, b)와 (x, y)의 내적이 결과의 첫째 줄, 2행과의 내적이 둘째 줄

코드로는 이중 루프입니다. 바깥 루프가 행, 안쪽 루프가 내적입니다.

matvec.py · 실행 검증됨
A = [[2.0, 1.0],
     [0.5, 3.0]]
v = [1.0, 2.0]

out = []
for row in A:                    # one dot product per row
    acc = 0.0
    for a_ij, v_j in zip(row, v):
        acc += a_ij * v_j
    out.append(acc)
print("A @ v =", out)

로봇에서 바로 쓰는 예를 봅시다. 차동 구동 로봇은 전진 속도 v와 회전 속도 ω를 명령받아, 바퀴 간격이 L일 때 왼쪽·오른쪽 바퀴 속도를 이렇게 정합니다.

vLvR = 1−L/21+L/2 vω 왼쪽 바퀴는 v − ωL/2, 오른쪽은 v + ωL/2

행렬은 "입력 묶음을 출력 묶음으로 바꾸는 선형 규칙"을 한 덩어리로 적은 것입니다. 입력과 출력이 몇 개든 같은 표기로 쓸 수 있다는 것이 행렬의 힘입니다.

행렬은 공간을 변형하는 기계다

행렬을 이해하는 가장 좋은 그림은 이것입니다. 행렬의 첫째 열은 가로 단위 벡터 (1, 0)이 옮겨 가는 곳, 둘째 열은 세로 단위 벡터 (0, 1)이 옮겨 가는 곳입니다. 실제로 계산해 보면 위 식에 (x, y) = (1, 0)을 넣으면 (a, c), 즉 첫째 열이 나옵니다. 나머지 모든 점은 이 두 화살표를 기준으로 비례해서 따라갑니다. 격자 전체가 평행선을 유지한 채 늘어나고, 기울고, 돕니다.

이 그림을 알면 회전 행렬을 외울 필요가 없습니다. 각도 θ만큼 돌리면 (1, 0)은 (cos θ, sin θ)로, (0, 1)은 (−sin θ, cos θ)로 갑니다(4장의 단위원). 이 둘을 열로 세우면 끝입니다.

프리셋을 하나씩 눌러 보세요. 회전은 모양과 크기를 그대로 두고 돌리기만 하고, 전단은 사각형을 평행사변형으로 기울입니다. 판독값의 행렬식 det = ad − bc는 넓이가 몇 배가 되는지를 알려 줍니다. 회전은 1, 가로 2배는 2입니다. 좌우 뒤집기는 −1, 음수는 "뒤집혔다"는 뜻입니다. "납작하게"를 누르면 행렬식이 0이 되고 평면 전체가 직선 하나로 짓눌립니다. 이 상태에서는 원래 어디에 있던 점인지 되돌릴 방법이 없습니다. 기억해 두세요. 잠시 뒤 연립방정식에서 다시 나옵니다.

변환 이어 붙이기 = 행렬 곱, 그리고 좌표계 변환

변환 B를 한 다음 A를 하면, 결과는 행렬 곱 AB 하나로 표현됩니다. 오른쪽부터 적용된다는 점, 그리고 순서를 바꾸면 결과가 달라진다(AB ≠ BA)는 점이 숫자 곱셈과 다릅니다. "돌리고 나서 옮기기"와 "옮기고 나서 돌리기"는 다른 곳에 도착합니다.

그런데 회전은 행렬 곱으로 되지만 평행이동(옮기기)은 곱셈이 아니라 덧셈입니다. 이를 하나로 합치는 요령이 동차 좌표(homogeneous coordinates)입니다. 2D 점 (x, y)에 1을 붙여 (x, y, 1)로 쓰면, 회전과 이동을 3×3 행렬 하나에 담을 수 있습니다.

xwyw1 = cos ψ−sin ψpxsin ψcos ψpy001 xryr1 로봇 좌표계의 점 (xr, yr) → 월드 좌표계 (xw, yw). 로봇 자세 = 위치 (px, py), 방향 ψ

라이다가 "로봇 기준 앞으로 2 m, 왼쪽으로 0.5 m에 장애물"이라고 알려 주면, 이 행렬을 곱해 지도 위의 장애물 위치를 얻습니다. 카메라 → 로봇 몸체 → 오도메트리 → 지도처럼 좌표계가 여러 단계라면 각 단계의 행렬을 차례로 곱합니다. 반대 방향(지도 → 로봇)은 역행렬입니다.

frames.py · 실행 검증됨
import numpy as np

def pose(px, py, psi_deg):
    """3x3 homogeneous transform: robot frame -> world frame."""
    c, s = np.cos(np.radians(psi_deg)), np.sin(np.radians(psi_deg))
    return np.array([[c, -s, px],
                     [s,  c, py],
                     [0,  0,  1]])

T_world_robot = pose(3.0, 1.0, 90)             # robot at (3, 1), facing +y
p_robot = np.array([2.0, 0.5, 1.0])            # lidar hit: 2 m ahead, 0.5 m left
p_world = T_world_robot @ p_robot
print("obstacle in world :", np.round(p_world[:2], 3))

# Going back: the inverse transform maps world -> robot
p_back = np.linalg.inv(T_world_robot) @ p_world
print("back to robot     :", np.round(p_back[:2], 3))

# Order matters: rotate-then-move vs move-then-rotate
R = pose(0, 0, 90); M = pose(1, 0, 0)
x = np.array([1.0, 0.0, 1.0])
print("M @ R @ x (rotate first):", np.round((M @ R @ x)[:2], 3))
print("R @ M @ x (move first)  :", np.round((R @ M @ x)[:2], 3))

연립방정식과 역행렬

행렬의 또 다른 큰 쓰임은 연립방정식입니다. 전자과의 메시 해석을 떠올려 봅시다. 12 V 전원과 2 Ω, 4 Ω, 6 Ω 저항으로 된 두 고리 회로에서 키르히호프 전압 법칙을 쓰면 다음 두 식이 나옵니다.

6I1 − 4I2 = 12,   −4I1 + 10I2 = 0  ⇔  6−4−410 I1I2 = 120

이렇게 Ax = b로 쓰면 질문은 "행렬 A로 변환해서 b가 되는 원래 벡터 x는?"이 됩니다. 변환을 되돌리면 되니 x = A−1b입니다. 그리고 벤치에서 본 것처럼 행렬식이 0이면 되돌릴 수 없습니다. 연립방정식으로는 식들이 서로 독립이 아니라서(한 식이 다른 식의 배수) 해가 없거나 무수히 많은 경우입니다.

A = np.array([[ 6.0, -4.0],

b = np.array([12.0, 0.0])

print("det(A) =", round(np.linalg.det(A), 6))

print("I1 = %.4f A, I2 = %.4f A" % tuple(I))
print("check A @ I =", A @ I)

복소수: 회전하는 수

이 장을 마치면: 복소수를 평면 위의 점이자 화살표로 보고 극형식(크기와 각도)으로 바꿀 수 있고, 복소수 곱셈이 "크기는 곱하고 각도는 더한다"는 것을 이용하며, 오일러 공식으로 사인파를 회전하는 화살표(페이저)로 다루고, 임피던스로 RC 필터의 이득과 위상을 계산할 수 있습니다.

j는 "옆으로 90도"다

"허수"라는 이름 때문에 복소수는 현실과 동떨어진 상상의 수처럼 느껴집니다. 이름을 잊고 그림으로 봅시다. 보통의 수(실수)는 수직선 위에 있습니다. +1을 곱하면 그대로, −1을 곱하면 원점을 중심으로 180° 뒤집힙니다. 그렇다면 "두 번 하면 180° 뒤집히는" 연산, 즉 90° 회전을 하는 수가 있으면 어떨까요? 그 수를 j라고 부르면 j × j = −1이 됩니다. 수학에서는 i라고 쓰지만, 전기에서는 i가 전류라서 j를 씁니다.

그러면 수가 사는 곳이 직선에서 평면으로 넓어집니다. 가로축은 실수, 세로축은 j의 배수(허수)이고, 복소수 z = a + jb는 이 평면 위의 점 (a, b)입니다. 8장의 2D 벡터와 같은 점인데, 곱셈이라는 연산이 하나 더 붙어 있다는 것이 다릅니다.

곱셈 = 회전 + 확대

복소수도 점이니까 4장처럼 원점에서의 거리와 각도로 나타낼 수 있습니다. 이것을 극형식이라고 합니다.

z = a + jb = r∠θ,   r = |z| = √a2 + b2,   θ = atan2(b, a) 거꾸로: a = r cos θ, b = r sin θ

이렇게 쓰면 복소수 곱셈의 비밀이 드러납니다. 크기는 곱하고, 각도는 더합니다.

(r1∠θ1) × (r2∠θ2) = (r1r2)∠(θ1 + θ2) 예: j = 1∠90°이므로 j를 곱하면 크기 그대로 90° 회전. j² = 1∠180° = −1

9장에서 점을 돌리려면 2×2 회전 행렬이 필요했지만, 복소수로는 1∠θ를 곱하기만 하면 됩니다. 나눗셈은 반대로 크기는 나누고 각도는 뺍니다. 켤레(conjugate) z* = a − jb는 가로축에 대해 뒤집은 점으로, 각도의 부호만 바뀝니다. z × z* = |z|²라서 크기를 구할 때 자주 씁니다.

크기를 정확히 1로 두면 점들이 원 위를 일정한 간격으로 돕니다. 크기를 1보다 조금만 작게 하면 안쪽으로 감기는 나선(사라지는 진동), 조금만 크게 하면 바깥으로 풀리는 나선(커지는 진동)이 됩니다. 7장에서 오일러 방법의 오차가 매 걸음 (1 − α)배가 되어 |1 − α| > 1이면 발산했던 것과 같은 이야기입니다. 디지털 필터와 제어기가 안정하려면 "극점이 단위원 안에 있어야 한다"는 말을 듣게 되는데, 그 단위원이 바로 이 그림의 원입니다.

오일러 공식: 회전하는 화살표로 사인파를 쓴다

크기 1, 각도 θ인 복소수는 cos θ + j sin θ입니다. 이것을 아주 짧게 쓰는 방법이 있습니다.

ejθ = cos θ + j sin θ 오일러 공식. "e의 jθ승"은 "각도 θ를 가리키는 길이 1인 화살표"라고 읽으면 된다

왜 지수 함수가 회전과 같은지는 5장의 미분으로 짐작할 수 있습니다. ejθ를 θ로 미분하면 jejθ, 즉 "변화 방향이 언제나 현재 위치에서 90° 옆"입니다. 원점에서 늘 직각 방향으로 움직이는 점은 원을 그립니다. 그리고 지수 법칙 ejαejβ = ej(α+β)이 "각도는 더한다"는 곱셈 규칙과 정확히 맞아떨어집니다.

이제 θ = ωt로 두면 ejωt는 1초에 f바퀴 도는 화살표이고, 그 실수부(가로 그림자)가 cos(ωt)입니다. 4장에서 "사인파는 원운동의 그림자"라고 했던 것을 수식 하나로 쓴 것입니다. 교류 회로에서는 주파수가 모두 같으니 회전은 잠시 잊고, 출발 화살표 A∠φ만 들고 다닙니다. 이것이 페이저(phasor)입니다. 같은 주파수의 사인파 두 개를 더하는 어려운 삼각함수 계산이 화살표 덧셈 한 번으로 끝납니다.

SDR이나 레이더에서 다루는 IQ 데이터는 복소수 샘플 I + jQ입니다. NumPy는 complex64, C99는 <complex.h>의 float complex로 그대로 다룰 수 있습니다. 신호를 주파수 성분으로 쪼개는 푸리에 변환(FFT)은 "신호와 각 주파수의 회전 화살표 e−jωt의 내적"입니다. 8장의 내적과 이 장의 회전 화살표를 합친 것이고, 더 깊이는 책장의 'RF·FPGA를 위한 신호처리 교본'에서 이어집니다.

흔한 함정
  • 위상을 atan으로 구하기: 복소수의 각도도 반드시 atan2(b, a) 또는 cmath.phase. 4장과 같은 이유입니다.
  • Hz와 rad/s 혼동: ω = 2πf. 임피던스 공식에 Hz를 그대로 넣으면 결과가 2π배 틀립니다.
  • Python의 j: 1j처럼 숫자를 붙여 써야 허수 단위입니다. j만 쓰면 변수 이름으로 해석됩니다.
핵심 정리
  • 복소수 = 평면 위의 점. j를 곱하면 90° 회전.
  • 곱셈: 크기는 곱하고 각도는 더한다. |w| < 1의 거듭제곱은 사라지고, > 1은 폭발한다.
  • ejθ = cos θ + j sin θ. 사인파 = 회전 화살표의 그림자, 임피던스로 교류 회로를 옴의 법칙처럼 푼다.

확률: 얼마나 그럴듯한가

이 장을 마치면: 확률을 "몇 번 중 몇 번"으로 계산하고 "적어도 한 번" 문제를 여사건으로 풀 수 있으며, 독립 사건의 곱셈 규칙으로 직렬·병렬(이중화) 시스템의 신뢰도를 계산하고, 조건부 확률과 베이즈 정리로 "경보가 울렸을 때 진짜 고장일 확률"을 구할 수 있습니다.

확률은 "몇 번 중 몇 번"이다

확률은 0부터 1 사이의 수로, 같은 상황을 아주 많이 반복했을 때 그 일이 일어나는 비율입니다. 패킷 손실률 1%란 패킷 100개 중 대략 1개가 사라진다는 뜻입니다. 이 책에서는 확률을 볼 때마다 "1000번 해 보면 몇 번?"으로 바꿔 생각하겠습니다. 이렇게 하면 헷갈리는 문제 대부분이 단순한 세기 문제가 됩니다.

첫 번째 도구는 여사건입니다. 어떤 일이 일어날 확률이 p이면, 일어나지 않을 확률은 1 − p입니다. 당연해 보이지만 "적어도 한 번"이 들어간 문제를 푸는 열쇠입니다. 패킷 100개를 보낼 때 하나라도 잃을 확률은? "하나라도 잃는" 경우는 너무 많아 세기 어렵지만, 반대인 "하나도 안 잃을" 확률은 쉽습니다.

P(적어도 한 번) = 1 − (1 − p)n = 1 − 0.99100 ≈ 0.634 1% 손실률이라도 100개를 보내면 63% 확률로 하나 이상 잃는다

독립이면 곱한다: 신뢰도 계산

두 일이 서로 영향을 주지 않을 때(독립) 둘 다 일어날 확률은 각각의 확률을 곱한 것입니다. "1000번 중 900번 A가 되고, 그 900번 중 다시 90%에서 B가 되면 810번"이니까요. 위의 0.99100도 패킷마다 독립이라고 보고 곱한 것입니다.

이 규칙으로 시스템 신뢰도를 계산할 수 있습니다. 로봇이 부품 5개 중 하나만 고장 나도 멈춘다면(직렬), 부품 각각이 1년간 고장 나지 않을 확률이 0.99라도 시스템 전체는 0.995 ≈ 0.951입니다. 부품이 많을수록 시스템은 약해집니다. 반대로 같은 부품 두 개를 두고 하나만 살아 있어도 된다면(병렬, 이중화), 시스템이 멈추려면 둘 다 고장 나야 하므로 고장 확률이 0.01 × 0.01 = 0.0001이 됩니다.

구성시스템이 살아 있을 확률예: 부품 신뢰도 0.99
직렬 (모두 살아야 함)R1 × R2 × … = Π Ri5개: 0.951
병렬 (하나만 살면 됨)1 − Π (1 − Ri)2개: 0.9999

"또는"(OR)은 어떨까요? 두 일이 동시에 일어날 수 없을 때만(배반) 확률을 그냥 더합니다. 동시에 일어날 수 있다면 겹치는 부분을 두 번 세게 되므로 빼 줘야 합니다. P(A 또는 B) = P(A) + P(B) − P(A 그리고 B). 확률을 더했는데 1이 넘었다면 이 실수를 한 것입니다.

reliability.py · 실행 검증됨
import numpy as np

p_loss = 0.01
print(f"P(at least one of 100 packets lost) = {1 - (1 - p_loss) ** 100:.3f}")

R = 0.99                                   # one part survives the year
series = R ** 5
parallel = 1 - (1 - R) ** 2
print(f"series of 5   : {series:.4f}")
print(f"parallel pair : {parallel:.4f}")

# Check by simulating 200,000 robots (Monte Carlo)
rng = np.random.default_rng(3)
alive = rng.random((200_000, 5)) < R       # True = part survived
print(f"simulated series of 5   : {alive.all(axis=1).mean():.4f}")
pair = rng.random((200_000, 2)) < R
print(f"simulated parallel pair : {pair.any(axis=1).mean():.4f}")

조건부 확률: "~라는 걸 알았을 때"

"경보가 울렸다는 걸 알았을 때, 진짜 고장일 확률"처럼 어떤 정보를 알고 난 뒤의 확률을 조건부 확률이라고 하고 P(고장 | 경보)로 씁니다. 세로 막대는 "~라는 조건에서"라고 읽습니다. 핵심은 세는 범위가 바뀐다는 것입니다. 전체 1000대 중에서가 아니라, 경보가 울린 로봇들 중에서 세는 것입니다.

구체적인 상황을 봅시다. 로봇 모터의 1%가 실제로 결함이 있습니다. 진단 소프트웨어는 결함이 있는 모터의 95%를 잡아내지만, 정상 모터에도 5%의 확률로 잘못 경보를 냅니다. 경보가 울렸을 때 그 모터가 진짜 결함일 확률은? 많은 사람이 95%라고 답하지만, 1000대로 세어 보면 다릅니다.

경보는 모두 59대(9.5 + 49.5)에서 울리고, 그중 진짜 결함은 9.5대입니다. 경보가 울렸을 때 진짜 결함일 확률은 겨우 16%입니다. 결함 자체가 드물어서(1%), 5%라는 작은 헛경보율이 아주 많은 정상 모터(990대)에 곱해지면 진짜 경보보다 훨씬 많아지기 때문입니다. 이렇게 기본 비율(base rate)을 무시해서 생기는 착각은 아주 흔합니다.

베이즈 정리: 증거를 보고 믿음을 고친다

방금 1000대로 센 계산을 공식으로 쓴 것이 베이즈 정리입니다.

P(결함 | 경보) = P(경보 | 결함) · P(결함)P(경보) = 0.95 × 0.010.95 × 0.01 + 0.05 × 0.99 ≈ 0.161

읽는 법: "증거를 보기 전 믿음(사전 확률 P(결함))에, 그 가설이 맞다면 이 증거가 나올 가능성을 곱하고, 증거가 나올 전체 가능성으로 나눈다." 결과는 증거를 본 뒤의 믿음(사후 확률)입니다.

베이즈 정리의 진짜 쓸모는 믿음을 단계적으로 고쳐 나가는 데 있습니다. 경보가 한 번 울려 16%가 되었다면, 독립적인 두 번째 검사를 할 때는 16%를 사전 확률로 넣습니다. 두 번째도 경보면 확률은 약 78%로 뛰어오릅니다. 13장의 칼만 필터는 이 "예측한 믿음 + 새 측정 → 고친 믿음"을 연속적인 값에 대해 매 순간 반복하는 장치입니다.

임베디드 엔지니어의 눈으로

CI의 불안정한 테스트(flaky test)도 같은 구조입니다. 실제 회귀 버그가 드물면, 1%의 무작위 실패율만으로도 "빨간불" 대부분이 가짜가 됩니다. 팀이 빨간불을 무시하기 시작하는 이유이고, 헛경보를 줄이는 것이 감지율을 올리는 것만큼 중요한 이유입니다.

흔한 함정
  • 독립이 아닌데 곱하기: 이중화한 두 보드가 같은 전원을 쓰면 전원 하나가 둘을 동시에 죽입니다(공통 원인 고장). 이때 0.01 × 0.01 계산은 지나치게 낙관적입니다.
  • P(A|B)와 P(B|A) 혼동: "결함이면 경보가 울릴 확률 95%"와 "경보가 울리면 결함일 확률"은 전혀 다른 숫자입니다.
  • 겹치는 사건을 그냥 더하기: 확률의 합이 1을 넘으면 겹침을 두 번 센 것입니다.
핵심 정리
  • 확률은 1000번 중 몇 번으로 바꿔 센다. "적어도 한 번"은 1 − (모두 실패하지 않을 확률).
  • 독립이면 곱한다: 직렬은 ΠRi, 병렬은 1 − Π(1 − Ri).
  • 베이즈: 사후 ∝ 가능도 × 사전. 드문 사건에서는 기본 비율과 헛경보율이 결과를 지배한다.

확률은 "어떤 일이 일어날지"를 다뤘습니다. 다음 장에서는 이미 측정한 숫자들이 얼마나 흩어져 있는지를 다루는 통계로 넘어갑니다. 센서 잡음의 크기를 하나의 숫자로 요약하는 표준편차, 그리고 여러 번 재서 평균하면 잡음이 얼마나 줄어드는지를 배웁니다.

통계와 잡음

이 장을 마치면: 평균·분산·표준편차를 계산하고 그 뜻을 설명할 수 있고, 정규분포의 68-95-99.7 규칙으로 측정값의 범위를 판단하며, 독립 잡음의 분산이 더해진다는 것과 N개를 평균하면 잡음이 √N배 줄어든다는 것을 쓰고, 최소제곱법으로 잡음 낀 데이터에 직선을 맞출 수 있습니다.

평균과 흩어짐: 분산과 표준편차

정지해 있는 센서를 100번 읽으면 값이 조금씩 다르게 나옵니다. 이 숫자 더미를 요약하는 첫 번째 숫자는 평균 μ(1장의 x)이고, 두 번째 숫자는 "평균에서 얼마나 흩어져 있나"입니다.

흩어짐을 재려면 각 값이 평균에서 벗어난 정도(편차) xi − μ를 봐야 하는데, 그냥 평균 내면 +와 −가 상쇄되어 0이 됩니다. 1장의 RMS와 같은 요령으로 제곱해서 평균내면 됩니다. 이것이 분산이고, 단위를 원래대로 돌리려고 루트를 씌운 것이 표준편차입니다.

σ2 = 1N NΣi=1 (xi − μ)2,   σ = √σ2 분산 σ²: 편차 제곱의 평균 · 표준편차 σ: 원래 단위로 된 "전형적인 흔들림 크기"

평균이 0인 잡음이라면 표준편차는 1장의 RMS와 같은 값입니다. 데이터시트의 "RMS 잡음 2 mV"는 곧 "표준편차 2 mV"라는 뜻입니다. 표본에서 분산을 추정할 때는 N 대신 N − 1로 나누기도 하는데(NumPy의 ddof=1), 데이터가 수십 개 이상이면 차이는 무시해도 됩니다.

정규분포와 68-95-99.7 규칙

측정값을 많이 모아 히스토그램을 그리면 대개 가운데가 볼록한 종 모양이 나옵니다. 이것이 정규분포(가우스 분포)입니다. 왜 이렇게 흔할까요? 측정 잡음은 보통 열잡음, 양자화, 진동 같은 수많은 작은 원인의 합입니다. 작고 독립적인 원인을 많이 더하면, 개별 원인의 모양과 상관없이 합은 종 모양에 가까워집니다(중심극한정리). 정규분포는 평균 μ와 표준편차 σ 두 숫자로 완전히 정해집니다.

이 규칙 하나로 실무 판단이 가능해집니다. ADC 잡음이 σ = 2 LSB라면 값의 99.7%는 평균 ±6 LSB 안에 들어옵니다. 그래서 "정상 범위 밖" 판정 문턱을 ±3σ에 두는 일이 많습니다. 다만 0.3%는 정상인데도 밖으로 나간다는 뜻이니, 초당 1000번 검사하면 초당 3번은 헛경보가 납니다. 11장의 헛경보 이야기가 여기서 다시 나옵니다.

평균내기의 힘: √N 법칙

통계에서 엔지니어가 가장 많이 쓰는 사실은 이것입니다. 서로 독립인 잡음을 더하면 분산이 더해집니다. 표준편차가 아니라 분산입니다.

Var(X + Y) = Var(X) + Var(Y)  ⇒  N개 평균의 표준편차 = σ√N

N개를 더하면 분산은 N배(표준편차 √N배)가 되고, N으로 나누면 표준편차가 N배 줄어드니, 합쳐서 √N배 줄어듭니다. 신호는 매번 같아서 그대로 남고 잡음만 줄어듭니다. 4번 평균하면 잡음이 절반, 100번이면 1/10입니다. 잡음이 절반이 되면 ADC 해상도가 1비트 늘어난 셈이므로 "4배 오버샘플링해서 평균하면 1비트 이득"이라는 규칙이 나옵니다.

직선 맞추기: 최소제곱법

2장에서는 두 점으로 센서를 보정했습니다. 그런데 두 점 모두에 잡음이 있다면 직선도 그만큼 틀어집니다. 더 좋은 방법은 여러 점을 재고, 모든 점에 "가장 잘 맞는" 직선을 찾는 것입니다. "가장 잘 맞는다"의 정의는 각 점과 직선 사이의 세로 오차를 제곱해서 더한 값이 가장 작은 직선입니다. 그래서 최소제곱법(least squares)이라고 부릅니다.

a = Σ (xi − x)(yi − y)Σ (xi − x)2,   b = y − a x 분자는 "x와 y가 함께 움직이는 정도"(공분산), 분모는 "x가 흩어진 정도"(분산)

왜 이런 식이 나오는지는 5장의 "최소일 때 미분이 0"을 기울기와 절편에 대해 풀면 됩니다. 실무에서는 np.polyfit이 대신해 줍니다. 분자의 Σ(x − x)(y − y)를 정규화한 것이 상관계수로, 두 양이 얼마나 직선적으로 함께 움직이는지를 −1~1로 나타냅니다. 8장의 "내적 = 얼마나 닮았나"와 같은 생각입니다.

least_squares.py · 실행 검증됨
import numpy as np

rng = np.random.default_rng(5)
raw = np.linspace(1000, 2000, 11)                 # ADC counts at 11 reference points
true_line = 0.08 * raw - 75.0                     # the sensor's true behaviour

def fit_two_point(x, y):
    a = (y[-1] - y[0]) / (x[-1] - x[0])           # uses only the end points
    return a, y[0] - a * x[0]

def fit_least_squares(x, y):
    xm, ym = x.mean(), y.mean()                   # uses every point
    a = np.sum((x - xm) * (y - ym)) / np.sum((x - xm) ** 2)
    return a, ym - a * xm

y = true_line + rng.normal(0, 0.5, raw.size)      # one calibration run, 0.5 degC noise
print("one run      : two-point a=%.5f b=%.2f | least squares a=%.5f b=%.2f"
      % (fit_two_point(raw, y) + fit_least_squares(raw, y)))
print("np.polyfit   :", np.round(np.polyfit(raw, y, 1), 5))

# Repeat the calibration 5000 times and compare the typical error
grid = np.linspace(1000, 2000, 101)
errs = {"two-point": [], "least squares": []}
for _ in range(5000):
    y = true_line + rng.normal(0, 0.5, raw.size)
    for name, fit in (("two-point", fit_two_point), ("least squares", fit_least_squares)):
        a, b = fit(raw, y)
        errs[name].append(np.max(np.abs(a * grid + b - (0.08 * grid - 75.0))))
for name, e in errs.items():
    print(f"{name:13s}: worst-case error over range, median of 5000 runs = {np.median(e):.3f} degC")
print(f"correlation coefficient r = {np.corrcoef(raw, y)[0, 1]:.4f}")

흔한 함정
  • 평균내기로 바이어스는 안 없어진다: 위 예제의 마지막 줄처럼, 10 mV 치우침은 64번 평균해도 10 mV입니다. 평균은 무작위 잡음(정밀도)만 줄이고, 계통 오차(정확도)는 보정으로 잡아야 합니다.
  • 상관된 잡음: 50/60 Hz 전원 험처럼 샘플끼리 연관된 잡음은 √N만큼 줄지 않습니다. √N 법칙은 독립일 때만 성립합니다.
  • 튀는 값(outlier): 제곱은 큰 오차를 크게 키웁니다. 가끔 튀는 값이 있는 센서는 평균 대신 중앙값(median)이 더 안전합니다.
핵심 정리
  • 표준편차 = 편차 제곱 평균의 루트 = 전형적인 흔들림. 평균 0인 잡음에서는 RMS와 같다.
  • 정규분포: ±1σ 68%, ±2σ 95%, ±3σ 99.7%.
  • 독립 잡음은 분산이 더해진다. N개 평균은 잡음을 √N배 줄인다. 최소제곱은 모든 점을 써서 직선을 맞춘다.

이제 모든 도구가 모였습니다. 7장의 상태 갱신, 6장의 적분과 드리프트, 11장의 베이즈 갱신, 그리고 이 장의 "분산은 더해진다". 마지막 장에서 이것들을 합쳐, 잡음 낀 측정과 드리프트하는 예측을 가장 좋은 비율로 섞는 칼만 필터를 직접 만듭니다.

두 추측을 섞는 법: 분산으로 가중한 평균

먼저 정지된 문제부터. 위치에 대한 추측이 두 개 있습니다. 예측은 10.0 m(분산 P), 측정은 10.6 m(분산 R)입니다. 어떻게 섞을까요? 그냥 평균 내면 10.3 m이지만, 둘 중 하나가 훨씬 정확하다면 그쪽을 더 믿어야 합니다. 정답은 분산이 작은 쪽에 더 큰 가중치를 주는 것입니다.

K = PP + R,   x ← x + K (z − x),   P ← (1 − K) P K: 칼만 이득(0~1) · z − x: 측정이 예측과 얼마나 다른가(혁신, innovation)

읽는 법: "예측이 불확실할수록(P가 클수록) 측정 쪽으로 더 많이 움직인다." 예측의 분산이 0이면 K = 0이라 측정을 무시하고, 측정의 분산이 0이면 K = 1이라 측정을 그대로 받습니다. 둘이 같으면 K = 0.5로 딱 가운데입니다.

이 식을 다시 보세요. x ← x + K(z − x)는 7장의 EMA 필터 y += α(x − y)와 모양이 똑같습니다. 칼만 필터는 α를 상황에 맞게 매번 자동으로 계산하는 EMA입니다. 그리고 섞고 난 뒤의 분산 (1 − K)P는 P보다도, R보다도 작습니다. 서로 독립인 두 정보를 합치면 어느 하나보다 확실해집니다. 11장의 베이즈 갱신을 정규분포에 대해 풀면 정확히 이 식이 나옵니다.

mini_kf.py · 실행 검증됨
"""Mini position estimator: a 1D Kalman filter that fuses wheel odometry
(prediction) with a noisy absolute position fix (measurement).

Run directly to see a 60-second simulation, or import Kalman1D / simulate / run.
Only numpy is required.
"""
import numpy as np


class Kalman1D:
    """Scalar Kalman filter for position x with variance P."""

    def __init__(self, x0, P0, Q, R):
        self.x = x0      # position estimate [m]
        self.P = P0      # variance of that estimate [m^2]
        self.Q = Q       # variance added by one prediction step [m^2]
        self.R = R       # variance of one measurement [m^2]

    def predict(self, u, dt):
        """Move by the odometry velocity u for dt seconds."""
        self.x += u * dt             # ch6: integrate velocity into position
        self.P += self.Q             # ch12: independent errors add their variances

    def update(self, z):
        """Blend in a position measurement z. Returns the gain used."""
        K = self.P / (self.P + self.R)   # ch11/ch12: trust each side by its variance
        self.x += K * (z - self.x)       # ch7: same shape as y += alpha * (x - y)
        self.P = (1.0 - K) * self.P      # the blend is more certain than either side
        return K


def simulate(seed=0, T=60.0, dt=0.1, sigma_odo=0.1, odo_bias=0.02, sigma_z=0.5):
    """Generate a ground-truth trajectory, odometry readings and position fixes."""
    rng = np.random.default_rng(seed)
    n = int(round(T / dt))
    t = np.arange(n) * dt
    v_true = 0.5 + 0.3 * np.sin(2 * np.pi * t / 20)             # speed profile [m/s]
    x_true = np.concatenate(([0.0], np.cumsum(v_true[:-1]) * dt))  # x[k+1] = x[k] + v[k] dt
    u = v_true + odo_bias + rng.normal(0, sigma_odo, n)          # wheel odometry [m/s]
    z = x_true + rng.normal(0, sigma_z, n)                       # position fix [m]
    return t, x_true, u, z


def run(seed=0, q_scale=1.0, T=60.0, dt=0.1, sigma_odo=0.1, odo_bias=0.02, sigma_z=0.5):
    """Run the filter and dead reckoning on one simulated mission."""
    t, x_true, u, z = simulate(seed, T, dt, sigma_odo, odo_bias, sigma_z)
    Q = q_scale * (sigma_odo * dt) ** 2
    kf = Kalman1D(x0=z[0], P0=sigma_z ** 2, Q=Q, R=sigma_z ** 2)
    est = np.empty_like(z)
    dead = np.empty_like(z)
    gain = np.empty_like(z)
    d = z[0]                                  # dead reckoning starts at the first fix
    for k in range(z.size):
        if k:
            kf.predict(u[k - 1], dt)
            d += u[k - 1] * dt
        gain[k] = kf.update(z[k])
        est[k] = kf.x
        dead[k] = d
    rms = lambda e: float(np.sqrt(np.mean(e ** 2)))
    return {
        "t": t, "true": x_true, "z": z, "est": est, "dead": dead, "gain": gain,
        "rms_meas": rms(z - x_true), "rms_kf": rms(est - x_true),
        "rms_dead": rms(dead - x_true), "final_dead": float(abs(dead[-1] - x_true[-1])),
    }


if __name__ == "__main__":
    r = run(seed=0)
    print(f"position fix alone  : rms error {r['rms_meas']:.3f} m")
    print(f"odometry alone      : rms error {r['rms_dead']:.3f} m (final {r['final_dead']:.2f} m)")
    print(f"Kalman filter       : rms error {r['rms_kf']:.3f} m")
    print(f"steady-state gain K : {r['gain'][-1]:.4f}")

표의 "추정 떨림"은 한 주기 사이에 추정 오차가 얼마나 흔들리는지입니다. Q를 작게 잡으면 매끄럽지만 바이어스를 따라잡지 못해 오차가 크고, 크게 잡으면 측정을 따라 떨립니다. 이 시뮬레이션에서 Q를 실제의 10배로 잡았을 때 오차가 가장 작은 것은 필터 모델에 없는 바이어스를 "모르는 잡음"으로 흡수하기 때문입니다. 실무의 튜닝도 이렇게 시뮬레이션이나 기록된 데이터로 오차와 떨림을 함께 보며 정합니다. 합격 시험은 30번의 임무 모두에서 사양을 만족했습니다.

펌웨어로 옮기기

1차원 칼만 필터는 MCU에서 돌리기에 충분히 가볍습니다. 곱셈 몇 번과 나눗셈 한 번이 전부입니다.

kalman1d.h 
typedef struct {
    float x;   /* position estimate [m] */
    float P;   /* variance of the estimate [m^2] */
    float Q;   /* variance added per prediction step */
    float R;   /* variance of one measurement */
} kalman1d_t;

static inline void kf_predict(kalman1d_t *kf, float u, float dt)
{
    kf->x += u * dt;
    kf->P += kf->Q;
}

static inline float kf_update(kalman1d_t *kf, float z)
{
    float K = kf->P / (kf->P + kf->R);
    kf->x += K * (z - kf->x);
    kf->P *= (1.0f - K);
    return K;
}

측위가 오도메트리보다 느리게 들어오면(예: 오도메트리 100 Hz, 측위 1 Hz), 매 주기 kf_predict만 부르고 측정이 도착한 주기에만 kf_update를 부르면 됩니다. 측정이 없는 동안 P가 커지다가, 측정이 오면 크게 반영하고 다시 줄어듭니다.

확장 과제

여기서 멈추지 말고 한 단계씩 더 가 보세요. 각 과제는 이 책의 어느 장을 다시 쓰는지 함께 적었습니다.

과제 1이상치 거르기 (12장): 혁신 z − x이 √P + R의 3배를 넘으면 그 측정은 버립니다. 측위 신호가 가끔 반사파로 수 미터씩 튀는 상황을 시뮬레이션에 넣어 효과를 확인하세요.
과제 2바이어스까지 추정하는 2상태 필터 (9장): 상태를 벡터 [x, b](위치, 오도메트리 바이어스)로 늘립니다. 예측은 x ← Fx + Bu, P ← FPFT + Q, 보정은 K = PHT(HPHT + R)−1. 여기서 F = [[1, −dt], [0, 1]], B = [dt, 0]T, H = [1, 0]. 1차원 식의 나눗셈이 역행렬로, 분산이 행렬 P로 바뀌었을 뿐입니다. 벤치에서 바이어스 0.1일 때의 오차가 얼마나 줄어드는지 비교하세요.
과제 3속도도 추정하기 (5장): 오도메트리가 없다고 치고 상태를 [위치, 속도]로 두어 측위만으로 속도를 추정해 보세요. 5장의 "미분은 잡음을 키운다"를 칼만 필터가 어떻게 피하는지 볼 수 있습니다.
과제 42차원과 방향 (4, 8, 9장): 평면 위의 로봇 (x, y, ψ)로 넓히면 예측식에 cos ψ, sin ψ가 들어가 비선형이 됩니다. 매 순간 그 자리에서 직선으로 근사(미분)해 쓰는 것이 확장 칼만 필터(EKF)이고, ROS 2의 robot_localization 패키지가 하는 일입니다.

최종 체크리스트

이 장의 30줄짜리 코드에는 이 책의 거의 모든 장이 들어 있습니다. 아래 질문에 답할 수 있다면 엔지니어를 위한 수학의 기초를 다시 세운 것입니다.

  • 수식 K = P/(P + R)를 소리 내어 읽고 코드로 옮길 수 있는가? (1장)

  • 오도메트리만 쓰면 왜 틀어지고, 바이어스는 왜 시간에 비례해 쌓이는가? (6장)
  • 보정 식이 EMA와 같은 모양이고 K가 α 역할이라는 것을 설명할 수 있는가? (7장)
  • P에 Q를 더하는 이유(분산의 합)와 섞은 뒤 분산이 줄어드는 이유를 설명할 수 있는가? (12장)
  • 보정이 베이즈 갱신의 한 형태라는 것을 아는가? (11장)
  • 2상태로 확장할 때 행렬 곱의 순서와 역행렬이 어디에 쓰이는지 아는가? (9장)
핵심 정리
  • 칼만 필터 = 예측(적분, 분산 증가) + 보정(분산 가중 평균, 분산 감소)의 반복.
  • K = P/(P + R)는 자동으로 계산되는 EMA 계수. 섞은 결과는 어느 한쪽보다 확실하다.
  • Q는 "내 예측 모델을 얼마나 못 믿나", R은 "측정을 얼마나 못 믿나". 모델이 틀리면 Q를 키우거나 상태를 늘린다.
