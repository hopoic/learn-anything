Part IV · 현대 C++ 실무 — 12장

실전: 미니 KV 저장소 만들기

이 장을 마치면: 클래스·RAII·스마트 포인터·가상 함수·STL·람다·string_view·expected를 한 프로그램 안에서 각자 맞는 자리에 쓸 수 있고, C로 짰다면 어떤 코드가 필요했을지 비교해 설명할 수 있으며, 확장 과제를 스스로 설계해 붙일 수 있습니다.

11개 장에서 배운 도구를 하나로 엮을 차례입니다. 만들 것은 Redis를 아주 작게 줄인 인메모리 키-값 셸 kvsh입니다. 표준 입력에서 명령을 한 줄씩 읽어 실행합니다. 표준 입력으로 동작하므로 이 페이지의 실행기에서 그대로 돌아가고, 예외를 쓰지 않으므로 브라우저 내장 엔진에서도 실행됩니다.

사양: 일곱 개의 명령과 한 가지 규칙

명령동작예
SET k v키 k에 값 v 저장SET temp 23 → OK
GET k값 조회, 없으면 오류GET temp → 23
DEL k키 삭제DEL temp → 1
INCR k정수 값 1 증가(없으면 0에서 시작), 정수가 아니면 오류INCR visits → 1
KEYS p접두사 p로 시작하는 키를 정렬해 나열(*는 전체)KEYS sensor.
COUNT키 개수COUNT → 5
UNDO마지막 변경(SET/DEL/INCR)을 되돌림UNDO → OK

규칙은 하나입니다. 잘못된 입력은 프로그램을 멈추지 않는다. 모든 오류는 (error) 이유 [line N]으로 보고하고 다음 줄로 넘어갑니다.

1단계: 가장 단순하게 동작시키기

먼저 if/else로 명령을 분기하는 최소 버전입니다. C로 짰다면 해시 테이블 구현과 문자열 메모리 관리에만 수백 줄이 들었을 부분이 std::unordered_map<std::string, std::string> 한 줄로 끝납니다.

#include #include #include #include int main() { std::unordered_map db; // hash table + string memory: done std::string line; while (std::getline(std::cin, line)) { std::istringstream in(line); std::string cmd, key, value; in >> cmd >> key >> value; if (cmd == "SET") { db[key] = value; std::cout << "OK\n"; } else if (cmd == "GET") { auto it = db.find(key); std::cout << (it != db.end() ? it->second : "(nil)") << '\n'; } else if (cmd == "DEL") std::cout << db.erase(key) << '\n'; else if (cmd == "COUNT") std::cout << db.size() << '\n'; else std::cout << "(error) unknown command\n"; } }

동작은 하지만 명령이 늘어날수록 if 사슬이 길어지고, 인자 개수 검사가 없고, 오류의 종류를 구분하지 못하고, UNDO를 넣을 자리가 없습니다. 2단계에서 구조를 바꿉니다.

완성본의 설계를 먼저 표로 보세요. 왼쪽 열은 이 책의 장, 오른쪽 열은 C라면 대신 무엇을 했어야 하는지입니다.

C 개발자의 눈으로

이 프로그램에는 new, delete, malloc, free, 고정 크기 버퍼가 하나도 없습니다. 그런데도 모든 메모리가 정확히 한 번 해제됩니다. 명령 객체는 unique_ptr가, 문자열과 테이블은 컨테이너가, 되돌리기 람다는 std::function이 소유하고, 이들은 모두 Shell 객체의 수명에 묶여 있기 때문입니다. Undo 람다가 this를 캡처하는 부분은 의도적인 주의 지점입니다. 람다를 Store가 직접 소유하므로 Store보다 오래 살 수 없어 안전합니다.

코드를 읽을 때 볼 곳
  • Store::remember: 이전 값을 std::optional로 캡처해 "없던 키였는지"까지 되돌립니다.
  • Shell::execute: 인자 개수 검사를 각 명령이 아니라 한 곳에서 합니다. 각 명령은 arity()로 요구사항만 선언합니다.
  • split: 반환된 string_view들은 line을 빌려 씁니다. execute가 끝나기 전에만 쓰이므로 안전합니다. 이것을 멤버 변수에 저장하면 11장의 함정에 빠집니다.

확장 과제

아래 과제는 뒤로 갈수록 어렵습니다. 위 실행 블록에서 편집을 눌러 바로 작업할 수 있고, 내용은 페이지를 떠나면 사라지니 긴 작업은 부록 C의 코드 놀이터(자동 저장)에 붙여 넣고 하세요.

과제 1APPEND k v: 기존 값 뒤에 문자열을 붙인다. Command를 하나 더 만들고 등록표에 한 줄 추가하면 끝나는지 확인한다(개방-폐쇄 원칙).
과제 2HELP: 등록된 모든 명령과 인자 수를 출력한다. Command에 virtual std::string_view help() const를 추가한다.
과제 3MSET k1 v1 k2 v2 ...: 가변 인자. arity()를 "최소 개수 + 짝수 조건"으로 일반화하려면 인터페이스를 어떻게 바꿔야 할까?
과제 4BEGIN / COMMIT / ROLLBACK: 되돌리기 기록에 표식을 넣어 트랜잭션 단위로 되돌린다. 강한 예외 안전성(10장)과 같은 생각이다.
과제 5SAVE file / LOAD file: std::ofstream/std::ifstream으로 저장·복원. 브라우저 내장 엔진에도 메모리 파일 시스템이 있어 같은 실행 안에서는 동작한다.
과제 6값 타입 확장: std::variant<std::string, long long>로 값을 저장해 INCR이 매번 문자열을 파싱하지 않게 한다(7장의 variant).
