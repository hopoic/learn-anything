더 나은 C: 참조·const·오버로딩

이 장을 마치면: 포인터 대신 참조를 써야 할 때를 구분하고, 매크로를 constexpr·인라인 함수·템플릿으로 바꿀 수 있으며, 오버로딩·기본 인자·auto·중괄호 초기화를 C 코드 개선에 바로 쓸 수 있습니다.

1장에서 C++이 C 위에 쌓은 언어라고 했습니다. 이 장의 기능들은 클래스가 없어도 쓸 수 있어서, 기존 C 코드를 C++로 옮길 때 가장 먼저 효과를 봅니다.

참조는 '널이 될 수 없는 별명'이다

C에서 함수가 인자를 수정하려면 포인터를 넘깁니다. 그러면 함수는 늘 "이 포인터가 NULL이면?"을 걱정해야 하고, 호출하는 쪽은 &를 잊지 말아야 합니다. C++의 참조(reference)는 이미 존재하는 객체에 붙인 또 하나의 이름입니다. 선언할 때 반드시 초기화해야 하고, 다른 객체를 가리키도록 바꿀 수 없고, 널 참조라는 것이 (정상적인 코드에서는) 없습니다.

void swap(int *a, int *b) { if (!a || !b) return; /* defensive NULL checks everywhere */ int t = *a; *a = *b; *b = t; } /* call site: swap(&x, &y); */
void swap(int& a, int& b) { // a and b ARE the caller's variables int t = a; a = b; b = t; } // call site: swap(x, y);

참조의 진짜 쓸모는 큰 객체를 복사 없이 읽기 전용으로 넘기는 것입니다. C에서 const struct config *cfg로 넘기던 것을 C++에서는 const Config& cfg로 넘깁니다. 기계어는 사실상 같고(대개 주소가 넘어갑니다), 호출부는 값처럼 깔끔합니다.

#include #include #include struct Config { std::string device = "/dev/ttyUSB0"; int baud = 115200; std::vector channels{1, 2, 3, 4}; }; // Read-only, no copy: const reference void print(const Config& c) { std::cout << c.device << " @ " << c.baud << " baud, " << c.channels.size() << " channels\n"; } // Output parameter: non-const reference void enable_fast_mode(Config& c) { c.baud = 921600; c.channels.push_back(5); } int main() { Config cfg; print(cfg); enable_fast_mode(cfg); // no &cfg needed print(cfg); int x = 10; int& alias = x; // alias is just another name for x alias += 5; std::cout << "x = " << x << ", &x == &alias: " << std::boolalpha << (&x == &alias) << '\n'; }
매개변수 전달 규칙(기본값)
  • 작은 값(int, double, 포인터, 작은 구조체) → 값으로: f(int n)
  • 큰 객체를 읽기만 → const 참조: f(const std::string& s)
  • 호출자의 객체를 수정 → 참조: f(Config& c)
  • "없을 수도 있음"이 의미가 있으면 → 포인터 또는 std::optional(10장)

매크로를 은퇴시키는 세 가지 도구

C 코드베이스의 매크로는 대개 세 종류입니다. 상수, 짧은 함수, 타입에 무관한 코드. C++은 셋 모두에 타입과 스코프가 있는 대안을 줍니다.

#define SQUARE(x) ((x)*(x))constexpr int square(int x) { return x*x; }인자가 한 번만 평가됨, 타입 검사

매크로의 고전적인 버그를 직접 보세요. MAX(i++, j)는 i를 두 번 증가시킬 수 있습니다. 그리고 constexpr 함수는 컴파일 타임에 계산될 수 있어서, 배열 크기나 static_assert에 쓸 수 있습니다.

#include #include #include #define MAX(a, b) ((a) > (b) ? (a) : (b)) constexpr int square(int x) { return x * x; } constexpr unsigned crc_table_size(unsigned bits) { return 1u << bits; } int main() { int i = 5, j = 3; int m = MAX(i++, j); // i++ is evaluated twice! std::cout << "macro: m=" << m << " i=" << i << '\n'; i = 5; int n = std::max(i++, j); // evaluated exactly once std::cout << "std::max: n=" << n << " i=" << i << '\n'; // Computed by the compiler: usable as an array size and in static_assert std::array table{}; static_assert(square(12) == 144, "math is broken"); std::cout << "table size = " << table.size() << '\n'; }

같은 이름, 다른 매개변수: 오버로딩과 기본 인자

C에서는 print_int, print_double, print_str처럼 타입마다 이름을 지어야 했습니다. C++에서는 이름 하나에 매개변수 타입만 다르게 여러 함수를 둘 수 있고, 컴파일러가 인자 타입을 보고 고릅니다(그림 1-1의 맹글링이 이것을 가능하게 합니다). 기본 인자는 자주 쓰는 값을 생략하게 해 줍니다.

#include #include #include namespace hw { // namespaces replace prefixes like hw_... void write(std::uint32_t addr, std::uint32_t value, bool verbose = false) { if (verbose) std::cout << "[write32] "; std::cout << std::hex << "0x" << addr << " <- 0x" << value << std::dec << '\n'; } void write(std::uint32_t addr, const std::string& text) { std::cout << "0x" << std::hex << addr << std::dec << " <- \"" << text << "\"\n"; } } int main() { hw::write(0x40021000, 0x1); // default verbose = false hw::write(0x40021000, 0x3, true); hw::write(0x20000000, std::string("boot")); using hw::write; // bring one name into scope write(0x40000000, 0xFF); }
흔한 함정

오버로딩은 정확한 일치, 승격, 변환 순으로 후보를 고릅니다. f(long)과 f(double)만 있을 때 f(1)은 둘 다 '변환'이라 모호하다는 오류가 납니다. 또 f(int*)와 f(int)가 있을 때 f(NULL)은 f(int)를 부를 수 있습니다. 그래서 C++11부터는 널 포인터에 nullptr를 씁니다.

auto, 범위 for, 중괄호 초기화

auto는 초기화 식에서 타입을 추론합니다. 동적 타입이 아니라, 컴파일러가 타입을 대신 적어 주는 것입니다. 범위 for는 배열과 컨테이너를 인덱스 없이 순회합니다. 중괄호 초기화 {}는 어디서나 같은 문법으로 초기화하면서, 정보가 사라지는 축소 변환(narrowing)을 막아 줍니다. 상수라면 컴파일 오류, 변수라면 GCC는 경고(-Wnarrowing)·Clang은 오류를 냅니다. 아래 예제는 일부러 컴파일되지 않습니다. 오류 메시지를 읽고 고쳐서 실행해 보세요(편집).

#include #include #include int main() { double ratio = 3.7; int a = ratio; // C-style: silently truncates to 3 int b{3.7}; // brace init: compile ERROR (narrowing) - fix me! std::map ports{{"uart", 1}, {"spi", 2}, {"i2c", 3}}; for (const auto& [name, id] : ports) // auto + structured binding std::cout << name << " -> " << id << '\n'; int* p = nullptr; // not NULL, not 0 std::cout << a << ' ' << b << ' ' << (p == nullptr) << '\n'; }
C 개발자의 눈으로

auto를 "타입을 숨기는 것"으로 느낄 수 있습니다. 기준은 간단합니다. 타입이 오른쪽에 이미 보이거나(auto p = std::make_unique<Dev>()) 타입 이름이 길고 의미가 없을 때(std::map<std::string, int>::const_iterator) 쓰고, 숫자 타입처럼 정확한 크기가 중요할 때는 명시하세요. auto x = 0;은 int이지 uint32_t가 아닙니다.
