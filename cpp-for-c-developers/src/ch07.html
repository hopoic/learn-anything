상속과 다형성

이 장을 마치면: C의 함수 포인터 테이블과 가상 함수의 대응 관계를 그림으로 설명할 수 있고, 인터페이스(추상 클래스)를 설계해 unique_ptr로 다형적 객체를 관리할 수 있으며, 가상 소멸자·override·슬라이싱 같은 함정을 피할 수 있습니다.

Part II에서 객체의 수명과 소유를 다뤘습니다. 이제 "같은 인터페이스, 다른 구현"이라는 추상화로 넘어갑니다. C 개발자에게는 이미 익숙한 패턴입니다.

C의 ops 테이블이 virtual이 되었다

리눅스 커널의 struct file_operations처럼, C에서 다형성은 함수 포인터 구조체로 구현합니다. 각 드라이버가 자기 함수로 테이블을 채우고, 객체는 그 테이블을 가리키는 포인터를 들고 다닙니다.

struct sensor; struct sensor_ops { int (*read)(struct sensor *s); const char *(*name)(const struct sensor *s); }; struct sensor { const struct sensor_ops *ops; /* "vptr": every object points at its type's table */ int bus_addr; }; /* call site: value = s->ops->read(s); */

C++의 가상 함수는 컴파일러가 이 구조를 대신 만들어 주는 것입니다. 클래스에 virtual 함수가 하나라도 있으면 컴파일러는 클래스마다 vtable(함수 포인터 표)을 하나 만들고, 각 객체에 그 표를 가리키는 숨은 포인터 vptr을 넣습니다. s->read() 호출은 s->vptr->read(s)로 번역됩니다.

#include #include #include #include class Sensor { // an interface: pure virtual functions only public: virtual ~Sensor() = default; // virtual destructor: required for polymorphic delete virtual int read() = 0; // "= 0": pure virtual, derived classes must implement virtual std::string name() const = 0; }; class Tmp36 : public Sensor { public: explicit Tmp36(int offset) : offset_(offset) {} int read() override { return 25 + offset_; } std::string name() const override { return "TMP36"; } private: int offset_; }; class FakeAccel : public Sensor { public: int read() override { return ++tick_ * 100; } std::string name() const override { return "fake-accel"; } private: int tick_ = 0; }; void poll(std::vector>& sensors) { for (auto& s : sensors) // same call, different behavior std::cout << s->name() << " = " << s->read() << '\n'; } int main() { std::vector> sensors; sensors.push_back(std::make_unique(-2)); sensors.push_back(std::make_unique()); poll(sensors); poll(sensors); std::cout << "sizeof(Tmp36) = " << sizeof(Tmp36) << " (int + vptr + padding)\n"; }

무엇이 불릴지는 '어떻게 접근하느냐'가 정한다

가상 디스패치는 포인터나 참조를 통해 호출할 때만 일어납니다. 객체를 기반 클래스 타입의 값으로 복사하면 파생 클래스 부분이 잘려 나갑니다(슬라이싱). 비가상 함수는 늘 컴파일 타임의 정적 타입으로 결정됩니다. 아래 클래스를 기준으로 조합을 바꿔 보세요.

struct Animal { virtual ~Animal() = default; virtual std::string speak() const { return "..."; } // virtual std::string name() const { return "animal"; } // NOT virtual }; struct Dog : Animal { std::string speak() const override { return "Woof"; } std::string name() const { return "dog"; } // hides Animal::name, does not override };

virtual 소멸자, override, final

  
기반 클래스 포인터로 파생 객체를 delete하려면(즉 unique_ptr<Base>로 소유하려면) 기반 클래스의 소멸자가 반드시 virtual이어야 합니다. 그렇지 않으면 기반 부분의 소멸자만 불리고, 파생 클래스가 가진 자원은 새거나 더 나쁜 일이 벌어집니다(정의되지 않은 동작).

  
override는 "기반 클래스의 가상 함수를 재정의하려는 것"이라는 선언입니다. 시그니처가 조금만 달라도(const 누락, 매개변수 타입 차이) 재정의가 아니라 새 함수가 되어 조용히 다형성이 깨지는데, override를 붙이면 그 실수가 컴파일 오류가 됩니다. 아래 코드는 일부러 틀렸습니다. 오류를 읽고 고쳐 보세요.


#include 
#include 

struct Motor {
    virtual ~Motor() = default;
    virtual void set_speed(int rpm) { std::cout << "Motor " << rpm << '\n'; }
    virtual int speed() const { return 0; }
};

struct StepperMotor final : Motor {             // final: nobody can derive from StepperMotor
    void set_speed(long rpm) override {         // BUG: long vs int -> not an override
        rpm_ = static_cast(rpm);
    }
    int speed() override { return rpm_; }       // BUG: missing const -> not an override
private:
    int rpm_ = 0;
};

int main() {
    std::unique_ptr m = std::make_unique();
    m->set_speed(1200);
    std::cout << "speed = " << m->speed() << '\n';
}


  
상속보다 합성, 열린 집합에는 virtual, 닫힌 집합에는 variant

  
상속은 강한 결합입니다. "B는 A의 일종이다(is-a)"이고 A의 인터페이스로 B를 다뤄야 할 때만 쓰세요. 단지 A의 기능을 재사용하고 싶다면 A를 멤버로 두는 합성(has-a)이 낫습니다. 또 다형성이 필요해도 종류가 고정되어 있고(예: 프로토콜 메시지 5종) 나중에 늘어날 일이 적다면 std::variant가 더 단순합니다. 힙 할당도 vtable도 없고, 처리하지 않은 종류가 있으면 컴파일러가 알려 줍니다.


#include 
#include 
#include 
#include 

struct Ping  { int seq; };
struct Data  { std::string payload; };
struct Reset { };

using Message = std::variant;     // a closed set of types, stored by value

template  struct overloaded : Fs... { using Fs::operator()...; };

int main() {
    std::vector inbox{Ping{1}, Data{"temp=23"}, Reset{}, Ping{2}};
    for (const auto& m : inbox) {
        std::visit(overloaded{
            [](const Ping& p)  { std::cout << "PING #" << p.seq << '\n'; },
            [](const Data& d)  { std::cout << "DATA " << d.payload << '\n'; },
            [](const Reset&)   { std::cout << "RESET\n"; },
        }, m);   // remove one lambda and the compiler rejects the program
    }
    std::cout << "sizeof(Message) = " << sizeof(Message) << '\n';
}

  
C 개발자의 눈으로
    
가상 함수의 비용은 객체당 포인터 하나와 호출당 간접 분기 하나, 그리고 인라인화가 막힌다는 점입니다. 대부분의 코드에서는 무시할 만하지만, 초당 수백만 번 도는 ISR 경로나 작은 MCU에서는 의식할 만합니다. 그럴 때는 8장의 템플릿(정적 다형성)이나 위의 variant를 고려하세요. std::variant는 C의 "태그 + union"을 타입 안전하게 만든 것입니다.
