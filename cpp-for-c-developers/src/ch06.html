Part II · 자원과 수명 — 6장

동적 메모리와 스마트 포인터

이 장을 마치면: new/delete와 malloc/free의 차이를 설명할 수 있고, 소유 관계에 따라 unique_ptr·shared_ptr·weak_ptr·원시 포인터를 골라 쓸 수 있으며, C 라이브러리 핸들을 사용자 정의 삭제자로 감쌀 수 있습니다.

5장의 이동 의미론 덕분에 "소유권을 넘긴다"는 개념이 언어로 표현됩니다. 스마트 포인터는 그 개념을 가장 직접적으로 쓰는 타입입니다.

new는 할당 + 생성, delete는 소멸 + 해제

malloc은 바이트를 줄 뿐이지만, new T(args)는 메모리를 할당한 뒤 그 자리에서 생성자를 실행합니다. delete p는 소멸자를 실행한 뒤 메모리를 돌려줍니다. 배열은 new T[n] / delete[] p로 짝을 맞춰야 하고, new로 얻은 것을 free로, malloc으로 얻은 것을 delete로 해제하면 정의되지 않은 동작입니다.

그런데 모던 C++ 코드에서 new와 delete를 직접 쓸 일은 거의 없습니다. 맨 delete는 C의 free와 똑같은 문제(누수, 이중 해제, 해제 후 사용)를 그대로 갖고 있기 때문입니다. 그래서 C++ 핵심 가이드라인은 "소유하는 원시 포인터를 쓰지 말라"고 권합니다. 대신 소유권을 타입으로 표현합니다.

unique_ptr: 소유자는 정확히 하나

std::unique_ptr<T>는 힙 객체 하나를 단독으로 소유하고, 자신이 소멸할 때 그 객체를 delete합니다. 복사는 금지되고 이동만 됩니다. 4장의 File과 같은 설계입니다. 크기는 원시 포인터와 같고, 역참조 비용도 같습니다.

#include #include #include #include #include struct Device { std::string name; explicit Device(std::string n) : name(std::move(n)) { std::cout << " probe " << name << '\n'; } ~Device() { std::cout << " remove " << name << '\n'; } }; struct FileCloser { // stateless deleter for C FILE handles void operator()(std::FILE* f) const { std::fclose(f); std::cout << " fclose\n"; } }; // Factory: ownership is transferred to the caller, visible in the type. std::unique_ptr probe(const std::string& name) { if (name.empty()) return nullptr; return std::make_unique(name); } int main() { std::cout << std::boolalpha << "sizeof(unique_ptr) == sizeof(raw ptr): " << (sizeof(std::unique_ptr) == sizeof(Device*)) << '\n'; std::vector> bus; bus.push_back(probe("i2c-0x48")); bus.push_back(probe("spi-flash")); if (auto d = probe("")) bus.push_back(std::move(d)); // nullptr: skipped std::unique_ptr keep = std::move(bus[0]); // transfer ownership out std::cout << "bus[0] is now " << (bus[0] ? "set" : "empty") << ", keep = " << keep->name << '\n'; // A C handle with a custom deleter: fclose runs automatically. std::unique_ptr logf(std::fopen("log.txt", "w")); if (logf) std::fputs("hello\n", logf.get()); std::cout << "sizeof(logf) = " << sizeof(logf) << " (empty deleter takes no space)\n"; std::cout << "end of main\n"; } // destruction order: logf (fclose), keep, bus (remaining devices)
C 개발자의 눈으로

C API에서 xxx_create() / xxx_destroy() 짝을 가진 핸들은 모두 unique_ptr + 삭제자로 감쌀 수 있습니다. 함수 포인터 대신 빈 구조체를 삭제자로 쓰면(struct Closer { void operator()(FILE* f) const { fclose(f); } };) 삭제자가 공간을 차지하지 않아 크기가 원시 포인터와 같아집니다.

shared_ptr와 weak_ptr: 공유 소유와 관찰

여러 곳이 같은 객체를 함께 소유하고, 마지막 소유자가 사라질 때 객체를 해제하고 싶을 때가 있습니다(캐시, 여러 스레드가 보는 설정, 그래프 노드). std::shared_ptr는 객체 옆에 제어 블록을 두고 참조 카운트를 셉니다. std::weak_ptr는 카운트에 참여하지 않고 객체가 아직 살아 있는지 확인만 할 수 있는 관찰자입니다.

실습 벤치 6-A · 참조 카운트 따라가기STEPPER · 8 STEPS

참조 카운트의 고전적인 함정은 순환 참조입니다. 부모가 자식을, 자식이 부모를 shared_ptr로 가리키면 둘 다 카운트가 0이 되지 않아 영원히 해제되지 않습니다. 아래 예제를 실행해 소멸자가 불리지 않는 것을 확인한 뒤, 주석대로 한 줄을 고쳐 다시 실행해 보세요.

#include #include #include #include struct Node { std::string name; std::shared_ptr parent; // FIX: change to std::weak_ptr parent; std::vector> children; explicit Node(std::string n) : name(std::move(n)) {} ~Node() { std::cout << "~Node " << name << '\n'; } }; int main() { { auto root = std::make_shared("root"); auto leaf = std::make_shared("leaf"); root->children.push_back(leaf); leaf->parent = root; std::cout << "root.use_count = " << root.use_count() << ", leaf.use_count = " << leaf.use_count() << '\n'; } std::cout << "scope ended (did you see ~Node lines above?)\n"; }
흔한 함정
  • shared_ptr는 공짜가 아닙니다. 복사할 때마다 원자적 증감이 일어나고, 제어 블록이 따로 있습니다. 함수에 넘길 때 소유권을 나눌 필요가 없으면 const T&나 T*로 넘기세요.
  • 같은 원시 포인터로 shared_ptr를 두 번 만들면 제어 블록이 두 개가 되어 이중 해제됩니다. 항상 std::make_shared로 만드세요.

포인터 선택 가이드: 소유권을 타입으로 말하라

C에서 int *p를 보면 그것이 소유하는 포인터인지, 빌려 쓰는 포인터인지, 배열인지, 널이 될 수 있는지 알 수 없습니다. 주석과 관례에 의존하죠. 모던 C++은 이 정보를 타입에 담습니다.

의도쓸 타입
그냥 값이면 된다T (스택, 멤버). 첫 번째 선택지
여러 개의 값std::vector<T>, std::array<T, N>
힙 객체를 단독 소유(다형성, 큰 객체, 선택적 존재)std::unique_ptr<T>
여러 소유자가 공유, 마지막이 해제std::shared_ptr<T>
공유 객체를 소유 없이 관찰(순환 끊기, 캐시)std::weak_ptr<T>
빌려 쓰기, 반드시 존재T& / const T&
빌려 쓰기, 없을 수도 있음T* (소유하지 않는 원시 포인터)
핵심 정리

원시 포인터 자체가 나쁜 것이 아니라 소유하는 원시 포인터가 나쁩니다. "소유 = 스마트 포인터 또는 컨테이너, 관찰 = 참조 또는 원시 포인터"로 나누면 delete를 쓸 일이 사라집니다.
