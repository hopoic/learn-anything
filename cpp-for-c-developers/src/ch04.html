RAII와 객체 수명

이 장을 마치면: 지역·전역·임시 객체가 언제 생성되고 소멸되는지 순서대로 추적할 수 있고, 파일·락·인터럽트 같은 자원을 소멸자로 정리하는 RAII 래퍼를 직접 만들 수 있으며, C의 goto cleanup 패턴을 C++ 방식으로 바꿀 수 있습니다.

3장에서 소멸자를 "객체가 사라질 때 정리하는 함수"라고만 소개했습니다. 이 장에서는 그 단순한 규칙이 왜 C++ 전체를 떠받치는 기둥인지 봅니다.

C의 goto cleanup을 떠올려 보자

자원을 세 개 잡는 C 함수는 대개 이런 모양입니다. 정리 순서를 맞추느라 레이블이 늘고, 중간에 새 자원이나 새 return을 추가할 때마다 누수 버그가 생길 여지가 생깁니다.

int load_calibration(const char *path, struct calib *out) { int ret = -1; FILE *f = fopen(path, "rb"); if (!f) return -1; char *buf = malloc(4096); if (!buf) goto close_file; if (pthread_mutex_lock(&calib_lock) != 0) goto free_buf; if (fread(buf, 1, 4096, f) < sizeof *out) goto unlock; /* early exit #1 */ if (!checksum_ok(buf)) goto unlock; /* early exit #2 */ memcpy(out, buf, sizeof *out); ret = 0; unlock: pthread_mutex_unlock(&calib_lock); free_buf: free(buf); close_file: fclose(f); return ret; }

이 코드가 하는 일은 사실 "자원을 얻은 역순으로, 어떤 경로로 나가든 반드시 놓는다"입니다. C++은 바로 이 규칙을 언어에 넣었습니다. 객체가 스코프를 벗어나는 모든 경로(정상 종료, return, break, 예외)에서 소멸자가 생성의 역순으로 실행됩니다. 그래서 자원을 객체 안에 넣기만 하면 정리는 자동이 됩니다. 이것을 RAII(Resource Acquisition Is Initialization)라고 부릅니다. 이름은 어색하지만 뜻은 "자원의 수명을 객체의 수명에 묶는다"입니다.

소멸자는 모든 출구에서, 역순으로 실행된다

임시 객체도 규칙을 따릅니다. std::string("a") + "b" 같은 식이 만드는 임시 객체는 그 식(full-expression)이 끝날 때 소멸합니다. 단, const T&에 바로 묶으면 참조의 수명만큼 연장됩니다. 이 규칙을 모르면 11장의 string_view에서 매달린 참조를 만들게 됩니다.

자원마다 작은 소유자 클래스를 하나씩

RAII 래퍼는 짧습니다. 생성자에서 자원을 얻고(실패하면 알리고), 소멸자에서 놓고, 복사를 막습니다. 복사를 막는 이유는 다음 장의 주제입니다. 우선 = delete로 "이 객체는 복사할 수 없다"고 선언한다는 것만 기억하세요.

#include #include #include class File { public: File(const char* path, const char* mode) : f_(std::fopen(path, mode)) { std::cout << " [open " << path << (f_ ? "]" : " FAILED]") << '\n'; } ~File() { if (f_) { std::fclose(f_); std::cout << " [close]\n"; } } File(const File&) = delete; // no copies: exactly one owner of the FILE* File& operator=(const File&) = delete; explicit operator bool() const { return f_ != nullptr; } void write(const std::string& s) { std::fputs(s.c_str(), f_); } std::string read_line() { char buf[128]; return std::fgets(buf, sizeof buf, f_) ? std::string(buf) : std::string(); } private: std::FILE* f_; }; int count_lines(const char* path, int limit) { File f(path, "r"); if (!f) return -1; // early exit #1: nothing to clean up by hand int n = 0; while (!f.read_line().empty()) { if (++n == limit) return n; // early exit #2: destructor still closes the file } return n; // normal exit } int main() { { File out("data.txt", "w"); out.write("alpha\nbeta\ngamma\ndelta\n"); } // closed (and flushed) here int a = count_lines("data.txt", 2); std::cout << "lines (limit 2): " << a << '\n'; int b = count_lines("data.txt", 100); std::cout << "lines (no limit): " << b << '\n'; int c = count_lines("nope.txt", 100); std::cout << "missing file: " << c << '\n'; }

실무에서는 래퍼를 매번 새로 짜지 않습니다. 표준 라이브러리가 대부분의 자원에 대해 이미 RAII 타입을 제공하고, C API 핸들은 6장의 std::unique_ptr에 사용자 정의 삭제자를 붙여 한 줄로 감쌉니다.

C 개발자의 눈으로

RAII는 리눅스 커널의 guard(mutex)(&lock)이나 GCC의 __attribute__((cleanup))이 흉내 내려는 바로 그 기능입니다. 차이는 C++에서는 이것이 언어의 기본 동작이라, 표준 라이브러리 전체와 여러분이 만드는 모든 타입이 같은 규칙으로 맞물린다는 점입니다.

흔한 함정
  • 이름 없는 가드: std::lock_guard<std::mutex>(m);처럼 변수 이름을 빠뜨리면 임시 객체가 그 줄에서 바로 소멸해 잠금이 즉시 풀립니다. 반드시 std::lock_guard lk(m);처럼 이름을 붙이세요.
  • 소멸자에서 예외 던지기 금지: 소멸자는 기본적으로 noexcept입니다. 정리 중 실패는 기록만 하고 삼키세요.
  • 복사 가능한 소유자: 위 File에서 = delete를 지우면 컴파일은 되지만 같은 FILE*을 두 번 닫게 됩니다. 다음 장에서 이유를 봅니다.
