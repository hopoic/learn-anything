Part I · C에서 C++로 — 1장

C 개발자를 위한 C++ 지도

이 장을 마치면: C++이 C와 어떤 관계인지 설명할 수 있고, 첫 C++ 프로그램을 컴파일·실행할 수 있으며, C 코드를 C++로 옮길 때 깨지는 지점과 extern "C"가 필요한 이유를 말할 수 있습니다.

C++은 C 위에 쌓아 올린 언어다

C++은 Bjarne Stroustrup이 1979년 벨 연구소에서 "C with Classes"라는 이름으로 시작해 1983년에 지금 이름을 얻었습니다. 출발점은 단순했습니다. C의 효율과 하드웨어 접근성은 그대로 두고, 큰 프로그램을 짤 때 필요한 추상화 도구를 더한다. 그래서 C++의 거의 모든 기능은 "C로 손으로 하던 패턴"을 언어가 직접 지원하도록 만든 것입니다. 구조체와 그 구조체를 다루는 함수 묶음은 클래스가 되었고, init/cleanup 짝은 생성자/소멸자가 되었고, 함수 포인터 테이블은 가상 함수가 되었고, 매크로로 흉내 내던 제네릭 코드는 템플릿이 되었습니다.

표준은 크게 두 시대로 나뉩니다. C++98/03이 "클래식 C++"이라면, C++11부터를 모던 C++이라고 부릅니다. 이동 의미론, 스마트 포인터, 람다, auto가 이때 들어오면서 C++ 코드의 모습이 크게 바뀌었습니다. 이 책은 C++20을 기본으로 쓰고, 필요한 곳에서 C++23 기능을 표시해 둡니다.

첫 프로그램: printf에서 std::cout으로

아래 예제를 ▶ 실행해 보세요. C의 printf도 그대로 쓸 수 있다는 점, 그리고 C++의 출력은 << 연산자로 값을 "흘려보내는" 방식이라는 점을 보면 됩니다.

hello.cpp
#include <cstdio>     // C headers keep working: <stdio.h> becomes <cstdio>
#include <iostream>   // C++ streams
#include <string>

int main() {
    std::printf("printf still works: %d\n", 42);

    std::string name = "C++";            // a real string type, no buffer sizes
    int year = 1983;
    std::cout << "Hello from " << name << ", named in " << year << '\n';

    name += " is " + std::to_string(2026 - year) + " years old";
    std::cout << name << " (length " << name.size() << ")\n";
    return 0;
}

몇 가지가 눈에 띕니다. std::는 네임스페이스입니다. 표준 라이브러리의 이름은 모두 std 안에 있어서, 여러분의 string이나 count와 충돌하지 않습니다. std::cout << x는 형식 지정자 없이 타입을 보고 알맞은 출력 함수를 고릅니다. %d에 double을 넘기는 실수가 원천적으로 사라집니다. 그리고 std::string은 길이를 알고, 스스로 메모리를 늘리고, 스코프를 벗어나면 스스로 해제합니다. 이 마지막 성질이 4장의 주제입니다.

입력도 같은 방식입니다. 이 예제는 표준 입력이 미리 채워져 있습니다. 출력 창의 stdin을 바꿔 다시 실행해 보세요.

sum.cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;                       // no &n, no format string

    std::vector<int> values(n);          // dynamic array sized at run time
    for (int& v : values) std::cin >> v; // range-for with a reference

    long sum = 0;
    for (int v : values) sum += v;

    std::string who;
    std::cin >> who;
    std::cout << who << ", sum of " << n << " values = " << sum << '\n';
}

컴파일 모델은 그대로다 — 이름만 바뀐다

C++도 C와 똑같이 전처리 → 컴파일 → 링크를 거칩니다. 헤더와 소스를 나누고, 헤더 가드를 쓰고, 오브젝트 파일을 링커가 묶습니다. Makefile이나 CMake 지식도 그대로 씁니다. 결정적으로 다른 점은 하나, 이름 맹글링(name mangling)입니다.

C++은 같은 이름의 함수를 매개변수 타입만 다르게 여러 개 둘 수 있습니다(2장의 오버로딩). 링커는 타입을 모르므로, 컴파일러가 타입 정보를 심벌 이름에 넣어 구분합니다. 문제는 C로 컴파일된 라이브러리입니다. 그 안의 심벌은 그냥 add인데, C++ 쪽은 _Z3addii를 찾으니 링크가 실패합니다. 해결책이 extern "C"이고, C/C++ 양쪽에서 쓰는 헤더는 보통 이렇게 생겼습니다.

sensor.h
#ifndef SENSOR_H
#define SENSOR_H

#ifdef __cplusplus
extern "C" {          /* C++ compilers: use C linkage (no mangling) */
#endif

int  sensor_open(const char *dev);
int  sensor_read(int fd, short *out, int count);
void sensor_close(int fd);

#ifdef __cplusplus
}
#endif

#endif /* SENSOR_H */
C 개발자의 눈으로

C++의 설계 원칙은 제로 오버헤드입니다. Stroustrup의 표현을 빌리면 "쓰지 않는 것에는 비용을 내지 않고, 쓰는 것은 손으로 짜도 더 낫게 만들 수 없다"입니다. 가상 함수를 쓰지 않는 클래스는 C 구조체와 크기가 같고, 템플릿은 컴파일 타임에 펼쳐지며, std::array는 C 배열과 메모리 배치가 같습니다. 펌웨어나 커널 가까운 코드에서도 C++을 쓸 수 있는 이유입니다. 다만 예외, RTTI, 동적 할당처럼 비용이 있는 기능은 프로젝트마다 끄거나 제한합니다(-fno-exceptions, -fno-rtti).

C++은 C의 상위 집합이 아니다

"C 코드는 C++ 컴파일러로도 컴파일된다"는 말은 대체로 맞지만 완전히 맞지는 않습니다. C++은 타입 검사가 더 엄격하고, 키워드가 더 많고, 몇몇 규칙이 다릅니다. 아래 벤치에서 직접 판정해 보세요. 확신이 없으면 아래 실행 예제에 코드를 붙여 넣고 컴파일러에게 물어보면 됩니다.

더 나은 C: 참조·const·오버로딩

이 장을 마치면: 포인터 대신 참조를 써야 할 때를 구분하고, 매크로를 constexpr·인라인 함수·템플릿으로 바꿀 수 있으며, 오버로딩·기본 인자·auto·중괄호 초기화를 C 코드 개선에 바로 쓸 수 있습니다.

1장에서 C++이 C 위에 쌓은 언어라고 했습니다. 이 장의 기능들은 클래스가 없어도 쓸 수 있어서, 기존 C 코드를 C++로 옮길 때 가장 먼저 효과를 봅니다.

참조는 '널이 될 수 없는 별명'이다

C에서 함수가 인자를 수정하려면 포인터를 넘깁니다. 그러면 함수는 늘 "이 포인터가 NULL이면?"을 걱정해야 하고, 호출하는 쪽은 &를 잊지 말아야 합니다. C++의 참조(reference)는 이미 존재하는 객체에 붙인 또 하나의 이름입니다. 선언할 때 반드시 초기화해야 하고, 다른 객체를 가리키도록 바꿀 수 없고, 널 참조라는 것이 (정상적인 코드에서는) 없습니다.

swap.c
void swap(int *a, int *b) {
    if (!a || !b) return;      /* defensive NULL checks everywhere */
    int t = *a; *a = *b; *b = t;
}
/* call site: swap(&x, &y); */
swap.cpp
void swap(int& a, int& b) {   // a and b ARE the caller's variables
    int t = a; a = b; b = t;
}
// call site: swap(x, y);

참조의 진짜 쓸모는 큰 객체를 복사 없이 읽기 전용으로 넘기는 것입니다. C에서 const struct config *cfg로 넘기던 것을 C++에서는 const Config& cfg로 넘깁니다. 기계어는 사실상 같고(대개 주소가 넘어갑니다), 호출부는 값처럼 깔끔합니다.

refs.cpp
#include <iostream>
#include <string>
#include <vector>

struct Config {
    std::string device = "/dev/ttyUSB0";
    int baud = 115200;
    std::vector<int> channels{1, 2, 3, 4};
};

// Read-only, no copy: const reference
void print(const Config& c) {
    std::cout << c.device << " @ " << c.baud << " baud, " << c.channels.size() << " channels\n";
}

// Output parameter: non-const reference
void enable_fast_mode(Config& c) {
    c.baud = 921600;
    c.channels.push_back(5);
}

int main() {
    Config cfg;
    print(cfg);
    enable_fast_mode(cfg);   // no &cfg needed
    print(cfg);

    int x = 10;
    int& alias = x;          // alias is just another name for x
    alias += 5;
    std::cout << "x = " << x << ", &x == &alias: " << std::boolalpha << (&x == &alias) << '\n';
}
매개변수 전달 규칙(기본값)
  • 작은 값(int, double, 포인터, 작은 구조체) → 값으로: f(int n)
  • 큰 객체를 읽기만 → const 참조: f(const std::string& s)
  • 호출자의 객체를 수정 → 참조: f(Config& c)
  • "없을 수도 있음"이 의미가 있으면 → 포인터 또는 std::optional(10장)

매크로를 은퇴시키는 세 가지 도구

C 코드베이스의 매크로는 대개 세 종류입니다. 상수, 짧은 함수, 타입에 무관한 코드. C++은 셋 모두에 타입과 스코프가 있는 대안을 줍니다.

C 매크로C++ 대안얻는 것
#define BUF_SIZE 256constexpr std::size_t BUF_SIZE = 256;타입, 스코프, 디버거에서 보임
#define SQUARE(x) ((x)*(x))constexpr int square(int x) { return x*x; }인자가 한 번만 평가됨, 타입 검사
#define MAX(a,b) ((a)>(b)?(a):(b))template<class T> T max(T a, T b) 또는 std::max모든 타입에 대해, 부작용 없이

매크로의 고전적인 버그를 직접 보세요. MAX(i++, j)는 i를 두 번 증가시킬 수 있습니다. 그리고 constexpr 함수는 컴파일 타임에 계산될 수 있어서, 배열 크기나 static_assert에 쓸 수 있습니다.

macros.cpp
#include <algorithm>
#include <array>
#include <iostream>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

constexpr int square(int x) { return x * x; }

constexpr unsigned crc_table_size(unsigned bits) { return 1u << bits; }

int main() {
    int i = 5, j = 3;
    int m = MAX(i++, j);             // i++ is evaluated twice!
    std::cout << "macro:  m=" << m << " i=" << i << '\n';

    i = 5;
    int n = std::max(i++, j);        // evaluated exactly once
    std::cout << "std::max: n=" << n << " i=" << i << '\n';

    // Computed by the compiler: usable as an array size and in static_assert
    std::array<unsigned, crc_table_size(8)> table{};
    static_assert(square(12) == 144, "math is broken");
    std::cout << "table size = " << table.size() << '\n';
}

같은 이름, 다른 매개변수: 오버로딩과 기본 인자

C에서는 print_int, print_double, print_str처럼 타입마다 이름을 지어야 했습니다. C++에서는 이름 하나에 매개변수 타입만 다르게 여러 함수를 둘 수 있고, 컴파일러가 인자 타입을 보고 고릅니다(그림 1-1의 맹글링이 이것을 가능하게 합니다). 기본 인자는 자주 쓰는 값을 생략하게 해 줍니다.

overload.cpp
#include <cstdint>
#include <iostream>
#include <string>

namespace hw {                       // namespaces replace prefixes like hw_...
    void write(std::uint32_t addr, std::uint32_t value, bool verbose = false) {
        if (verbose) std::cout << "[write32] ";
        std::cout << std::hex << "0x" << addr << " <- 0x" << value << std::dec << '\n';
    }
    void write(std::uint32_t addr, const std::string& text) {
        std::cout << "0x" << std::hex << addr << std::dec << " <- \"" << text << "\"\n";
    }
}

int main() {
    hw::write(0x40021000, 0x1);              // default verbose = false
    hw::write(0x40021000, 0x3, true);
    hw::write(0x20000000, std::string("boot"));

    using hw::write;                        // bring one name into scope
    write(0x40000000, 0xFF);
}
흔한 함정

오버로딩은 정확한 일치, 승격, 변환 순으로 후보를 고릅니다. f(long)과 f(double)만 있을 때 f(1)은 둘 다 '변환'이라 모호하다는 오류가 납니다. 또 f(int*)와 f(int)가 있을 때 f(NULL)은 f(int)를 부를 수 있습니다. 그래서 C++11부터는 널 포인터에 nullptr를 씁니다.

auto, 범위 for, 중괄호 초기화

auto는 초기화 식에서 타입을 추론합니다. 동적 타입이 아니라, 컴파일러가 타입을 대신 적어 주는 것입니다. 범위 for는 배열과 컨테이너를 인덱스 없이 순회합니다. 중괄호 초기화 {}는 어디서나 같은 문법으로 초기화하면서, 정보가 사라지는 축소 변환(narrowing)을 막아 줍니다. 상수라면 컴파일 오류, 변수라면 GCC는 경고(-Wnarrowing)·Clang은 오류를 냅니다. 아래 예제는 일부러 컴파일되지 않습니다. 오류 메시지를 읽고 고쳐서 실행해 보세요(편집).

클래스: 데이터와 함수를 묶다

이 장을 마치면: C의 "구조체 + 함수 묶음" 모듈을 클래스로 옮길 수 있고, 생성자·소멸자·접근 제어·const 멤버 함수로 불변식(invariant)을 지키는 타입을 설계할 수 있으며, 연산자 오버로딩으로 값 타입을 자연스럽게 쓰게 만들 수 있습니다.

모든 클래스는 C의 모듈 패턴에서 출발한다

C로 링 버퍼를 만든다면 대개 이렇게 합니다. 구조체 하나, 그 구조체 포인터를 첫 인자로 받는 함수들, 그리고 "ring_init을 먼저 부르고 내부 필드는 직접 건드리지 마세요"라는 주석.

ring.c
typedef struct {
    int    data[8];
    size_t head, tail, count;
} ring_t;

void ring_init(ring_t *r)            { r->head = r->tail = r->count = 0; }
int  ring_push(ring_t *r, int v)     { if (r->count == 8) return -1; r->data[r->tail] = v;
                                       r->tail = (r->tail + 1) % 8; r->count++; return 0; }
int  ring_pop(ring_t *r, int *out)   { if (r->count == 0) return -1; *out = r->data[r->head];
                                       r->head = (r->head + 1) % 8; r->count--; return 0; }
/* Rule by comment: "never touch head/tail/count directly; always call ring_init first" */

클래스는 이 관례를 컴파일러가 강제하는 규칙으로 바꿉니다. 함수를 구조체 안으로 옮기면 멤버 함수가 되고, 첫 인자 r은 암묵적인 this가 되고, "직접 건드리지 마세요"는 private이 되고, "ring_init을 먼저 부르세요"는 생성자가 됩니다.

#include <array>
#include <cstddef>
#include <iostream>
#include <optional>

class RingBuffer {
public:
    RingBuffer() = default;                 // members below already have initial values

    bool push(int v) {
        if (full()) return false;
        data_[tail_] = v;
        tail_ = (tail_ + 1) % data_.size();
        ++count_;
        return true;
    }
    std::optional<int> pop() {              // "maybe a value" without an out-parameter
        if (empty()) return std::nullopt;
        int v = data_[head_];
        head_ = (head_ + 1) % data_.size();
        --count_;
        return v;
    }
    bool empty() const { return count_ == 0; }          // const: does not modify *this
    bool full() const { return count_ == data_.size(); }
    std::size_t size() const { return count_; }

private:                                    // the invariant lives here, out of reach
    std::array<int, 8> data_{};
    std::size_t head_ = 0, tail_ = 0, count_ = 0;
};

int main() {
    RingBuffer rb;                          // constructed: no "forgot to init" bug possible
    for (int i = 1; i <= 10; ++i)
        if (!rb.push(i * 10)) std::cout << "full, dropped " << i * 10 << '\n';

    while (auto v = rb.pop()) std::cout << *v << ' ';
    std::cout << "\nsize=" << rb.size() << ", sizeof(RingBuffer)=" << sizeof(RingBuffer) << '\n';
    // rb.count_ = 3;   // uncomment: error, 'count_' is private
}

생성자는 불변식을 세우고, 소멸자는 거둔다

불변식(invariant)은 객체가 살아 있는 동안 늘 참이어야 하는 조건입니다. 링 버퍼라면 "count_ ≤ 8이고 head_, tail_은 범위 안"입니다. 생성자는 객체가 태어나는 순간 불변식을 세우고, 모든 public 멤버 함수는 불변식을 유지하며, 소멸자는 객체가 사라질 때 정리합니다.

생성자에서는 멤버 초기화 리스트를 쓰세요. 본문 안에서 대입하면 "기본값으로 만든 뒤 다시 대입"이 되고, const 멤버나 참조 멤버는 아예 대입할 수 없습니다. 인자 하나짜리 생성자에는 explicit을 붙여 원치 않는 암묵 변환을 막습니다.

#include <iostream>
#include <stdexcept>
#include <string>

class Uart {
public:
    explicit Uart(std::string dev, int baud = 115200)
        : dev_(std::move(dev)), baud_(baud), id_(next_id_++)   // initializer list: in declaration order
    {
        if (baud_ <= 0) baud_ = 9600;                          // keep the invariant: baud > 0
        std::cout << "open  #" << id_ << ' ' << dev_ << " @" << baud_ << '\n';
    }
    ~Uart() { std::cout << "close #" << id_ << ' ' << dev_ << '\n'; }

    const std::string& device() const { return dev_; }
    int baud() const { return baud_; }
    static int opened() { return next_id_ - 1; }               // static: belongs to the class

private:
    const std::string dev_;      // const member: only settable in the initializer list
    int baud_;
    const int id_;
    static inline int next_id_ = 1;                            // one counter shared by all Uarts
};

void log_to(const Uart& u) { std::cout << "using " << u.device() << '\n'; }

int main() {
    Uart a("/dev/ttyS0");
    {
        Uart b("/dev/ttyUSB1", -5);
        log_to(b);
    }                                // b's destructor runs here
    log_to(a);
    // log_to("/dev/ttyS9");         // blocked by 'explicit': no hidden Uart is created
    std::cout << "total opened: " << Uart::opened() << '\n';
}

C의 goto cleanup을 떠올려 보자

자원을 세 개 잡는 C 함수는 대개 이런 모양입니다. 정리 순서를 맞추느라 레이블이 늘고, 중간에 새 자원이나 새 return을 추가할 때마다 누수 버그가 생길 여지가 생깁니다.

load.c
int load_calibration(const char *path, struct calib *out) {
    int ret = -1;
    FILE *f = fopen(path, "rb");
    if (!f) return -1;
    char *buf = malloc(4096);
    if (!buf) goto close_file;
    if (pthread_mutex_lock(&calib_lock) != 0) goto free_buf;

    if (fread(buf, 1, 4096, f) < sizeof *out) goto unlock;   /* early exit #1 */
    if (!checksum_ok(buf)) goto unlock;                       /* early exit #2 */
    memcpy(out, buf, sizeof *out);
    ret = 0;

unlock:     pthread_mutex_unlock(&calib_lock);
free_buf:   free(buf);
close_file: fclose(f);
    return ret;
}

이 코드가 하는 일은 사실 "자원을 얻은 역순으로, 어떤 경로로 나가든 반드시 놓는다"입니다. C++은 바로 이 규칙을 언어에 넣었습니다. 객체가 스코프를 벗어나는 모든 경로(정상 종료, return, break, 예외)에서 소멸자가 생성의 역순으로 실행됩니다. 그래서 자원을 객체 안에 넣기만 하면 정리는 자동이 됩니다. 이것을 RAII(Resource Acquisition Is Initialization)라고 부릅니다. 이름은 어색하지만 뜻은 "자원의 수명을 객체의 수명에 묶는다"입니다.

#include <cstdio>

class File {
public:
    File(const char* path, const char* mode) : f_(std::fopen(path, mode)) {
        std::cout << "  [open " << path << (f_ ? "]" : " FAILED]") << '\n';
    }
    ~File() {
        if (f_) { std::fclose(f_); std::cout << "  [close]\n"; }
    }
    File(const File&) = delete;              // no copies: exactly one owner of the FILE*
    File& operator=(const File&) = delete;

    explicit operator bool() const { return f_ != nullptr; }
    void write(const std::string& s) { std::fputs(s.c_str(), f_); }
    std::string read_line() {
        char buf[128];
        return std::fgets(buf, sizeof buf, f_) ? std::string(buf) : std::string();
    }
private:
    std::FILE* f_;
};

int count_lines(const char* path, int limit) {
    File f(path, "r");
    if (!f) return -1;                       // early exit #1: nothing to clean up by hand
    int n = 0;
    while (!f.read_line().empty()) {
        if (++n == limit) return n;          // early exit #2: destructor still closes the file
    }
    return n;                                // normal exit
}

int main() {
    {
        File out("data.txt", "w");
        out.write("alpha\nbeta\ngamma\ndelta\n");
    }                                        // closed (and flushed) here
    int a = count_lines("data.txt", 2);
    std::cout << "lines (limit 2): " << a << '\n';
    int b = count_lines("data.txt", 100);
    std::cout << "lines (no limit): " << b << '\n';

}

    ~IrqGuard() { arch_irq_restore(saved_); }      // restore on every exit path
    IrqGuard(const IrqGuard&) = delete;
    IrqGuard& operator=(const IrqGuard&) = delete;
private:
    unsigned long saved_;
};

void push_sample(Fifo& q, int s) {
    IrqGuard guard;            // critical section starts here
    if (q.full()) return;      // early return: interrupts are still restored
    q.push(s);
}                              // ...and ends here

RAII는 리눅스 커널의 guard(mutex)(&lock)이나 GCC의 __attribute__((cleanup))이 흉내 내려는 바로 그 기능입니다. 차이는 C++에서는 이것이 언어의 기본 동작이라, 표준 라이브러리 전체와 여러분이 만드는 모든 타입이 같은 규칙으로 맞물린다는 점입니다.

복사와 이동

이 장을 마치면: 자원을 소유한 클래스에서 기본 복사가 왜 이중 해제를 일으키는지 설명할 수 있고, Rule of 3/5/0에 따라 복사·이동 연산을 설계할 수 있으며, 어떤 식이 복사·이동·생략 중 무엇을 일으키는지 판정할 수 있습니다.

4장의 File 래퍼에서 복사를 = delete로 막았습니다. 이 장은 그 이유와, 복사 대신 "소유권을 넘기는" 이동 의미론을 다룹니다.

얕은 복사는 이중 해제를 부른다

컴파일러는 클래스에 복사 생성자를 따로 정의하지 않으면 멤버별 복사를 만들어 줍니다. C 구조체 대입과 같습니다. 멤버가 포인터면 포인터 값만 복사되므로, 두 객체가 같은 버퍼를 가리키고, 둘 다 소멸자에서 그 버퍼를 해제합니다.

shallow.cpp
class Buffer {
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }
private:
    std::size_t size_;
    int* data_;
};

void oops() {
    Buffer a(1024);
    Buffer b = a;     // compiler-generated copy: b.data_ == a.data_
}                     // ~b deletes the buffer, then ~a deletes it AGAIN -> double free

이 문제는 C에서도 똑같이 있습니다. 포인터를 가진 구조체를 =로 대입하면 같은 일이 벌어지니까요. C++이 다른 점은 복사가 일어나는 순간에 실행될 코드를 직접 정의할 수 있다는 것입니다.

Rule of 3/5: 복사·이동·소멸은 한 세트다

소멸자를 직접 써야 하는 클래스라면, 거의 틀림없이 복사 생성자와 복사 대입도 직접 써야 합니다(Rule of 3). C++11부터는 여기에 이동 생성자와 이동 대입이 더해져 다섯 개가 됩니다(Rule of 5). 이동은 "곧 사라질 객체에게서 자원을 훔쳐 오는" 복사입니다. 버퍼를 새로 할당해 내용을 복사하는 대신 포인터만 가져오고, 원본은 비워 둡니다.

rule5.cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <utility>
#include <vector>

class Buffer {
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) { log("ctor"); }
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& o) : size_(o.size_), data_(new int[o.size_]) {        // deep copy
        std::copy(o.data_, o.data_ + size_, data_);
        log("COPY ctor");
    }
    Buffer(Buffer&& o) noexcept : size_(o.size_), data_(o.data_) {            // steal
        o.size_ = 0; o.data_ = nullptr;                                       // leave source empty
        log("move ctor");
    }
    Buffer& operator=(Buffer o) noexcept {     // copy-and-swap: handles copy AND move assignment
        std::swap(size_, o.size_);
        std::swap(data_, o.data_);
        log("assign");
        return *this;
    }                                          // o (holding our old buffer) is destroyed here

    std::size_t size() const { return size_; }
private:
    void log(const char* what) const { std::cout << "  " << what << " (size " << size_ << ")\n"; }
    std::size_t size_;
    int* data_;
};

Buffer make(std::size_t n) { return Buffer(n); }   // guaranteed elision since C++17

int main() {
    std::cout << "1) Buffer a(4)\n";             Buffer a(4);
    std::cout << "2) Buffer b = a\n";            Buffer b = a;
    std::cout << "3) Buffer c = std::move(a)\n"; Buffer c = std::move(a);
    std::cout << "   a.size() is now " << a.size() << '\n';
    std::cout << "4) Buffer d = make(8)\n";      Buffer d = make(8);
    std::cout << "5) b = d\n";                   b = d;
    std::cout << "6) vector growth\n";
    std::vector<Buffer> v;
    v.reserve(1);
    v.emplace_back(2);
    v.emplace_back(3);   // reallocation: moves old elements because the move ctor is noexcept
}

출력을 주의 깊게 보세요. 4번(make(8))에서는 복사도 이동도 일어나지 않습니다. 함수가 값으로 반환한 객체가 처음부터 d 자리에 만들어집니다(보장된 복사 생략). 6번에서 벡터가 커질 때 기존 원소를 이동하는 것도 확인하세요. 이동 생성자에서 noexcept를 지우고 다시 실행하면 벡터가 안전을 위해 복사로 바꿉니다. 재할당 도중 예외가 나면 원래 상태로 되돌릴 수 있어야 하기 때문입니다.

lvalue와 rvalue, 그리고 std::move의 정체

어떤 생성자가 선택될지는 인자의 값 범주가 정합니다. 대략적으로, 이름이 있어 나중에 다시 쓸 수 있는 것은 lvalue(복사해야 안전), 이름이 없는 임시값은 rvalue(곧 사라지니 훔쳐도 됨)입니다. T&&는 rvalue에만 묶이는 참조이고, 이동 생성자가 이것을 받습니다.

std::move(x)는 이름과 달리 아무것도 옮기지 않습니다. "x는 이제 안 쓸 테니 rvalue로 취급해도 된다"는 캐스팅일 뿐이고, 실제로 옮기는 일은 그 결과를 받은 이동 생성자가 합니다. 옮겨진 객체는 "유효하지만 값은 지정되지 않은" 상태이므로, 새 값을 대입하거나 소멸시키는 것 외에는 기대하지 마세요.

최선은 Rule of 0

지금까지의 코드를 실무에서 직접 쓸 일은 드뭅니다. 자원 관리를 이미 올바르게 하는 타입(std::vector, std::string, std::unique_ptr)을 멤버로 쓰면, 컴파일러가 만들어 주는 복사·이동·소멸이 멤버별로 올바르게 동작합니다. 다섯 개 중 아무것도 쓰지 않는 것, 이것이 Rule of 0입니다. 자원을 직접 소유하는 클래스는 File이나 Buffer 같은 작은 래퍼 한 곳에만 두세요.

rule0.cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

struct Frame {                        // Rule of 0: no destructor, no copy/move code
    std::string source;
    std::vector<unsigned char> payload;
};

int main() {
    Frame a{"camera0", std::vector<unsigned char>(1'000'000, 0x7f)};
    const unsigned char* before = a.payload.data();

    Frame b = a;                      // deep copy: new 1 MB buffer
    Frame c = std::move(a);           // move: steals the buffer, O(1)

    std::cout << std::boolalpha;
    std::cout << "b has its own buffer:  " << (b.payload.data() != before) << '\n';
    std::cout << "c took a's buffer:     " << (c.payload.data() == before) << '\n';
    std::cout << "a.payload.size() now:  " << a.payload.size() << '\n';
    std::cout << "c.source = " << c.source << ", c.payload.size() = " << c.payload.size() << '\n';
}
Rule 0기본값. 멤버가 스스로 자원을 관리하게 하고 특수 멤버 함수를 쓰지 않는다.
= delete복사가 의미 없는 소유자(파일, 락, 장치 핸들)는 복사를 금지하고, 필요하면 이동만 허용한다.
Rule 5자원을 직접 소유하는 저수준 래퍼에서만. 다섯 개를 함께 정의하고 이동에는 noexcept.
흔한 함정

return std::move(local);은 쓰지 마세요. 반환식이 이름 없는 지역 객체라면 컴파일러는 복사 생략(NRVO)을 하거나, 못 하더라도 자동으로 이동합니다. std::move를 붙이면 오히려 생략이 막힙니다. GCC의 -Wpessimizing-move가 이것을 경고합니다.

동적 메모리와 스마트 포인터

이 장을 마치면: new/delete와 malloc/free의 차이를 설명할 수 있고, 소유 관계에 따라 unique_ptr·shared_ptr·weak_ptr·원시 포인터를 골라 쓸 수 있으며, C 라이브러리 핸들을 사용자 정의 삭제자로 감쌀 수 있습니다.

5장의 이동 의미론 덕분에 "소유권을 넘긴다"는 개념이 언어로 표현됩니다. 스마트 포인터는 그 개념을 가장 직접적으로 쓰는 타입입니다.

new는 할당 + 생성, delete는 소멸 + 해제

malloc은 바이트를 줄 뿐이지만, new T(args)는 메모리를 할당한 뒤 그 자리에서 생성자를 실행합니다. delete p는 소멸자를 실행한 뒤 메모리를 돌려줍니다. 배열은 new T[n] / delete[] p로 짝을 맞춰야 하고, new로 얻은 것을 free로, malloc으로 얻은 것을 delete로 해제하면 정의되지 않은 동작입니다.

그런데 모던 C++ 코드에서 new와 delete를 직접 쓸 일은 거의 없습니다. 맨 delete는 C의 free와 똑같은 문제(누수, 이중 해제, 해제 후 사용)를 그대로 갖고 있기 때문입니다. 그래서 C++ 핵심 가이드라인은 "소유하는 원시 포인터를 쓰지 말라"고 권합니다. 대신 소유권을 타입으로 표현합니다.

unique_ptr: 소유자는 정확히 하나

std::unique_ptr<T>는 힙 객체 하나를 단독으로 소유하고, 자신이 소멸할 때 그 객체를 delete합니다. 복사는 금지되고 이동만 됩니다. 4장의 File과 같은 설계입니다. 크기는 원시 포인터와 같고, 역참조 비용도 같습니다.

unique.cpp
#include <cstdio>
#include <iostream>
#include <memory>
#include <string>
#include <vector>

struct Device {
    std::string name;
    explicit Device(std::string n) : name(std::move(n)) { std::cout << "  probe " << name << '\n'; }
    ~Device() { std::cout << "  remove " << name << '\n'; }
};

struct FileCloser {                       // stateless deleter for C FILE handles
    void operator()(std::FILE* f) const { std::fclose(f); std::cout << "  fclose\n"; }
};

// Factory: ownership is transferred to the caller, visible in the type.
std::unique_ptr<Device> probe(const std::string& name) {
    if (name.empty()) return nullptr;
    return std::make_unique<Device>(name);
}

int main() {
    std::cout << std::boolalpha << "sizeof(unique_ptr) == sizeof(raw ptr): "
              << (sizeof(std::unique_ptr<Device>) == sizeof(Device*)) << '\n';

    std::vector<std::unique_ptr<Device>> bus;
    bus.push_back(probe("i2c-0x48"));
    bus.push_back(probe("spi-flash"));
    if (auto d = probe("")) bus.push_back(std::move(d));   // nullptr: skipped

    std::unique_ptr<Device> keep = std::move(bus[0]);       // transfer ownership out
    std::cout << "bus[0] is now " << (bus[0] ? "set" : "empty") << ", keep = " << keep->name << '\n';

    // A C handle with a custom deleter: fclose runs automatically.
    std::unique_ptr<std::FILE, FileCloser> logf(std::fopen("log.txt", "w"));
    if (logf) std::fputs("hello\n", logf.get());
    std::cout << "sizeof(logf) = " << sizeof(logf) << " (empty deleter takes no space)\n";

    std::cout << "end of main\n";
}   // destruction order: logf (fclose), keep, bus (remaining devices)
C 개발자의 눈으로

C API에서 xxx_create() / xxx_destroy() 짝을 가진 핸들은 모두 unique_ptr + 삭제자로 감쌀 수 있습니다. 함수 포인터 대신 빈 구조체를 삭제자로 쓰면(struct Closer { void operator()(FILE* f) const { fclose(f); } };) 삭제자가 공간을 차지하지 않아 크기가 원시 포인터와 같아집니다.

shared_ptr와 weak_ptr: 공유 소유와 관찰

여러 곳이 같은 객체를 함께 소유하고, 마지막 소유자가 사라질 때 객체를 해제하고 싶을 때가 있습니다(캐시, 여러 스레드가 보는 설정, 그래프 노드). std::shared_ptr는 객체 옆에 제어 블록을 두고 참조 카운트를 셉니다. std::weak_ptr는 카운트에 참여하지 않고 객체가 아직 살아 있는지 확인만 할 수 있는 관찰자입니다.

C의 ops 테이블이 virtual이 되었다

리눅스 커널의 struct file_operations처럼, C에서 다형성은 함수 포인터 구조체로 구현합니다. 각 드라이버가 자기 함수로 테이블을 채우고, 객체는 그 테이블을 가리키는 포인터를 들고 다닙니다.

sensor_ops.c
struct sensor;
struct sensor_ops {
    int  (*read)(struct sensor *s);
    const char *(*name)(const struct sensor *s);
};
struct sensor {
    const struct sensor_ops *ops;   /* "vptr": every object points at its type's table */
    int bus_addr;
};
/* call site: value = s->ops->read(s); */

C++의 가상 함수는 컴파일러가 이 구조를 대신 만들어 주는 것입니다. 클래스에 virtual 함수가 하나라도 있으면 컴파일러는 클래스마다 vtable(함수 포인터 표)을 하나 만들고, 각 객체에 그 표를 가리키는 숨은 포인터 vptr을 넣습니다. s->read() 호출은 s->vptr->read(s)로 번역됩니다.

sensors.cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Sensor {                                   // an interface: pure virtual functions only
public:
    virtual ~Sensor() = default;                 // virtual destructor: required for polymorphic delete
    virtual int read() = 0;                      // "= 0": pure virtual, derived classes must implement
    virtual std::string name() const = 0;
};

class Tmp36 : public Sensor {
public:
    explicit Tmp36(int offset) : offset_(offset) {}
    int read() override { return 25 + offset_; }
    std::string name() const override { return "TMP36"; }
private:
    int offset_;
};

class FakeAccel : public Sensor {
public:
    int read() override { return ++tick_ * 100; }
    std::string name() const override { return "fake-accel"; }
private:
    int tick_ = 0;
};

void poll(std::vector<std::unique_ptr<Sensor>>& sensors) {
    for (auto& s : sensors)                      // same call, different behavior
        std::cout << s->name() << " = " << s->read() << '\n';
}

int main() {
    std::vector<std::unique_ptr<Sensor>> sensors;
    sensors.push_back(std::make_unique<Tmp36>(-2));
    sensors.push_back(std::make_unique<FakeAccel>());
    poll(sensors);
    poll(sensors);
    std::cout << "sizeof(Tmp36) = " << sizeof(Tmp36) << " (int + vptr + padding)\n";
}

virtual 소멸자, override, final

  
기반 클래스 포인터로 파생 객체를 delete하려면(즉 unique_ptr<Base>로 소유하려면) 기반 클래스의 소멸자가 반드시 virtual이어야 합니다. 그렇지 않으면 기반 부분의 소멸자만 불리고, 파생 클래스가 가진 자원은 새거나 더 나쁜 일이 벌어집니다(정의되지 않은 동작).

  
override는 "기반 클래스의 가상 함수를 재정의하려는 것"이라는 선언입니다. 시그니처가 조금만 달라도(const 누락, 매개변수 타입 차이) 재정의가 아니라 새 함수가 되어 조용히 다형성이 깨지는데, override를 붙이면 그 실수가 컴파일 오류가 됩니다. 아래 코드는 일부러 틀렸습니다. 오류를 읽고 고쳐 보세요.


override.cpp
#include <iostream>
#include <memory>

struct Motor {
    virtual ~Motor() = default;
    virtual void set_speed(int rpm) { std::cout << "Motor " << rpm << '\n'; }
    virtual int speed() const { return 0; }
};

struct StepperMotor final : Motor {             // final: nobody can derive from StepperMotor
    void set_speed(long rpm) override {         // BUG: long vs int -> not an override
        rpm_ = static_cast<int>(rpm);
    }
    int speed() override { return rpm_; }       // BUG: missing const -> not an override
private:
    int rpm_ = 0;
};

int main() {
    std::unique_ptr<Motor> m = std::make_unique<StepperMotor>();
    m->set_speed(1200);
    std::cout << "speed = " << m->speed() << '\n';
}



  
상속보다 합성, 열린 집합에는 virtual, 닫힌 집합에는 variant

  
상속은 강한 결합입니다. "B는 A의 일종이다(is-a)"이고 A의 인터페이스로 B를 다뤄야 할 때만 쓰세요. 단지 A의 기능을 재사용하고 싶다면 A를 멤버로 두는 합성(has-a)이 낫습니다. 또 다형성이 필요해도 종류가 고정되어 있고(예: 프로토콜 메시지 5종) 나중에 늘어날 일이 적다면 std::variant가 더 단순합니다. 힙 할당도 vtable도 없고, 처리하지 않은 종류가 있으면 컴파일러가 알려 줍니다.


variant.cpp
#include <iostream>
#include <string>
#include <variant>
#include <vector>

struct Ping  { int seq; };
struct Data  { std::string payload; };
struct Reset { };

using Message = std::variant<Ping, Data, Reset>;     // a closed set of types, stored by value

template <class... Fs> struct overloaded : Fs... { using Fs::operator()...; };

int main() {
    std::vector<Message> inbox{Ping{1}, Data{"temp=23"}, Reset{}, Ping{2}};
    for (const auto& m : inbox) {
        std::visit(overloaded{
            [](const Ping& p)  { std::cout << "PING #" << p.seq << '\n'; },
            [](const Data& d)  { std::cout << "DATA " << d.payload << '\n'; },
            [](const Reset&)   { std::cout << "RESET\n"; },
        }, m);   // remove one lambda and the compiler rejects the program
    }
    std::cout << "sizeof(Message) = " << sizeof(Message) << '\n';
}

템플릿과 컨셉트

  
이 장을 마치면: 매크로나 void*로 만들던 제네릭 코드를 함수·클래스 템플릿으로 바꿀 수 있고, 비타입 템플릿 매개변수로 크기가 고정된 컨테이너를 만들 수 있으며, C++20 컨셉트로 템플릿의 요구사항을 적고 if constexpr로 타입별 분기를 컴파일 타임에 할 수 있습니다.

  
7장의 가상 함수는 실행 중에 구현을 고릅니다. 템플릿은 같은 일을 컴파일할 때 합니다. 비용 없는 추상화라는 C++의 약속이 가장 잘 드러나는 기능입니다.


  
void*와 매크로의 대안

  
C에서 타입에 무관한 코드를 쓰는 방법은 두 가지였습니다. qsort처럼 void*와 함수 포인터를 쓰거나(타입 검사 없음, 간접 호출), 매크로로 코드를 찍어내거나(디버깅 어려움). 템플릿은 "타입을 매개변수로 받는 코드 틀"이고, 컴파일러가 쓰이는 타입마다 진짜 함수를 만들어 줍니다(인스턴스화).


sort.cpp
#include <algorithm>
#include <cstdlib>
#include <iostream>
#include <string>
#include <vector>

// C style: comparator through void*, called indirectly for every comparison
int cmp_int(const void* a, const void* b) {
    int x = *static_cast<const int*>(a), y = *static_cast<const int*>(b);
    return (x > y) - (x < y);
}

// A function template: T is deduced from the arguments
template <typename T>
T clamp_to(T v, T lo, T hi) { return v < lo ? lo : (hi < v ? hi : v); }

int main() {
    int raw[] = {42, 7, 19, 3, 88};
    std::qsort(raw, 5, sizeof(int), cmp_int);

    std::vector<int> v{42, 7, 19, 3, 88};
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });  // comparator can be inlined

    for (int x : raw) std::cout << x << ' ';
    std::cout << "| ";
    for (int x : v) std::cout << x << ' ';
    std::cout << '\n';

    std::cout << clamp_to(150, 0, 100) << ' '                       // T = int
              << clamp_to(-0.5, 0.0, 1.0) << ' '                    // T = double
              << clamp_to<std::string>("zebra", "apple", "mango")   // T = std::string (explicit)
              << '\n';
}


  
std::sort는 비교 함수를 템플릿 인자로 받으므로 컴파일러가 비교 코드를 정렬 루프 안에 인라인할 수 있습니다. 그래서 대체로 qsort보다 빠릅니다. 추상화를 높였는데 성능도 좋아지는, 제로 오버헤드 원칙의 대표 사례입니다.


  
클래스 템플릿: 타입과 크기를 매개변수로

  
클래스도 템플릿이 될 수 있습니다. std::vector<T>가 그렇습니다. 템플릿 매개변수에는 타입뿐 아니라 컴파일 타임 상수도 올 수 있어서, 힙을 쓰지 않는 고정 용량 컨테이너처럼 임베디드에서 유용한 타입을 만들 수 있습니다.


static_vector.cpp
#include <array>
#include <cstddef>
#include <iostream>
#include <string>

template <typename T, std::size_t N>
class StaticVector {                      // like std::vector, but storage lives inside the object
public:
    bool push_back(const T& v) {
        if (size_ == N) return false;
        data_[size_++] = v;
        return true;
    }
    T& operator[](std::size_t i) { return data_[i]; }
    std::size_t size() const { return size_; }
    static constexpr std::size_t capacity() { return N; }
    T* begin() { return data_.data(); }   // begin/end make range-for work
    T* end() { return data_.data() + size_; }
private:
    std::array<T, N> data_{};
    std::size_t size_ = 0;
};

int main() {
    StaticVector<int, 4> samples;                       // no heap allocation at all
    for (int i = 0; i < 6; ++i)
        if (!samples.push_back(i * i)) std::cout << "full at " << i << '\n';
    for (int s : samples) std::cout << s << ' ';
    std::cout << "\ncapacity=" << decltype(samples)::capacity()
              << " sizeof=" << sizeof(samples) << '\n';

    StaticVector<std::string, 2> names;                 // same template, different T
    names.push_back("left");
    names.push_back("right");
    std::cout << names[0] << '/' << names[1] << '\n';
}


  
흔한 함정
    
템플릿은 쓰이는 곳에서 인스턴스화되므로, 그 지점에서 정의 전체가 보여야 합니다. 그래서 템플릿은 보통 헤더에 정의까지 둡니다. 선언만 헤더에 두고 정의를 .cpp에 두면 다른 파일에서 쓸 때 링크 오류가 납니다. 또 타입마다 코드가 생기므로, 거대한 템플릿을 많은 타입으로 인스턴스화하면 바이너리가 커질 수 있습니다.

  


  
컨셉트로 요구사항을 적는다

  
C++20 이전의 템플릿은 "일단 넣어 보고 안 되면 수백 줄짜리 오류"였습니다. 컨셉트(concept)는 템플릿 인자가 만족해야 할 조건을 이름 붙여 적는 기능입니다. 조건을 어기면 컴파일러가 어떤 조건이 깨졌는지 짧게 알려 줍니다. 표준 라이브러리에 std::integral, std::floating_point, std::totally_ordered 같은 컨셉트가 준비되어 있고, 직접 만들 수도 있습니다.


concepts.cpp
#include <concepts>
#include <iostream>
#include <vector>

template <typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

// A custom concept: anything with .size() returning something convertible to size_t
template <typename C>
concept Sized = requires(const C& c) {
    { c.size() } -> std::convertible_to<std::size_t>;
};

template <Numeric T>
double average(const std::vector<T>& v) {
    if (v.empty()) return 0.0;
    double sum = 0;
    for (T x : v) sum += x;
    return sum / v.size();
}

void describe(const Sized auto& c) {          // abbreviated template syntax
    std::cout << "container with " << c.size() << " elements\n";
}

int main() {
    std::cout << average(std::vector<int>{1, 2, 3, 4}) << '\n';
    std::cout << average(std::vector<double>{0.5, 1.5}) << '\n';
    describe(std::vector<char>(7));
    // average(std::vector<const char*>{"a", "b"});   // uncomment: "constraints not satisfied"
}



  
if constexpr: 타입별 분기를 컴파일 타임에

  
if constexpr의 조건은 컴파일 타임에 평가되고, 선택되지 않은 가지는 아예 컴파일되지 않습니다. 매크로의 #if를 타입 정보까지 보면서 쓸 수 있게 된 것입니다. 아래 예제는 어떤 정수 타입이든 받아 바이트 순서를 바꾸고, 타입 크기에 맞는 경로를 컴파일 타임에 고릅니다.


if_constexpr.cpp
#include <bit>
#include <concepts>
#include <cstdint>
#include <iostream>

template <std::unsigned_integral T>
constexpr T to_big_endian(T v) {
    if constexpr (std::endian::native == std::endian::big) {
        return v;                                   // compiled only on big-endian targets
    } else if constexpr (sizeof(T) == 1) {
        return v;                                   // nothing to swap
    } else {
        T out = 0;
        for (std::size_t i = 0; i < sizeof(T); ++i) {
            out = static_cast<T>((out << 8) | (v & 0xFF));
            v = static_cast<T>(v >> 8);
        }
        return out;
    }
}

int main() {
    static_assert(to_big_endian<std::uint16_t>(0x1234) == 0x3412 || std::endian::native == std::endian::big);
    std::cout << std::hex
              << to_big_endian<std::uint16_t>(0x1234) << ' '
              << to_big_endian<std::uint32_t>(0xA1B2C3D4u) << ' '
              << +to_big_endian<std::uint8_t>(0x7F) << '\n';
}

반복자는 일반화된 포인터다

  
STL 알고리즘은 컨테이너를 직접 받지 않고 반복자 쌍 [first, last)을 받습니다. 반복자는 포인터를 일반화한 것입니다. *it로 원소를 읽고 ++it로 다음으로 갑니다. 그래서 C 배열의 포인터도 그대로 반복자로 쓸 수 있습니다. 알고리즘과 자료구조가 반복자로 분리되어 있기 때문에 알고리즘 N개 × 컨테이너 M개를 N + M개의 코드로 해결합니다.


iterators.cpp
#include <algorithm>
#include <iostream>
#include <list>
#include <numeric>
#include <vector>

int main() {
    int raw[] = {5, 3, 9, 1, 7};                    // plain C array
    std::sort(raw, raw + 5);                        // pointers are iterators
    std::cout << "sorted C array: ";
    for (int* p = raw; p != raw + 5; ++p) std::cout << *p << ' ';

    std::vector<int> v(raw, raw + 5);               // construct from an iterator range
    std::list<int> l(v.rbegin(), v.rend());         // reverse iterators

    auto it = std::find(l.begin(), l.end(), 7);     // same algorithm, different container
    std::cout << "\nfound 7 in list: " << (it != l.end() ? "yes" : "no");
    std::cout << "\nsum = " << std::accumulate(v.begin(), v.end(), 0);

    auto [mn, mx] = std::minmax_element(v.begin(), v.end());
    std::cout << "\nmin = " << *mn << ", max = " << *mx
              << ", max at index " << (mx - v.begin()) << '\n';
}



  
알고리즘 + 람다 = 루프 대신 의도

  
람다는 그 자리에서 정의하는 이름 없는 함수 객체입니다. 문법은 [캡처](매개변수) { 본문 }. 캡처는 바깥 변수를 어떻게 가져올지 정합니다. [x]는 값 복사, [&x]는 참조, [=]/[&]는 쓰인 것 전부. C의 콜백 + void *user_data 조합이 람다 하나로 바뀝니다.


lambdas.cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Reading { std::string sensor; double value; };

int main() {
    std::vector<Reading> rs{{"t0", 21.5}, {"t1", 85.2}, {"t2", 19.0}, {"t3", 90.1}, {"t4", 22.3}};
    const double limit = 80.0;

    // count_if + lambda capturing 'limit' by value
    auto hot = std::count_if(rs.begin(), rs.end(), [limit](const Reading& r) { return r.value > limit; });
    std::cout << hot << " readings above " << limit << '\n';

    // sort by value, descending
    std::sort(rs.begin(), rs.end(), [](const Reading& a, const Reading& b) { return a.value > b.value; });

    // a stateful lambda: captures 'total' by reference
    double total = 0;
    std::for_each(rs.begin(), rs.end(), [&total](const Reading& r) { total += r.value; });

    // transform into another container
    std::vector<std::string> labels(rs.size());
    std::transform(rs.begin(), rs.end(), labels.begin(),
                   [](const Reading& r) { return r.sensor + "=" + std::to_string(int(r.value)); });

    for (const auto& s : labels) std::cout << s << ' ';
    std::cout << "\naverage = " << total / rs.size() << '\n';

    // C++20: erase all elements matching a predicate in one call
    std::erase_if(rs, [](const Reading& r) { return r.value < 20.0; });
    std::cout << "after erase_if: " << rs.size() << " readings\n";

    // a lambda stored in a variable, used like a function
    auto in_range = [lo = 20.0, hi = 30.0](double x) { return lo <= x && x <= hi; };
    std::cout << std::boolalpha << "in_range(25) = " << in_range(25) << '\n';
}

레인지(ranges)는 begin/end 쌍 대신 컨테이너를 통째로 받고, 뷰(view)를 |로 이어 지연 평가 파이프라인을 만듭니다. 셸의 파이프와 비슷하게 읽힙니다. 뷰는 원소를 복사하지 않고, 결과를 실제로 꺼낼 때 계산합니다.


ranges.cpp
#include <algorithm>
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> adc{512, 1023, 0, 700, 300, 950, 128, 880};

    namespace views = std::views;
    auto volts = adc
        | views::filter([](int raw) { return raw > 256; })            // drop low readings
        | views::transform([](int raw) { return raw * 3.3 / 1023; })  // scale to volts
        | views::take(4);                                             // first 4 only

    for (double v : volts) std::cout << v << " V\n";

    std::ranges::sort(adc);                                           // no begin()/end() needed
    std::cout << "median-ish: " << adc[adc.size() / 2] << '\n';

    for (int i : views::iota(0, 5) | views::reverse) std::cout << i << ' ';
    std::cout << '\n';
}

C의 오류 처리가 놓치는 것

  
C에서는 반환값(-1, NULL)과 errno로 실패를 알립니다. 단순하고 비용이 예측 가능하지만 세 가지 약점이 있습니다. 호출자가 검사를 잊어도 컴파일러가 모르고, 오류를 위로 전달하려면 모든 중간 함수가 검사하고 다시 반환해야 하며, 생성자처럼 반환값이 없는 곳에서는 실패를 알릴 방법이 없습니다. C++은 이 문제에 두 가지 답을 줍니다. 제어 흐름을 바꾸는 예외, 그리고 실패를 타입에 담는 결과 타입(optional, expected)입니다.


  
예외: 던지고, 되감고, 잡는다

  
throw는 현재 함수를 즉시 빠져나가 호출 스택을 거슬러 올라가며 맞는 catch를 찾습니다. 이 과정이 스택 되감기(stack unwinding)이고, 되감기 중에 지나치는 모든 스코프의 지역 객체는 소멸자가 실행됩니다. 중간 함수들은 오류 검사 코드를 한 줄도 쓰지 않았는데 자원은 하나도 새지 않습니다.


exceptions.cpp
#include <iostream>
#include <stdexcept>
#include <string>

struct Guard {                                   // RAII object to observe unwinding
    std::string name;
    explicit Guard(std::string n) : name(std::move(n)) { std::cout << "  acquire " << name << '\n'; }
    ~Guard() { std::cout << "  release " << name << '\n'; }
};

class SensorError : public std::runtime_error {  // derive from the standard hierarchy
public:
    SensorError(const std::string& what, int addr) : std::runtime_error(what), addr_(addr) {}
    int addr() const { return addr_; }
private:
    int addr_;
};

int read_register(int addr) {
    Guard bus("i2c bus lock");
    if (addr == 0x77) throw SensorError("device did not ACK", addr);
    return addr * 2;
}

int read_calibration() {
    Guard buf("dma buffer");
    int a = read_register(0x48);                 // no error checks in between
    int b = read_register(0x77);                 // throws
    return a + b;                                // never reached
}

int main() {
    try {
        int c = read_calibration();
        std::cout << "calibration = " << c << '\n';
    } catch (const SensorError& e) {             // catch by const reference
        std::cout << "SensorError: " << e.what() << " at 0x" << std::hex << e.addr() << std::dec << '\n';
    } catch (const std::exception& e) {          // more general handlers go last
        std::cout << "other error: " << e.what() << '\n';
    }
    std::cout << "program continues\n";
}


  
출력에서 release 줄이 언제 찍히는지 보세요. 예외가 read_register에서 출발해 main의 catch에 닿기 전에, 두 Guard가 생성의 역순으로 정리됩니다.


  
예외 안전성과 noexcept

  
예외가 지나간 뒤 객체가 어떤 상태로 남는지에 대해 C++은 세 단계의 약속을 씁니다.

  

    
기본자원 누수가 없고 불변식이 유지된다. 값은 바뀌었을 수 있다. RAII만 지키면 대부분 자동으로 얻는다.

    
강한실패하면 호출 전과 완전히 같은 상태. "트랜잭션처럼". 5장의 copy-and-swap 대입이 이 보장을 준다.

    
nothrow절대 예외를 던지지 않는다. 소멸자, 이동 연산, swap은 이 수준이어야 하고 noexcept로 표시한다.

  

  
noexcept는 문서 이상의 의미가 있습니다. 5장에서 본 것처럼 std::vector는 원소의 이동 생성자가 noexcept일 때만 재할당에 이동을 씁니다. 그리고 noexcept 함수에서 예외가 새어 나가면 프로그램은 std::terminate로 즉시 종료됩니다.

  
C 개발자의 눈으로
    
주요 구현의 예외는 "제로 비용" 모델입니다. 예외가 던져지지 않는 정상 경로에는 검사 코드가 없고, 대신 되감기 정보 테이블이 바이너리에 들어갑니다. 던질 때는 테이블을 해석하느라 비쌉니다(마이크로초 단위). 그래서 예외는 드문 실패에 쓰고, 흔한 실패에는 아래의 결과 타입을 씁니다. 코드 크기나 결정적 실행 시간이 중요한 펌웨어는 -fno-exceptions로 예외를 아예 끄는 경우가 많습니다.

  


  
실패를 값으로: optional과 expected

  
std::optional<T>(C++17)는 "T 값이 있거나 없거나"입니다. 3장 링 버퍼의 pop()에서 이미 썼습니다. 없는 이유를 알릴 필요가 없을 때 가장 가볍습니다. std::expected<T, E>(C++23)는 "T 값이거나, 실패 이유 E이거나"입니다. 예외처럼 이유를 전달하면서도 제어 흐름은 평범한 반환입니다. 반환 타입에 실패 가능성이 드러나므로 호출자가 무시하기 어렵습니다.


expected.cppc++23
#include <charconv>
#include <expected>
#include <iostream>
#include <optional>
#include <string>
#include <string_view>

// optional: "maybe there is a value" - no reason needed
std::optional<std::string_view> find_value(std::string_view line, std::string_view key) {
    auto pos = line.find(key);
    if (pos == std::string_view::npos || line.substr(pos + key.size(), 1) != "=") return std::nullopt;
    auto rest = line.substr(pos + key.size() + 1);
    return rest.substr(0, rest.find(','));
}

// expected: "a value, or the reason why not"
enum class ParseError { Empty, NotANumber, OutOfRange };

std::expected<int, ParseError> parse_int(std::string_view s, int lo, int hi) {
    if (s.empty()) return std::unexpected(ParseError::Empty);
    int v = 0;
    auto [ptr, ec] = std::from_chars(s.data(), s.data() + s.size(), v);   // no locale, no exceptions
    if (ec != std::errc{} || ptr != s.data() + s.size()) return std::unexpected(ParseError::NotANumber);
    if (v < lo || v > hi) return std::unexpected(ParseError::OutOfRange);
    return v;
}

const char* explain(ParseError e) {
    switch (e) {
        case ParseError::Empty:      return "empty";
        case ParseError::NotANumber: return "not a number";
        case ParseError::OutOfRange: return "out of range";
    }
    return "?";
}

int main() {
    std::string_view cfg = "baud=115200,retries=x3,timeout=,parity=none";
    for (std::string_view key : {"baud", "retries", "timeout", "stopbits"}) {
        auto raw = find_value(cfg, key);
        if (!raw) { std::cout << key << ": missing, using default\n"; continue; }
        auto n = parse_int(*raw, 0, 1'000'000);
        if (n) std::cout << key << " = " << *n << '\n';
        else   std::cout << key << ": invalid (" << explain(n.error()) << ")\n";
    }
    // value_or: a default in one call
    std::cout << "retries or 3: " << parse_int("x3", 0, 10).value_or(3) << '\n';
}

enum class: 이름이 새지 않고, 정수와 섞이지 않는다

  
C의 enum은 이름이 바깥 스코프로 퍼지고(RED가 전역 이름이 됨), 아무 정수와 섞입니다. enum class는 이름이 Mode::Fast처럼 한정되고, 정수로의 암묵 변환이 막히며, 기저 타입을 지정해 레지스터나 프로토콜 필드 크기에 맞출 수 있습니다.


enum_class.cpp
#include <cstdint>
#include <iostream>
#include <type_traits>

enum class Mode : std::uint8_t { Sleep = 0, Normal = 1, Fast = 3 };   // fits a 2-bit register field

enum class Irq : std::uint32_t { None = 0, RxReady = 1u << 0, TxEmpty = 1u << 1, Overrun = 1u << 7 };

// Opt-in bit operations for a flags enum
constexpr Irq operator|(Irq a, Irq b) {
    using U = std::underlying_type_t<Irq>;
    return static_cast<Irq>(static_cast<U>(a) | static_cast<U>(b));
}
constexpr bool has(Irq set, Irq bit) {
    using U = std::underlying_type_t<Irq>;
    return (static_cast<U>(set) & static_cast<U>(bit)) != 0;
}

const char* name(Mode m) {
    switch (m) {                       // -Wall warns if a Mode is missing here
        case Mode::Sleep:  return "sleep";
        case Mode::Normal: return "normal";
        case Mode::Fast:   return "fast";
    }
    return "?";
}

int main() {
    Mode m = Mode::Fast;
    // int x = m;                      // error: no implicit conversion
    auto raw = static_cast<unsigned>(m);   // explicit when you really need the bits
    std::cout << name(m) << " = " << raw << ", sizeof(Mode) = " << sizeof(Mode) << '\n';

    Irq pending = Irq::RxReady | Irq::Overrun;
    std::cout << std::boolalpha << "rx: " << has(pending, Irq::RxReady)
              << ", tx: " << has(pending, Irq::TxEmpty)
              << ", overrun: " << has(pending, Irq::Overrun) << '\n';
}



  
span과 string_view: 포인터 + 길이를 하나로

  
C 함수는 배열을 (const int *p, size_t n) 두 인자로 받습니다. 길이를 잘못 넘기는 버그가 끊이지 않죠. std::span<T>(C++20)은 "포인터 + 길이"를 하나로 묶은 소유하지 않는 뷰입니다. C 배열, std::array, std::vector 무엇이든 받습니다. 문자열에는 같은 역할의 std::string_view(C++17)가 있습니다. 복사 없이 부분 문자열을 다룰 수 있어 파서에 특히 좋습니다.

// One function for every contiguous byte sequence; the length travels with the pointer.
int checksum(std::span<const std::uint8_t> bytes) {
    int sum = 0;
    for (auto b : bytes) sum = (sum + b) & 0xFF;
    return sum;
}

// string_view: tokenize without allocating
void print_fields(std::string_view line, char sep) {
    while (true) {
        auto pos = line.find(sep);
        std::cout << '[' << line.substr(0, pos) << ']';
        if (pos == std::string_view::npos) break;
        line.remove_prefix(pos + 1);
    }
    std::cout << '\n';
}

int main() {
    std::uint8_t raw[] = {0x10, 0x20, 0x30};

    std::cout << checksum(raw) << ' ' << checksum(arr) << ' ' << checksum(vec) << '\n';

constexpr과 static_assert: 컴파일러에게 검증을 맡긴다

  
C에서는 CRC 테이블을 스크립트로 생성해 소스에 붙여 넣거나, 시작 시 계산합니다. C++에서는 constexpr 함수로 컴파일 타임에 만들 수 있고, 결과는 읽기 전용 데이터로 바이너리에 들어갑니다. static_assert는 통신 패킷 구조체의 크기와 오프셋처럼 "깨지면 안 되는 가정"을 빌드 단계에서 검사합니다.

#include <array>
#include <cstddef>
#include <cstdint>
#include <iostream>

constexpr std::array<std::uint8_t, 256> make_crc8_table(std::uint8_t poly) {
    std::array<std::uint8_t, 256> t{};
    for (int i = 0; i < 256; ++i) {
        std::uint8_t c = static_cast<std::uint8_t>(i);
        for (int b = 0; b < 8; ++b)
            c = static_cast<std::uint8_t>((c & 0x80) ? (c << 1) ^ poly : (c << 1));
        t[i] = c;
    }
    return t;
}

constexpr auto CRC8 = make_crc8_table(0x07);       // computed by the compiler
static_assert(CRC8[1] == 0x07 && CRC8[255] == 0xF3, "unexpected CRC-8 table");

constexpr std::uint8_t crc8(const std::uint8_t* p, std::size_t n) {
    std::uint8_t c = 0;
    while (n--) c = CRC8[c ^ *p++];
    return c;
}

struct [[gnu::packed]] Packet {                    // wire format shared with a C peer

std::format, 구조적 바인딩, 그리고 동시성 맛보기

  
std::format(C++20)은 printf의 간결함과 iostream의 타입 안전성을 합쳤습니다. 형식이 맞지 않으면 컴파일 오류가 납니다. 구조적 바인딩은 구조체·pair·tuple을 이름 있는 변수로 풀어 줍니다. 마지막으로, C++11부터 스레드·뮤텍스·원자 변수가 표준에 들어 있습니다. pthread 대신 이식 가능한 코드를 쓸 수 있고, RAII 원칙이 그대로 적용됩니다(std::jthread는 소멸자에서 join합니다).

std::tuple<double, double, int> stats(const std::vector<double>& v) {
    double lo = v.front(), hi = v.front();

    return {lo, hi, static_cast<int>(v.size())};
}

    std::atomic<int> hits{0};
    std::mutex log_mutex;
    std::vector<std::string> log;
    {
        std::vector<std::jthread> workers;
        for (int id = 0; id < 4; ++id)

}

kvsh.cppc++23
// kvsh: a tiny in-memory key-value shell.
// Reads commands from stdin, one per line. Built with C++23 (std::expected).
#include <algorithm>
#include <cctype>
#include <charconv>
#include <expected>
#include <functional>
#include <iostream>
#include <map>
#include <memory>
#include <optional>
#include <string>
#include <string_view>
#include <unordered_map>
#include <vector>

// ---------- errors as values ----------
enum class Errc { UnknownCommand, BadArity, NotFound, NotInteger, NothingToUndo };

struct Error {
    Errc code;
    std::string detail;
};

std::string_view to_string(Errc e) {
    switch (e) {
        case Errc::UnknownCommand: return "unknown command";
        case Errc::BadArity:       return "wrong number of arguments";
        case Errc::NotFound:       return "no such key";
        case Errc::NotInteger:     return "value is not an integer";
        case Errc::NothingToUndo:  return "nothing to undo";
    }
    return "?";
}

using Result = std::expected<std::string, Error>;
using Args = std::vector<std::string_view>;

// ---------- the store: encapsulation + an undo log of lambdas ----------
class Store {
public:
    std::optional<std::string> get(std::string_view key) const {
        auto it = data_.find(std::string(key));
        if (it == data_.end()) return std::nullopt;
        return it->second;
    }

    void set(std::string_view key, std::string value) {
        remember(std::string(key));
        data_[std::string(key)] = std::move(value);
    }

    bool erase(std::string_view key) {
        if (!data_.contains(std::string(key))) return false;
        remember(std::string(key));
        data_.erase(std::string(key));
        return true;
    }

    bool undo() {
        if (undo_.empty()) return false;
        undo_.back()();          // run the stored inverse operation
        undo_.pop_back();
        return true;
    }

    std::vector<std::string> keys(std::string_view prefix) const {
        std::vector<std::string> out;
        for (const auto& [k, v] : data_)
            if (k.starts_with(prefix)) out.push_back(k);
        std::ranges::sort(out);
        return out;
    }

    std::size_t size() const { return data_.size(); }

private:
    // Capture the old state of 'key' in a lambda that can restore it later.
    void remember(std::string key) {
        auto old = get(key);
        undo_.push_back([this, key = std::move(key), old = std::move(old)] {
            if (old) data_[key] = *old;
            else data_.erase(key);
        });
    }

    std::unordered_map<std::string, std::string> data_;
    std::vector<std::function<void()>> undo_;
};

// ---------- commands: an interface + one class per command ----------
class Command {
public:
    virtual ~Command() = default;
    virtual std::size_t arity() const = 0;                 // number of arguments expected
    virtual Result run(Store& db, const Args& args) = 0;
};

class Set : public Command {
public:
    std::size_t arity() const override { return 2; }
    Result run(Store& db, const Args& a) override { db.set(a[0], std::string(a[1])); return "OK"; }
};

class Get : public Command {
public:
    std::size_t arity() const override { return 1; }
    Result run(Store& db, const Args& a) override {
        if (auto v = db.get(a[0])) return *v;
        return std::unexpected(Error{Errc::NotFound, std::string(a[0])});
    }
};

class Del : public Command {
public:
    std::size_t arity() const override { return 1; }
    Result run(Store& db, const Args& a) override {
        if (db.erase(a[0])) return "1";
        return std::unexpected(Error{Errc::NotFound, std::string(a[0])});
    }
};

class Incr : public Command {
public:
    std::size_t arity() const override { return 1; }
    Result run(Store& db, const Args& a) override {
        long long n = 0;
        if (auto v = db.get(a[0])) {
            auto [ptr, ec] = std::from_chars(v->data(), v->data() + v->size(), n);
            if (ec != std::errc{} || ptr != v->data() + v->size())
                return std::unexpected(Error{Errc::NotInteger, *v});
        }
        db.set(a[0], std::to_string(++n));
        return std::to_string(n);
    }
};

class Keys : public Command {
public:
    std::size_t arity() const override { return 1; }
    Result run(Store& db, const Args& a) override {
        std::string out;
        for (const auto& k : db.keys(a[0] == "*" ? "" : a[0])) out += (out.empty() ? "" : " ") + k;
        return out.empty() ? "(empty)" : out;
    }
};

class Count : public Command {
public:
    std::size_t arity() const override { return 0; }
    Result run(Store& db, const Args&) override { return std::to_string(db.size()); }
};

class Undo : public Command {
public:
    std::size_t arity() const override { return 0; }
    Result run(Store& db, const Args&) override {
        if (db.undo()) return "OK";
        return std::unexpected(Error{Errc::NothingToUndo, ""});
    }
};

// ---------- parsing: string_view tokens, no copies ----------
Args split(std::string_view line) {
    Args out;
    while (!line.empty()) {
        auto start = line.find_first_not_of(' ');
        if (start == std::string_view::npos) break;
        line.remove_prefix(start);
        auto end = line.find(' ');
        out.push_back(line.substr(0, end));
        line.remove_prefix(end == std::string_view::npos ? line.size() : end);
    }
    return out;
}

std::string upper(std::string_view s) {
    std::string r(s);
    std::ranges::transform(r, r.begin(), [](unsigned char c) { return static_cast<char>(std::toupper(c)); });
    return r;
}

// ---------- the shell ----------
class Shell {
public:
    Shell() {
        commands_["SET"]   = std::make_unique<Set>();
        commands_["GET"]   = std::make_unique<Get>();
        commands_["DEL"]   = std::make_unique<Del>();
        commands_["INCR"]  = std::make_unique<Incr>();
        commands_["KEYS"]  = std::make_unique<Keys>();
        commands_["COUNT"] = std::make_unique<Count>();
        commands_["UNDO"]  = std::make_unique<Undo>();
    }

    Result execute(std::string_view line) {
        Args words = split(line);
        if (words.empty()) return "";
        auto it = commands_.find(upper(words[0]));
        if (it == commands_.end())
            return std::unexpected(Error{Errc::UnknownCommand, std::string(words[0])});
        Args args(words.begin() + 1, words.end());
        if (args.size() != it->second->arity())
            return std::unexpected(Error{Errc::BadArity, std::string(words[0])});
        return it->second->run(db_, args);
    }

private:
    Store db_;
    std::map<std::string, std::unique_ptr<Command>> commands_;
};

int main() {
    Shell sh;
    std::string line;
    int lineno = 0;
    while (std::getline(std::cin, line)) {
        ++lineno;
        if (line.empty() || line.starts_with('#')) continue;
        std::cout << "> " << line << '\n';
        if (auto r = sh.execute(line))
            std::cout << *r << '\n';
        else
            std::cout << "(error) " << to_string(r.error().code)
                      << (r.error().detail.empty() ? "" : ": " + r.error().detail)
                      << "  [line " << lineno << "]\n";
    }
}

  • split: 반환된 string_view들은 line을 빌려 씁니다. execute가 끝나기 전에만 쓰이므로 안전합니다. 이것을 멤버 변수에 저장하면 11장의 함정에 빠집니다.

용어

  

    
용어뜻

    
      
RAII자원의 수명을 객체의 수명에 묶는 기법. 생성자에서 얻고 소멸자에서 놓는다.

      
이름 맹글링오버로딩을 위해 컴파일러가 함수 심벌 이름에 타입 정보를 넣는 것. C와 링크할 때 extern "C"로 끈다.

      
참조 (T&)기존 객체의 별명. 반드시 초기화되고 다른 대상으로 바꿀 수 없다.

      
불변식객체가 살아 있는 동안 늘 참이어야 하는 조건. 생성자가 세우고 멤버 함수가 유지한다.

      
lvalue / rvalue이름이 있어 다시 쓸 수 있는 식 / 곧 사라질 임시값. 복사냐 이동이냐를 가른다.

      
이동 의미론곧 사라질 객체의 자원을 복사 대신 넘겨받는 것. T&&를 받는 이동 생성자·대입이 구현한다.

      
복사 생략 (RVO/NRVO)반환값을 호출자 자리에 직접 만들어 복사·이동을 없애는 것. C++17부터 prvalue에 대해 보장.

      
Rule of 0/3/5특수 멤버 함수(소멸자, 복사 2개, 이동 2개)를 하나도 안 쓰거나, 쓰려면 함께 쓴다는 지침.

      
제어 블록shared_ptr가 참조 카운트(use/weak)를 보관하는 별도 메모리.

      
vtable / vptr클래스별 가상 함수 포인터 표 / 각 객체가 그 표를 가리키는 숨은 포인터.

      
슬라이싱파생 객체를 기반 타입 값으로 복사할 때 파생 부분이 잘려 나가는 것.

      
인스턴스화템플릿에 구체 타입을 넣어 실제 함수·클래스를 만드는 컴파일러의 작업.

      
컨셉트템플릿 인자가 만족해야 할 조건에 붙인 이름(C++20).

      
반복자 / 무효화원소를 가리키는 일반화된 포인터 / 컨테이너 변경으로 반복자가 더는 유효하지 않게 되는 것.

      
람다 캡처람다가 바깥 변수를 값([x])이나 참조([&x])로 가져오는 방식.

      
스택 되감기예외가 전파되며 지나는 스코프의 지역 객체를 소멸시키는 과정.

      
예외 안전성예외 후 상태에 대한 약속: 기본 / 강한 / nothrow.

      
뷰(view)원소를 소유하지 않고 다른 범위를 바라보는 가벼운 객체(span, string_view, 레인지 뷰).

      
정의되지 않은 동작(UB)표준이 결과를 정하지 않은 동작. 이중 해제, 범위 밖 접근, 매달린 참조 사용 등. C와 같다.
